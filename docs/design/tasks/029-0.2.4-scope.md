## Theme

Set by the maintainer during 0.2.3's preparation: 0.2.4 fixes the
places where the existing code's **design is excessively complex**, or
where the **design itself harbors a bug class** — whether or not any
instance is currently wrong, and not limited to what the 0.2.x line
had previously planned. 0.2.3 stays frozen as shipped; design-class
findings from its review loop were routed here (`024.55`, `024.56`,
`024.62`, `024.63` carry `target: 0.2.4` in the register). No new
capabilities: this release simplifies and de-risks what exists.

## How this scope was produced, and what its claims rest on

Three independent audit rounds over the whole tree (core/lib ~20k
lines, vscode/src ~3k non-test, scripts, spec support), each round a
fresh agent given the prior rounds' map as *coverage, never
exclusion* — the same rule the review loop uses (`024.36`). Round 2
corrected round 1 twice (one factual error, one over-unification);
round 3 confirmed the corrected map with **zero further corrections**,
examined every area the first two rounds had not read deeply, and
added two items. Every load-bearing claim below — line references,
call-site counts, lock inventories, the live divergences — was then
re-verified against source by a second party before entering this
document. Line references are against 0.2.3's tree (`4fdf17e`); 0.2.4
work begins after 0.2.3 merges, so that is the reference frame that
will be current.

**Where 0.2.4's work lives** (per CLAUDE.md's residency rule): the
engine thread inherited from the parallel 0.2.3 preparation lives on
`fix/0.2.3`, whose content is brought onto the implementation branch
after 0.2.3 merges (028's "Two preparations, one release" records the
dispositions, including renumbering that branch's colliding `024.49`
and its `028-*.md` → `030-0.2.4-review-loop.md`, this file having taken
the 029 number on `main`).

**The implementation branch is `feat/0.2.5`** (renamed from
`feat/0.2.4` when the numbers moved; see the note at the top). That is what this
section owed once the scope merged, and it is the whole point of the
residency rule: a session resuming this release starts with
`git fetch --all --prune` and finds the branch named here, on `main`.
`fix/0.2.3` is kept until its content has demonstrably landed, then
deleted — it is the 0.2.3-era name for work that is no longer 0.2.3,
and leaving it addressable under that name is the confusion the rule
exists to prevent.

## Must

### M-1. Land the engine thread from the parallel preparation, through a clean review loop

The work parked on `fix/0.2.3` fixes three live design defects, each
verified present on 0.2.3's tree:

- **Vendor ABI containment** (`024.58`-family): `core/bin/ovallsp:29`
  globs `vendor/bundle/**/gems/*/lib` across *every* ABI directory
  under one whole-root `compatible?` boolean, so a two-Ruby dev
  checkout loads the other ABI's native prism
  (`LoadError: linked to incompatible libruby`). The branch's
  `VendorBootstrap` moves the which-directories decision into a
  module with a unit spec, ABI-scoped by `RbConfig`.
- **The synchronous sweep**: `Server#build_cache_store` runs
  `prune_generations` on the dispatch thread (server.rb:1124, before
  the `Thread.new` at 1128) — measured at ~26 s of a server
  answering nothing on the machine the sweep exists for — and
  removes an absent workspace's cache with no grace period. The
  branch moves it to a tracked background thread with an explicit
  `ABSENT_WORKSPACE_GRACE`, reads the clock from the `.workspace`
  marker's mtime, and keeps tolerance/containment in
  `remove_within`/per-entry rescues.
- **`writeHandshakeLines`**: the handshake formatting extracted from
  the untested `runVersionHandshake` into a tested pure function.

Explicitly **excluded**: the branch's debounce work (rolled back
there after four consecutive defective rounds; it depends on M-3 and
stays out until M-3 exists). Landing means rebase + register
reconciliation + resuming that loop under fix-don't-add until a round
is clean — the branch stopped at rounds finding 8, 12, 9, 11 without
one. Their `store_spec`'s fabricated absolute path takes the unified
fixture on rebase.

**Fold-in (round 3):** the containment guard
(`cache_removal_containment_spec.rb:36`) matches `FileUtils.*` verbs
only, and `Cache::Store` deletes files via `File.delete` at store.rb
:256 and :287 — inside `@cache_dir` by construction today, which is
exactly the pre-0.2.2 posture the incident section of CLAUDE.md warns
about. Extend the guard to `File.delete`/`File.unlink` and route file
deletion through the contained helper. Close the class, not the
instance.

Size: M–L (code exists; the cost is rebase + the loop).
Priority: must — live user-visible defects, and 028 already binds
this thread to 0.2.4.

### M-2. Immutable document snapshots (new finding, round 2)

`TextDocument` is mutated in place on the dispatch thread:
`apply_incremental_change` writes `@text` then `@version`
sequentially (text_document.rb:37–45), and `text=` assigns `@text`
*before* recomputing both line-offset tables (:119–122).
`DocumentStore#open_documents` dups the array but hands out the
shared mutable objects (document_store.rb:50–52). All six
`republish_open_diagnostics` call sites (server.rb:649, 1449, 3077,
3208, 3343, 3375) run on background threads and read
`document.text`/`document.version` — `handle_did_change` mutates
*before* taking `@index_mutation_mutex` (server.rb:342–350), and the
version read at server.rb:417 is outside every lock.

Bug class: torn multi-field read; cross-thread state without one
owner. A background publish can pair old-text findings with a new
version number (the client's staleness filter then *accepts* them —
`024.56`'s user symptom arriving from the input side), or run
position math with new `@text` against stale offsets. No observed
instance; the interleavings exist by lock inventory.

Direction: make `TextDocument` an immutable snapshot — offsets
computed at construction, no `apply_*` mutators; `DocumentStore#change`
builds a new document and swaps the hash entry (one reference
assignment). Text, version and offsets then always travel together.
The only mutator caller is `DocumentStore` itself.

Size: S–M. Priority: must — it is the precondition for M-3's
version-ordering rule meaning anything.

### M-3. One writer, with memory, for the publish funnel (`024.56`)

Four writer kinds reach `publish_findings` (server.rb:432–437), which
is four lines with no state: the dispatch thread (:417, clears at
:376/:736/:2854), the workspace pass on its own thread
(workspace_diagnostics.rb:124→130 — whose own open-check at :118/:128
has an unguarded window), six background `republish_open_diagnostics`
sites, and the changed-files batch thread (:2925). Nothing orders a
background publish against `didClose`'s clear; `024.56` records the
reproduced `[2, 0, 2]` publish sequence for a closed file, present in
**every shipped build**.

Direction (`024.56`'s, all three rounds concur): `publish_findings`
gains a per-uri record of the last published version under one small
mutex — refuse older writes, a clear always wins and resets, delete
on `didClose`. That subsumes the workspace pass's window and the
republish path without either knowing about it. The memory lives in
`Server#publish_findings`, **not** `FramedWriter` (which also carries
responses and must stay a dumb frame mutex — framed_writer.rb:16–34).
This is also the precondition the rolled-back debounce work was
missing.

Size: S. Priority: must — the one live, reproduced, user-visible
race, and it gates the debounce 0.2.4 inherits.

**Sequencing within must: M-1 first or in parallel (disjoint
surface); M-2 before M-3; the stale threading section of
`docs/design/docs/02-architecture.md` (C-3 below) is rewritten in the
same change set as M-2/M-3, which would otherwise ship code its own
architecture document contradicts.**

## Should

### S-1. One factory and one apply-path for the semantic stack (new finding, rounds 1–3)

`Server#initialize` hand-builds ~25 collaborators (server.rb:55–152);
`scripts/corpus_diagnostics.rb:71–102` hand-copies the wiring under a
comment whose whole countermeasure is "keep every constructor here
matching" — `024.48`'s fix, which held for constructors and was then
outflanked one layer up: the script's corpus loop writes
`workspace_index` + `hierarchy_index` only (:116–117), while
`Server#apply_file_summary` (server.rb:1168–1180) also writes
`@file_summaries`, invalidates method summaries, writes
`@generated_method_index`, and marks the reference index dirty. The
script constructs a `GeneratedMethodIndex` (:93) and never writes it,
so **every corpus measurement of `delegate`/`scope`/`enum` code runs
an inference no user runs** (`MethodAnalyzer#fact_for`,
method_analyzer.rb:125, always misses). `024.48` records what this
class cost: seven review rounds quoting numbers from a phantom
engine, and a 55-report regression shipped on them.

Direction: module functions (the form CLAUDE.md's 0.1.12 lesson
prescribes) — `build_semantic_stack(...)` *and*
`apply_summary_to(stores, summary)` — used by `Server`, the script,
and `benchmark/cold_index_benchmark.rb`. The factory alone would
repeat `024.48`'s countermeasure mistake (guarding the previous
symptom's vocabulary); the apply-path half is load-bearing.

Size: S–M. Priority: should — it protects the instrument every other
item's verification runs through; land **before any 0.2.4 corpus
baseline is taken**.

### S-2. One aggregation mechanism for the per-file stores; retire the dormant write path (`024.62` + new finding NEW-2)

The mutex+generation store shape is hand-written 9+ times, three of
them self-citing the pattern as a pattern
(generated_method_index.rb:7–11, observation/store.rb:8–10,
method_summary_store.rb:38–41). Four writer sites touch four
different subsets; `ColdIndexer`'s direct path
(cold_indexer.rb:168–172) writes two stores and is reachable only
because its one non-Server caller
(benchmark/cold_index_benchmark.rb:81) passes no `on_summary` — a
loaded gun for the first future caller. `024.62` records the hazard
and the two candidate shapes; option 2 (one aggregation type/module,
boundaries kept) is the one consistent with the 0.1.12 caution.
Make `on_summary` required; the benchmark moves onto the real path it
should have been measuring.

**Folded in — NEW-2 (round 3): `GeneratedMethodIndex#fact_for`
answers by insertion order.** `@by_symbol.fetch(symbol_id, nil)
&.last&.last` (generated_method_index.rb:42) under remove-then-append
`replace_file` (:24–31) means two files declaring the same-named DSL
fact get whichever file was most recently re-indexed — and re-saving
the *first* file unchanged flips hover/inference for the method. This
is `024.15`'s class ("answers depend on which file was edited last",
fixed for `WorkspaceIndex` in 0.1.13) in a sibling store the fix
never reached. The existing spec pins only the removal path
(method_analyzer_spec.rb:377–389). Fix: a deterministic tie-break at
the read (by `[uri, location]`, `024.15`'s key shape), pinned by a
fixture where the two candidate facts yield *different* observable
types, per CLAUDE.md's distinguishing-fixture rule.

**Constraint the aggregation must preserve** (round 3): the read
nesting HierarchyIndex→WorkspaceIndex
(hierarchy_index.rb:191–193 holds its own mutex while calling
`resolve_type_name`) and the write nesting
index_mutation_mutex→store mutex.

Size: M. Priority: should — two register entries and two audit
findings describe the same waiting accident; NEW-2 is user-visible
instability, S-sized, in the same file.

### S-3. Per-call walk state for `LocalInferencer`; name the memo family (`024.39`-family)

Five entry points reset `@steps`/`@step_budget`/`@self_type_stack`/
`@scope_capture`/`@capturing_scope` on the shared instance
(local_inferencer.rb:107–124, 125–140, 141–156, 165–168, 178–183),
plus a single-slot `@parse_cache` (:218–224). Every reachable path is
safe **only** because every caller happens to hold
`@index_mutation_mutex` — dispatch wraps the feature handlers in
`with_index_snapshot` (server.rb:267–297), both diagnostics paths
take it internally, and the reference rebuild is reached only from
inside it. That is emergent containment — "correctness as a property
of every caller being right at once", which CLAUDE.md's incident
section says is not a property — and it is also the latency coupling:
the one big lock cannot be narrowed (`024.45`'s seconds-long
serialization) until this state is per-call. Server's own
`@structural_tokens_key/value` (server.rb:2601–2607),
`@non_code_spans_key/value` (:2653–2660) and `@helper_ivars`
(:1745–1776) memos are the same class; the item includes them so they
are not rediscovered.

Direction: a per-call walk object carrying steps/budget/stack/capture;
`@parse_cache` stays the one deliberately shared piece with its own
lock. Do `024.38`'s capture-on-write in the same pass (it rearranges
the same walk).

Size: M. Priority: should — converts "safe by lock discipline nothing
states" into an invariant, and unblocks ever answering `024.45`.

Direction: `024.63`'s option 1 — `#type_at` obtains the view

After S-3 (the cluster drives the inferencer's ivar entry points).

Size: L — its own task inside the release, **cut to 0.2.5 without
ceremony** if the loop starts reviewing a moving target (the 0.1.12 /
0.2.1 growth lesson).
Priority: should — the release's centerpiece only if the must items
land small.
