# Task 023.4: Apple Silicon Ruby resolver・vendor互換性・packaged semantic smoke

## Goal

Apple Silicon上でのRuby環境解決を堅牢にし、実際にパッケージされたVSIXが
「意味のある」semantic機能を実際に提供できることを、より広いLSP機能と
stderr内容の両面から検証できるようにする。

## Depends on

- Task 020(既存のRuby resolver)、ADR-0005(vendor互換性検証)

## In scope

- Homebrew Ruby resolver戦略(GUI起動時のPATH不足問題への対応)
- Ruby実サポート範囲の宣言をテスト証跡に合わせて絞り込み
- `ruby`と`bundle`が異なるインストールを指す場合のbuild失敗
- vendor依存(prism/rbs)がgemspecの宣言するversion要件を満たすことの検証
- Rosetta/x86_64 Ruby誤選択の拒否(既存chekcの回帰テスト)
- `scripts/vsix_semantic_smoke.rb`のdocumentSymbol/definition・stderr allowlist拡張

## Out of scope

- GUI起動時のPATH不足そのものの自動回避(mise/asdf/rbenv/Homebrewの
  絶対パス直接チェックで大部分は既に回避されている — 残るPATHベースの
  `pathRuby`戦略のみ影響を受けるが、これは`ovallsp.rubyExecutablePath`
  で明示回避可能であり、新規実装は不要と判断)
- 明示パス設定のスペース/日本語文字対応(`serverConfig.test.ts`の
  "passes a path containing spaces and non-ASCII characters through
  unescaped"で既にカバー済み、新規追加なし)

## 実装

### Homebrew Ruby resolver戦略

`vscode/src/rubyResolver.ts`に`homebrewRuby`関数を追加。GUI起動された
VS Code(Dock/Finder/Spotlight)はmacOS自身の最小限のlaunchd継承PATHしか
持たず、`/opt/homebrew/bin`を含まないことが多い — この戦略は
`/opt/homebrew/opt/ruby/bin/ruby`をPATHに頼らず直接チェックする。
mise/asdf/rbenv/chrubyの次、PATHベースの`pathRuby`の前に配置(Apple
Silicon prefixのみ対象、Intel `/usr/local`はこのPreviewの対象外)。

### Ruby実サポート範囲の絞り込み

`docs/SUPPORT_MATRIX.md`を更新: Ruby 3.3は`required_ruby_version >= 3.3`
が"拒否しない"という宣言に過ぎず実際の動作確認実績ではないため、
supportedからunsupported(未検証)へ変更。`docs/RELEASE_CHECKLIST.md`の
該当箇所も同様に修正(以前は3.3/3.4両方をテスト済みと記載していた不備)。
実際にテストスイートを実行し確認したのは3.4.5・3.4.7のみ。

### `ruby`と`bundle`の不一致検出

`vscode/scripts/copy-core.js`に`verifyRubyAndBundleAgree`を追加。
`bundle install`実行後、`ruby -e`で得た identityと`bundle exec ruby -e`で
得たidentityを比較し、engine/version(major.minor)/platformのいずれかが
異なればpackaging自体をhard failさせる(以前はbare `ruby`のidentityのみを
無条件に信頼していた)。実際に`npm run copy-core`で正常系がgreenで
あることを確認済み(このマシンでは`ruby`と`bundle exec ruby`が一致する
ため、実運用上はこのチェックは通過する)。

### vendor依存のversion要件検証

`copy-core.js`に`verifyVendoredGemVersionsSatisfyGemspec`を追加。
`core/ovallsp.gemspec`の`add_dependency`宣言(`prism >= 0.24`、
`rbs >= 3.0`)を読み取り、実際にvendoringされたgemのバージョンが
これを満たすか検証。Bundler自身の依存解決が通常この制約を強制する
ため(実際に`prism`の要求バージョンを`>= 999.0`へ一時的に書き換えて
`bundle install`自体が失敗することを確認済み)、本チェックは
「手で編集されたLockfile」等の想定しにくいケースに対する明示的な
独立した保証として追加した。

### Rosetta/x86_64誤選択の拒否

`vscode/src/test/unit/platformCompatibility.test.ts`に、Apple Silicon
向けmanifest(`arm64-darwin25`)に対しRosetta経由のx86_64 Ruby
(`x86_64-darwin25`)を渡すケースの回帰テストを追加。既存の
`checkBundledCoreCompatibility`のplatform文字列比較で既に正しく
拒否されることを確認(実装変更なし、テストのみ追加)。

### `scripts/vsix_semantic_smoke.rb`の拡張

- fixtureに`App.new.call`を追加し、`textDocument/documentSymbol`
  (ParserServiceによる宣言抽出を検証)と`textDocument/definition`
  (受信者型推論+WorkspaceIndexによる`#call`解決を検証)を追加。
  従来はhoverのみだった。
- `FORBIDDEN_STDERR_PATTERNS`(`[ovallsp] ERROR`、`LoadError`、
  `NoMethodError`、native extension ABI不一致、未処理例外のbacktrace行)
  を導入。マッチした場合、他の全リクエストが成功していてもFAILする。
- `ALLOWED_STDERR_PATTERNS`による明示的allowlist。現状1件
  (このスクリプト自身が`workspaceTrusted`を送らないことによる
  Runtime Agent起動スキップの警告 — 実際のExtensionは必ず送るため
  実運用では発生しない)。allowlistにもforbiddenにもマッチしない
  stderr出力はfail-closedで失敗扱いにする。
- 実機で`ruby scripts/vsix_semantic_smoke.rb <vscode-dir>`を実行し
  全ステップ(hover/documentSymbol/definition/shutdown/no-leftover-
  process/stderr allowlist)がPASSすることを確認済み。
