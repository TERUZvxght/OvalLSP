# Task 033: 0.2.5 — the foundations, and the answers that rested on them

The release the maintainer redefined 0.2.4 into and then had to give up
the number for: a security patch took 0.2.4 (see `031`), and this became
0.2.5. Its goal is `032`'s, verbatim from the maintainer; `029` holds
candidate items produced under a narrower reading and is not the scope.

**Everything here was chosen against two axes and nothing else** — the
general safety obligations that shipping a product creates, and section 0
of `docs/design/docs/01-product-requirements.md`. Where an audit finding
could not be tied to one of them it was left alone, however real.

## What shipped

### Axis A — obligations that hold whether or not section 0 mentions them

**Workspace Trust gates everything that executes.** Trust was read out of
the `initialize` params at `maybe_start_agent` and never kept, so the
three other paths to code execution never asked: restarting the Agent,
`runObservedTests` with a caller-supplied command, and loading a static
plugin. Reproduced before fixing. One predicate now, failing closed
before `initialize` has been handled at all. Six existing examples
encoded the ungated contract — one of them asserting that an untrusted
restart *should* be acknowledged, which was the hole written down as a
requirement.

**The cache is owner-only.** `vscode/PRIVACY.md` says it holds method
bodies from the user's source; it was created at the umask's 0755.
`Observation::Runner` already wrote the same evidence through `Tempfile`,
owner-only — so the project's standard for this data was already stricter
than what its long-lived copy got.

**The shipped artifact is inspected.** The `$HOME` check had never run
against the build a user installs: CI greps an ubuntu-built VSIX, a
different build with different vendored extensions, and the Apple Silicon
workflow had no such step. `release.sh` does it now and refuses on a hit,
calling `/usr/bin/grep` by absolute path — the bare name resolves to a
ugrep wrapper on this machine and skips binary files, which produced a
withdrawn register entry in 0.2.3.

**`release.sh` refuses a token file readable beyond its owner**, which it
had documented and never checked.

### Axis B — section 0's core

Two wrong answers in the thing 1.0.0 *is* — type tracking and method
resolution. Both were **measured before being fixed**, because 0.4 says
frequency decides and estimating is not measuring.

| Defect | Frequency | Verdict |
|---|---|---|
| `scope` named its relation by the owner's last path segment | **13.6% of class basenames are shared across namespaces** (476 of 3,508). A round-3 re-derivation found the companion figure wrong: "63 of 66 `scope` declarations" counted every receiverless call named `scope`, including the routing DSL; real `scope :sym` declarations in that corpus are **2**. The collision rate is what justifies the fix, and it reproduces exactly | ordinary path — fixed |
| RBS type names truncated to their last segment | 240 of 334 loaded RBS types are nested; 27 of their basenames are also classes in the gem corpus | ordinary path — fixed |

The second was one line, and its blast radius was measured **against the
suite, which was the wrong instrument** — see round 2. The suite reported
one failure (`Mutex` now answering `Thread::Mutex`, which is correct and
kept). Driving a corpus found a second consequence the suite had no
fixture for: `String::selector` became capitalised, which switched off
the guard that skips RBS aliases, and `"a.b".tr(".", "")` started being
reported. Measuring a blast radius with a suite measures the blast radius
*the suite can see*.

Both lines were **unpinned** in the sense CLAUDE.md means: every existing
fixture used a top-level class, where the two candidate behaviours give
the same string. The new fixtures use two namespaces holding the same
name — the only shape that can tell them apart.

### Rules that were working against section 0

**The review gate.** "Repeat until a round comes back clean" measured
reviewer exhaustion: `028` declares merge round 8 clean and the next
entry is an external reviewer finding two defects; roughly sixty rounds
are recorded across 0.2.x. A procedure meant to raise accuracy, that does
not measure accuracy and pushes the release away, is 0.4's own failure
arriving through machinery built to serve it. Replaced with a checkable
form — fresh reviewer, method the previous round did not use, method
enumerated — and bounded at three rounds, after which the release ships
with its open findings recorded.

**The register became searchable.** 72 entries, ~4,300 lines, 25 out of
numeric sequence. `scripts/reindex_findings.rb` sorts and generates the
index; the spec calls the script rather than reimplementing it.

## Deliberately not done

- **`024.73`** — `Marshal.load` on plugin output defeats the fork
  boundary. JSON does not fit: declarations legitimately carry real type
  objects. Needs a protocol change; loading a plugin is gated on trust
  meanwhile.
- **The register's retention rule.** Entries are almost never deletable
  because the standard fix leaves a citing comment, so 0 of 72 have been
  removed and the file only grows. That is a change to the citation
  convention, larger than making the file findable.
- **Case-insensitive home-path matching.** Tried, and reverted on
  measurement: it flags 37 lines of ordinary `app/views/users/...`. A
  check that cries wolf 37 times is one people switch off. The rejected
  variant is pinned as *not* matched so the decision reads as a decision.
- **`024.47`'s naming convention decision**, and the remaining `029`
  items. Recorded, not attempted.

## Verified

Recorded per the review arrangement in CLAUDE.md; rounds and their
methods are appended below as they run.

### Round 1 — method `attack`, four findings, all addressed

Not a diff read: the reviewer took each claim the release makes and tried
to break it by running things.

**The release-script pin caught one mutation in six.** Its regexes ran
`(.*\n)*?.*exit 1` across the whole file, and the file has eight
`exit 1`s, so an assertion about one block was satisfied by any of them;
deleting a refusal's own `exit 1` left all four examples green. The
anti-ugrep matcher missed `if ! grep`. Fixed by scoping each matcher to
its `if ... fi` block, executing the PAT refusal against a real 0644
file, and making the artifact check report how many files it inspected
and refuse an implausible count — because the two remaining mutations are
semantic and no text match can see them. Four of six caught now, and the
spec says which two it cannot.

**"The cache is owner-only" was larger than the change.** Only the scope
being opened was tightened, so on a machine with ten projects, opening
one made one private and the other nine kept 0755 directories and 0644
entries — with method bodies in them. The sweep already walks every scope
on every launch, so it tightens them there. Both changelogs corrected:
they said existing caches are tightened "when opened", which was true and
misleading.

**The gate guards callers, not what executes** (`024.74`), and
**`rubyResolver`'s `workspaceRoot` documents a feature that does not
exist** (`024.75`). Both recorded rather than fixed here; the first
changes a return contract, the second is a deliberate deletion that wants
its own change.

What the round attacked and could not break is worth as much as what it
broke: trust end to end over stdio, before and after an untrusted
`initialize`, with a trusted control run proving the null result was a
gate rather than a dead probe; every `spawn`/`fork`/`load` site in
`core/lib` enumerated against the predicate; both naming fixes driven
against the real server, including a search for a case where the new
qualified name is the *wrong* answer, which did not find one.

### Round 2 — method `drive`, one regression and four standing defects

Driven, not read: two worktrees (`origin/main` and this branch), each
printing its own path and revision before running, one side at a time,
separate cache roots, identical client, corpus hashes printed by both
sides and equal. Corpora: `rails_real` with two namespaces holding an
`Order` and a workspace `Stat`; 213 files of installed gem source.

**The regression is recorded above** — nested aliases became capitalised
and ordinary `tr` became an error. The important part is not the line: it
is that this release's record claimed a blast radius measured by the
suite, and the suite had no fixture that could contain it. That claim is
corrected in this file and the general form is now in CLAUDE.md.

**What the round confirmed 0.2.5 actually fixed**, against 0.2.4 on the
same corpus: `Shipping::Order.in_transit.first.` offered exactly one
completion on 0.2.4 — `invoice_reference`, *Billing's* method — and
offers the right ones now. Hover: `Relation[Order]` →
`Relation[Billing::Order]`, `Stat` → `File::Stat`. A `File.stat(path).size`
false positive is gone.

**Four standing defects, none caused by this release, all in section 0's
core**, recorded as `024.76`–`024.79` and documented in
`KNOWN_LIMITATIONS` in both languages:

| | measured |
|---|---|
| `unknown-method` on real gem source | **54 reports, 54 false, 0 true**, over 213 files |
| undefined call through a relation | missed entirely, while the same call via `find` is reported |
| completion vs hover on a shadowed name | disagree on one expression; 0.2.5 fixed two readers of three |
| `Model.first.` | completes to nothing; `Model.scope.first.` completes to 329 |

The first of those is the release's own standard turned on itself: a
check whose entire output on real code is wrong is worse than no check,
by 0.4. They are recorded rather than fixed here because 0.2.5's change
set is closed — and because the fix for two of them is one task about
where a type's answer is produced, which is `024.47`'s subject and is
too large to bolt on.

**Not covered by this round:** signature help, rename, references,
semantic tokens, ERB, and the trust/cache/vendor work, which was round
1's ground.

### Round 3 — method `reproduce`, and three of this release's own claims were false

The method was chosen because twice already in this release a confident
measurement had been overstated in the same direction. It found the same
failure a third time, and two more besides.

**An assertion that could not fail, and a claim built on it.** The
nested-alias spec's control asserted `be_an(Array)` on a method whose
last operation is `map`. The commit said "without it, 'stop checking
arguments' would pass every other example here"; running exactly that
mutation gave 4 examples, 0 failures. The replacement declares a
signature and asserts the report exists — verified by *removing the
check* (1 failure) and by restoring the old guard (2 failures), rather
than by reasoning about it. A second example in the same file
(`delete`/`squeeze`/`count`) passes under both behaviours and is now
labelled as illustrative rather than distinguishing;
`release_script_guard_spec.rb` had the same shape and is gone.

**The file-count guard guarded the wrong thing.** `INSPECTED` was
computed from `$UNPACK_DIR` while the grep took `$UNPACK_DIR` as a
separate argument — so pointing the *grep* somewhere empty left the count
plausible and the script published. Both now read one `INSPECT_ROOT`;
the mutation exits 1 before reaching the publish step.

**"63 of 66 `scope` declarations are namespaced" counted the wrong
thing** — every receiverless call named `scope`, most of them the routing
DSL. Real declarations in that corpus: 2. The fix stands on the 13.6%
basename-collision figure, which reproduced exactly; the sentence is
removed from both changelogs, this file, the source comment and the spec.

**`024.76`'s "all 54 false" had one contestable member** — an abstract
template method genuinely undefined on the class it is called on — and
its itemisation was short by three. Corrected to 53 of 54 in the register
and in both `KNOWN_LIMITATIONS`, with the 54th described rather than
adjudicated away.

**`024.78`'s mechanism was wrong, which changed its fix.** Completion and
hover get the *same* type; the qualification is lost inside
`QueryService#members_of` during member lookup. The entry had pointed the
work at `024.47` on the strength of a divergence that does not exist; it
now points at the member lookup, which is far cheaper.

Reproduced exactly: the collision rate, the nested-RBS counts, the
register's 72/25, the suite at 2,024 with the real-Rails suites actually
running, and the release pin's four-of-six.

**Not re-derivable:** the "1,169 files inspected" figure (needs a built
VSIX; recorded in no tracked file), and `024.77`/`024.79`, whose
measurements went through the real server with a Runtime Agent that the
round's harness did not have. Both are marked in the register as
measured through the server rather than reproduced.

### Shipping decision

Three rounds have found defects, which is the bound. 0.2.5 ships with
`024.73`–`024.79` open and documented, per the rule in CLAUDE.md and
section 0.4: pursuing them further delays a release that fixes two
wrong-answer classes and four security gaps, and the standing defects are
recorded in the terms a user would notice.

### CI found two platform assumptions, and the branch had never been run through it

Both had been failing since `M-1` landed. The 0.2.4 hotfix was cut from a
tag and ran CI; this branch did not until its own pull request, and I had
been reading a green macOS suite as the answer.

**`stat -f` is not portable, and the failure is silent.** The PAT-mode
check tried BSD's spelling first and GNU's second. GNU's `stat -f` means
*file system* status: it succeeds, with output that is not a mode, so on
Linux the variable held garbage and the refusal never fired. Reordered —
GNU rejects nothing, BSD rejects `-c` outright, so GNU-first degrades
correctly both ways. A check whose entire purpose is to refuse, exercised
on one operating system only.

**A fixture named the running platform.** `vendor_bootstrap_spec`'s
"payload built for another Ruby" example used the literal
`x86_64-linux` — another Ruby on the maintainer's Mac, and *this* Ruby on
CI, so the payload was compatible there and nothing was refused. It is
derived from `RUBY_PLATFORM` now, so it is wrong everywhere it needs to
be.

Neither is verifiable here: macOS returns 644 under both `stat` orders,
and there is no Linux available locally. CI is the instrument, which is
the same lesson as the entry above it — the suite measures the radius it
can see.
