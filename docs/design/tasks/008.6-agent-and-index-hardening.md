# Task 008.6: Runtime AgentとIndexの構造的是正

## 背景

Task 008.5（14項目＋実Rails統合テスト＋非ASCIIテスト）は自己レビューの上で完了と判断されたが、その後の独立レビューで不合格となった。指摘は局所的な不具合ではなく、Task 009以降を安心して積み上げるにはLSP基盤側の設計そのものに構造的な穴が残っている、という性質のものだった。

Task 008.6はその指摘10項目への対応である。ユーザーからの明示的な指示は次の通り。

> 今回の目的は個々の箇所を修正することではありません。目的はLSP基盤として将来Task 009以降を安心して積み上げられる状態へすることです。一時しのぎのif文追加や局所修正は禁止します。設計レベルで整理してください。

このため各項目は「報告された症状を消す」のではなく「その症状を生んだ設計上の穴を塞ぐ」ことを目標に実装した。

## 修正内容一覧

1. **Runtime Agentのstdout隔離をFD1レベルで完成させる** — `$stdout`/`STDOUT`定数のRubyオブジェクトレベルの差し替えだけでは、ネイティブ拡張や子プロセスがfd 1へ直接書き込む経路を防げない。`boot.rb`をfd 1自体をdup2でstderrへ向け替える方式に変更。
2. **ERB位置マッピングのUTF-16/非BMP対応** — `RubyRegionExtractor#blank`が文字数（Rubyコードポイント数）単位でプレースホルダーを生成しており、絵文字等の非BMP文字（UTF-16では2 code unit）1文字につき1 code unit分の位置ズレが生じていた。UTF-16 code unit数を保存する方式に変更。
3. **WorkspaceIndexでOpen Buffer優先を構造的に保証** — Cold Indexの「開いていたらスキップ」チェックはcheck-then-actの間にdidOpenが割り込む競合窓を持っていた。`FileSummary`に`source`/`read_sequence`を導入し、`WorkspaceIndex#replace_file`自体がbuffer-vs-disk優先順位を強制する設計に変更。
4. **Registry更新の失敗検知とgeneration guard** — Agent通信失敗（nil）と正常な空配列が区別されておらず、失敗時にRegistryが空で上書きされていた。また再起動をまたいだ古いAgent世代からの遅延応答が新しいAgentのデータを上書きする競合があった。
5. **Workspace境界チェックをファイル単位でもrealpath検証** — symlinkディレクトリのみ境界チェックしており、通常ディレクトリ配下のsymlinkファイル単体は境界チェックを回避できた。
6. **ERB解析経路をParserService#summarize自体へ統一** — Cold Indexだけが独自にERB抽出を行っており、didOpen/didChange/didChangeWatchedFilesの再索引経路は生のHTML+ERBをそのままPrismへ渡していた（一部入力ではクラッシュもあり得た）。
7. **Runtime Agent状態遷移をイベント駆動で一元化** — reader threadがEOF/crashを検出しても、次にrequestが送られるまで`:ready`のまま残っていた。reader thread自身がイベント発生時点で状態遷移するよう変更。
8. **schema変更検知の追加** — `db/schema.rb`・`db/structure.sql`・`db/migrate/**`が監視対象外で、マイグレーション後もModelRegistryが更新されなかった。
9. **belongs_to optional判定にbelongs_to_required_by_defaultを考慮** — `options[:optional] != false`のみを見ており、Rails 5以降のデフォルト設定（`belongs_to_required_by_default: true`）下で明示指定のない`belongs_to`を誤ってoptionalと報告していた。
10. **実Rails CIの必須化** — 実Rails統合テストはローカル開発機にRails/sqlite3が無ければskipする設計だが、CIでskipが起きても検出されない状態だった。GitHub Actionsワークフローを追加し、CI内でskipが発生したらビルド自体を失敗させるようにした。

加えて、独立レビュー（項目1〜5終了時点、項目6〜10終了時点の2回）で計2件の追加指摘を受け、両方とも同一パスで修正済み：

- `WorkspaceIndex#replace_file`のcontent-hash一致による早期returnが、source昇格（disk→buffer）より先に評価されており、内容が偶然一致する開いたファイルでdisk→buffer昇格が起きないケースがあった。
- `AgentProcessManager#stop`の最終状態書き込みが`@status_mutex`を経由しておらず、`agent/shutdown`が引き起こすreader threadのEOF検知と競合して`:stopped`ではなく`:static_only`に着地し得る狭い窓があった。

## 設計変更理由

### 1. Agent stdout隔離（fd 1自体をリダイレクト）

`$stdout = $stderr`のようなRubyオブジェクトレベルの差し替えは、Rubyコードが`$stdout`/`STDOUT`経由で書き込む場合にしか効かない。ネイティブ拡張の`write(2)`直接呼び出しや、対象アプリが`system`/backticks/Open3で起動する子プロセスは、fd 1を継承してそこへ直接書き込める。`boot.rb`はfd 1を`STDOUT.dup`で退避した上で`STDOUT.reopen(STDERR)`（実質`dup2(2, 1)`）を行い、fd 1自体をstderrの送信先へ向け替える。退避した複製fdは`close_on_exec = true`とし、後から起動される子プロセスへ漏れないようにした。

### 2. 位置単位（UTF-16 code unit優先）

LSPの位置は常にUTF-16 code unit単位である。`RubyRegionExtractor`のプレースホルダー生成は、元の文字を「文字数」または「バイト数」で保存する実装では、非BMP文字（絵文字など）でUTF-16単位数とズレが生じる。`Rslsp::TextDocument.utf16_unit_count`をそのまま再利用し、1文字ごとにUTF-16 code unit数と同じ数のASCIIスペースへ置換する方式に統一した。

### 3. Cold Index方式（Open Buffer優先の構造的保証）

`FileSummary`に`source`（`:buffer`/`:disk`）と`read_sequence`（disk読み込み開始前に採番するモノトニックカウンタ）を追加し、`WorkspaceIndex#replace_file`が次を強制する。

- diskはbufferを絶対に上書きできない。
- bufferはdiskを常に上書きできる。
- 同じsource同士は、bufferなら`document_version`、diskなら`read_sequence`（読み込み開始順、書き込み完了順ではない）で順序判定する。

この保証はWorkspaceIndex内部で一度だけ実装されており、Cold Indexや将来追加される背景indexer（Task 009以降）が個別に「開いているか」を確認する責務を負わない。

### 4. Railsモデル/Route reload方式（Registry世代置換とfail-safe）

Agent通信の失敗（nil）と、対象アプリが本当にモデル/ルートを持たない場合（空配列）を区別する。失敗時はRegistryを直前の既知状態（last-known-good）のまま維持する。加えて、再起動によって`@agent_manager`が差し替えられた後に旧世代Agentからの遅延応答が届いた場合、`@agent_restart_mutex`で保護された「現在の`@agent_manager`と同一か」の照合により、古い世代の書き込みを破棄する。

### 5. ERB位置対応方式（抽出の一元化）

`Erb::RubyRegionExtractor`によるHTML→Rubyの変換自体は元々一つの実装だったが、それを「いつ呼び出すか」がCold Indexだけの責務になっていた。`ParserService#summarize`がuriから`.erb`判定を行い内部で変換するよう変更し、宣言抽出を行うすべての経路（didOpen/didChange、didChangeWatchedFilesの再索引、Cold Index）が同じ変換を通るようにした。content_hashは変換前の生ソースから計算し、「ファイルの中身が変わったか」を正しく反映する。

### 6. Agent障害時の状態遷移（イベント駆動・一元化）

`AgentProcessManager`のstatus遷移は、reader threadがEOF/crashを検出した「その瞬間」に更新するよう変更した（`#mark_unavailable`）。requestのタイムアウトも同じメソッドを経由する。状態書き込み自体は`@status_mutex`でcompare-and-setとして保護し、二重トリガーが二重cleanupを走らせないようにした。`#terminate_process`はreader thread自身から呼ばれる場合（`@reader_thread.kill`が自分自身を殺すことになる）は別スレッドへ委譲し、`@terminate_mutex`で並行呼び出しを直列化する。
