# 046 — 0.2.14: making the record true

**Branch: `feat/0.2.14`.** Measured at `6bc31b9`. Every count below was
re-derived at that revision, and where one differs from an auditor's, the
one here is the one that was run.

Asked for by the maintainer, in two parts: close the three gaps the
0.2.13 assessment left open, and audit the whole repository at a root
level for accumulated cruft — "指摘は作業量や手戻りの量を加味せず、とにかく
綺麗にすることにフォーカスを当ててください". Nine auditors over disjoint
areas produced 122 findings; each non-trivial one was then given to a
second agent whose instructions were to *refute* it. **15 survived
adversarial check, 9 were refuted, 28 low-severity carried forward.**

## The hypothesis, and the half of it that was wrong

The maintainer's hypothesis was that documentation has accumulated to the
point of quietly polluting the context of anyone working here.

**Half right, and the wrong half is the one that would have driven the
work.** "Too much documentation" predicts that the cure is volume
reduction. The evidence refuses that reading:

- The largest file in the tree — the 7,596-line register — is the one
  whose discipline is being *followed*. 61 of its 74 resolved entries are
  cited from `core/lib`, `core/spec`, `vscode/src` or `scripts/`. Exactly
  **one** is cited from nowhere outside it.
- `core/lib` is 52.7% comment, and only **7 sentences** repeat across
  files. The heaviest-commented files are guards recording a specific
  incident.
- **Four "delete the accumulation" proposals were refuted**, each because
  the accumulation *was* the deliverable. `024.122`'s five successive
  figures are the record of a measurement going wrong, which
  `CLAUDE.md`'s "A measurement is a claim" section requires. `024.15` and
  `024.47` are named *in `CLAUDE.md`* as the mandated output of its own
  same-place rule.

What the evidence supports is sharper: **the pollution is not at the
front of the context window, it is at the end of every pointer.** The
1,753 lines an agent must read at session start are maintained and
largely true. The rot is in the files an agent reaches *because something
pointed at them*, and **nothing in this tree resolves a documentation
pointer.**

## One release, or several

**This ships as 0.2.14. `0.3.0` stays the capability release the roadmap
already promises.** The maintainer's instruction was conditional — insert
it as 0.3.0 *if* the change is wide enough to deserve a minor version —
and the condition is not met, for a reason that is about meaning rather
than size:

**The minor version in this repository is a claim, and this change set
would make it false.** `045`, both roadmaps, both site roadmap pages and
both README matrices state that 0.3.0 is *the first release that may add
capability*. This change set adds zero capability and changes zero engine
answers. Numbering it 0.3.0 makes the version number itself a wrong
answer — the precise defect class the change set exists to remove.

Supporting: the shift costs **249 edits across 41 files** in two
languages including the public site, and `roadmap_parity_spec` and
`check_site_links` compare per-version item counts, so a half-finished
shift goes red in a way that says nothing about the cleanup. And every
mechanism-only release in this line shipped as a patch — 0.2.11, 0.2.12
(which shipped a whole new guard layer), 0.2.13.

**The structural half already has a home, and it is 0.3.0.** `024.R9` —
"This register outgrew its file, and 0.3.0 moves it" — is the recorded
place for the register restructure. Putting it in 0.2.14 would be
*adding* during a truth pass, which the review-cadence rule forbids.

pointer broke *while being fixed*.

### What they turned out to be

All nine are in. Four changed shape once built, and the changes are the
part worth reading:

- **C2** was to verify `AGENTS.md` names the highest task file on HEAD.
  0.2.14 deleted the number instead — a pointer that must be edited every
  release is wrong most of the time — so the check is that the number
  does not come *back*. `agents_pointer_spec.rb`.
- **C6** needed comment-stripping to mean anything. Its first version
  searched for a cited script's name anywhere in the workflows and specs,
  and `release_script_guard_spec.rb` and `check_home_paths.rb` both
  *name* `make-final-review-bundle.sh` in comments explaining that it was
  deleted — so a plain text search found it and called the gate wired.
  **A check whose evidence is that a string appears somewhere is the same
  mistake as the table it is checking.**
- **C7** could not be a spec until the generator could compare without
  writing: it writes `docs/SBOM.md` in place, so a failing example would
  have left the tree modified. `--check` and `SBOM_PATH` exist for that.
- **C8** found a live hole while being built. Anything not a directory
  was taken as a file, so a mistyped corpus path became a corpus of one —
  the run reported `corpus-files=1`, found almost nothing, and looked
  like a run.

**Every one of the nine is checked by planting the thing it hunts**, not
by observing that it passes: C1 against a path no commit ever carried,
C5 against `07`'s actual pre-0.2.14 command list, C6 against a gate
citing a script nothing runs, C7 against a mutated licence field, C8
against a control that moved. A check that has only ever been seen
passing is `024.109`.

**And two of them tripped `024.126` while being written** — the
self-scanning trap, at its third and fourth occurrences. Both took the
same repair the entry already prescribes (make the example unspellable,
never exempt the file), which is the evidence that the rule sits at the
right level.

**Where a check deliberately does not go**, stated so the absence is a
decision rather than an oversight:

- **`024.90`'s grab-bag shape gets no spec.** Any rule counting bullets
  is guessing at authorial intent, and this repo has rolled back one
  countermeasure aimed at the wrong level (`024.47`). The fix is the
  split plus one legend sentence: *one entry states one defect, with one
  Area and one reproduction.*
- **`03`, `04`, `08`–`11` get a label, not a check.** One header
  sentence each: *this is a pre-implementation brief; where it and the
  code disagree, the code is the answer.*

**And a rule that changes rather than being enforced.** The register's
deletion rule — "a resolved entry is deleted once nothing cites it" —
fires on **zero of 74** entries, because the register is itself in the
tree. It guarantees monotonic growth. It becomes the tombstone form,
which the guard already accepts, and that is `024.R9`'s work in 0.3.0.

## Review rounds

**The finding list goes here as each round reports it.** `024.109` is
what the other arrangement cost — findings that lived only in a session
and were lost when it ended — and `CLAUDE.md` names writing them down as
the rule rather than the courtesy.

**Recorded departure, restated because it must be re-checked each
round:** `041` asks that one round use `drive`. This change set alters no
engine answer — the only `core/lib` edits in the range are two comment
rewrites and one deleted tombstone comment, and the corpus is not
consulted by anything that changed — so `drive` has nothing to compare
and cannot apply. Methods used are `diff`, `attack`, `reproduce`.

**How each round was asked.** Full tool access, the change set as
`main..HEAD`, `CLAUDE.md` and `AGENTS.md` given as the standard to hold
it to, and the instruction to *report anything you consider a defect,
whether or not it looks already known or deliberate*. No exclusion list,
no "concentrate on", no statement about what a clean report would look
like — `024.36` records what those three did to 0.1.15's counts.

Each finding is then given to two independent verifiers with different
lenses: one told to **refute** it and to default to refuted when
uncertain, one asked only whether it **reproduces**. A finding survives
only if neither kills it.

### Round 1 — `diff`

Five readers over the change set, each with a different starting point
(claims, checks, deletions, documents, code) and each free to report
anything anywhere. *Results below as they land.*

### Round 2 — `attack`

Twelve attackers, one guarantee each, told to make it false while every
check stays green. **70 findings survived refutation**; 15 were killed.
Every attacker worked in a clone or reverted, and the tree was verified
clean and at the same HEAD afterwards.

**This round found roughly four times what round 1 did, and the reason is
the method.** `diff` reads what changed; `attack` asks whether a
guarantee *holds*, and almost every one of these is invisible to reading
because the code is correct — it is the code's **reachability** that is
not defended.

The full list, by guarantee. It is long, and it is here in full because
the standing instruction for this pass is that raising a finding without
recording it is not allowed.
