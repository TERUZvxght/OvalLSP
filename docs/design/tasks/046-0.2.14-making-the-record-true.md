# 046 — 0.2.14: making the record true

**Branch: `feat/0.2.14`.** Measured at `6bc31b9`. Every count below was
re-derived at that revision, and where one differs from an auditor's, the
one here is the one that was run.

Asked for by the maintainer, in two parts: close the three gaps the
0.2.13 assessment left open, and audit the whole repository at a root
level for accumulated cruft — "指摘は作業量や手戻りの量を加味せず、とにかく
綺麗にすることにフォーカスを当ててください". Nine auditors over disjoint
areas produced 122 findings; each non-trivial one was then given to a
second agent whose instructions were to *refute* it. **15 survived
adversarial check, 9 were refuted, 28 low-severity carried forward.**

## The hypothesis, and the half of it that was wrong

The maintainer's hypothesis was that documentation has accumulated to the
point of quietly polluting the context of anyone working here.

**Half right, and the wrong half is the one that would have driven the
work.** "Too much documentation" predicts that the cure is volume
reduction. The evidence refuses that reading:

- The largest file in the tree — the 7,596-line register — is the one
  whose discipline is being *followed*. 61 of its 74 resolved entries are
  cited from `core/lib`, `core/spec`, `vscode/src` or `scripts/`. Exactly
  **one** is cited from nowhere outside it.
- `core/lib` is 52.7% comment, and only **7 sentences** repeat across
  files. The heaviest-commented files are guards recording a specific
  incident.
- **Four "delete the accumulation" proposals were refuted**, each because
  the accumulation *was* the deliverable. `024.122`'s five successive
  figures are the record of a measurement going wrong, which
  `CLAUDE.md`'s "A measurement is a claim" section requires. `024.15` and
  `024.47` are named *in `CLAUDE.md`* as the mandated output of its own
  same-place rule.

What the evidence supports is sharper: **the pollution is not at the
front of the context window, it is at the end of every pointer.** The
1,753 lines an agent must read at session start are maintained and
largely true. The rot is in the files an agent reaches *because something
pointed at them*, and **nothing in this tree resolves a documentation
pointer.**

## Root causes

**RC-1 — frozen copies of sources that later became maintained.**
`RUBY_SEMANTIC_LSP_COMPLETE_DESIGN.md` (2,680 lines) concatenates README
+ START_HERE + docs 01–11 as of 2026-07-25, is referenced by **nothing**,
carries the threading model 0.2.7 retracted and the plugin API that never
existed — and **omits part of section 0**, the trusted root every rule in
this repository is subordinate to (4 section-0 headings against the
source's 8). `make-final-review-bundle.sh` has no exclusion for it, so it
ships to every external reviewer under the name "COMPLETE DESIGN", beside
the maintained originals. Same class: `START_HERE.md`,
`IMPLEMENTATION_SEQUENCE.md`, and the dependency manifest in three
hand-maintained copies whose gate reads `目視確認済み`.

**RC-2 — briefs being read as descriptions.** `docs/design/docs/04`–`11`
are pre-implementation briefs from Task 001, and 156 citation lines in
`core/lib` point into the package. Three now describe a product that does
not exist: `05-protocol.md` (three agent requests specified and never
implemented, two shipped ones absent, §5/§6/§8 unimplemented and reading
as contract), `06-plugin-system.md` (**five registration methods, none of
which exists**; the shipped three are `register_declarations`,
`register_generic_rules`, `register_diagnostics`), `07-vscode-extension.md`
(**zero of eight command ids exist**, 8 of 10 settings absent). The
structural cause: `DOCUMENTATION_MAP.md`'s trigger table has **one** row
pointing into `docs/design/docs/`. Twelve documents, one trigger.

**RC-3 — pointers with no resolver.** **19 lines across 17 files** cite
five task filenames that have never existed in any commit. The whole
`plugins/` subsystem and the public SDK document point at one of them.
`024.87`'s **Area** names a file never committed, and it is the first
thing whoever picks up that open user-visible entry will act on.
`scripts/check_site_links.rb` exists and makes exactly this argument in
its own header — scoped to `site/` alone.

**RC-4 — registers whose entries have no second reader.** `024.64` is
open and its body asserts that running `activate()` in CI "was never
added… the reason is cost, not principle" — `ci.yml` has run it since
0.2.12, and `043`'s own *What shipped* table lists `024.64`. A 19-line
section of `024.57` sits inside `024.25`, opening "The table above" about
a table `024.25` does not contain. `024.90` is nine unrelated defects
under one number, and two of them are documented nowhere.
`AGENTS.md`'s work-in-progress paragraph has gone stale for the **third**
time, and the paragraph says so about itself.

**RC-5 — gates cited as green, run by nothing.**
`make-final-review-bundle.sh` (918 lines) is named by `RELEASE_CHECKLIST`
as the enforcement for five gate rows; its `BASELINE_COMMIT` does not
resolve (`fatal: Not a valid object name`) and no workflow, script or
spec invokes it. `test:integration:packaged` is marked ✅ in two rows and
run by no CI job. `verify_sbom_against_vsix.rb` is invoked by nothing.

**RC-6 — a discipline written in prose beside the tool that should
enforce it.** The 0.2.13 assessment's own finding, and it belongs here:
`scripts/corpus_diagnostics.rb` documents in a comment exactly the three
failures `026` records, and checks none of them.

## One release, or several

**This ships as 0.2.14. `0.3.0` stays the capability release the roadmap
already promises.** The maintainer's instruction was conditional — insert
it as 0.3.0 *if* the change is wide enough to deserve a minor version —
and the condition is not met, for a reason that is about meaning rather
than size:

**The minor version in this repository is a claim, and this change set
would make it false.** `045`, both roadmaps, both site roadmap pages and
both README matrices state that 0.3.0 is *the first release that may add
capability*. This change set adds zero capability and changes zero engine
answers. Numbering it 0.3.0 makes the version number itself a wrong
answer — the precise defect class the change set exists to remove.

Supporting: the shift costs **249 edits across 41 files** in two
languages including the public site, and `roadmap_parity_spec` and
`check_site_links` compare per-version item counts, so a half-finished
shift goes red in a way that says nothing about the cleanup. And every
mechanism-only release in this line shipped as a patch — 0.2.11, 0.2.12
(which shipped a whole new guard layer), 0.2.13.

**The structural half already has a home, and it is 0.3.0.** `024.R9` —
"This register outgrew its file, and 0.3.0 moves it" — is the recorded
place for the register restructure. Putting it in 0.2.14 would be
*adding* during a truth pass, which the review-cadence rule forbids.

| Unit | Contents | Release |
|---|---|---|
| **A — the truth pass** | Make every existing statement true or delete it | 0.2.14 |
| **B — the countermeasures** | Nine checks, each closing a class at occurrence ≥3 | 0.2.14 |
| **C — the register restructure** | Tombstones, relocation, the `024.90` split, the move | 0.3.0, as `024.R9`, *before* `024.85` |

**One deliberate exclusion.** The VSIX prune (≈4.4 MB of `.c`/`.h`/`.rbi`
in `core/vendor`) is the only audited item that changes bytes users
install. It stays out of 0.2.14 so the release's own claim — *nothing a
user can observe changed* — stays true, and gets its own 0.3.0 task with
a `verifyVendoredPayload` assertion that the two `.bundle` files survive.

**One amendment to `045`.** Its "the first task is `024.85`" sentence
becomes `024.R9` first: a register is cheapest to move when nothing is
appending to it, and 0.3.0 is a review loop that will append. `045`'s
argument for `024.85` orders the *capability* items and survives intact.

## Order, and why

**No deletion is safe until "nothing cites this" is a question the tree
can answer, and no pointer is worth fixing until the set of destinations
is final.** Both halves have already failed here — 19 citations to five
never-existent files survived because nobody could ask, and `AGENTS.md`'s
pointer broke *while being fixed*.

### A0 — done

`scripts/check_doc_links.rb` inspects **527 tracked files** and finds
**661 documentation citations**. The census it produced on its first run
reproduced the audit exactly: **19 citations, 5 names, 17 files**, every
one in a source comment. Each named a document that exists under a
different filename —

| cited | actual |
|---|---|
| `007-active-record-model-and-local-inference.md` | `007-active-record-snapshot.md` |
| `013-unified-semantic-query-and-lsp-integration.md` | `013-unified-semantic-queries-and-lsp-features.md` |
| `016-guarded-rename-and-preview.md` | `016-guarded-rename.md` |
| `017-rails-dsl-extension.md` | `017-rails-dsl-expansion.md` |
| `018-static-runtime-plugin-api-and-sdk.md` | `018-plugin-api-and-sdk.md` |

— so all 19 were repointed rather than deleted, and the checker is green.
It runs in the suite (`core/spec/meta/doc_links_spec.rb`) and gates in CI.

**These five were fixed before the rest of A4**, out of the stated order,
and the reason is worth recording: a checker that is red on things it can
already resolve produces noise for every later step, so it has to be
green on the resolvable set before it can gate the pass that freezes the
rest of the destinations.

**A0 — the resolver, first and blocking.** `scripts/check_doc_links.rb`
resolves every `docs/**.md`, `tasks/*.md` and `adrs/*.md` path in tracked
content — **source comments included, since all 19 dangling ones live
there** — with a normalisation rule for the `docs/NN-*.md` shorthand (91
occurrences across 39 files; an established shorthand, not an error).
Then record the census in this file, because every deletion in A2 rests
on it.

### A1 — in progress

Done: `024.87`'s Area (`built_in_generic_rules.rb`, never committed →
`generic_rule_registry.rb`), verified by **C3 built first and watched
firing on exactly that entry and no other** — which is the measurement
that the rest of the open entries' Areas are sound. `024.64` closed
against what shipped, with its Round 40 section deleted rather than
corrected because the claim had no surviving half:
`bin_vendor_bootstrap_wiring_spec.rb` had pinned that call before the
section was written. Its one surviving claim became `024.125`.

**Friction found while doing it, and fixed:** a checker that scans all
tracked content scans itself, so an example path written the way a real
one is written becomes a finding about the checker's own comment — and
then the sentence written to *explain* that became one too, because it
quoted the bad form in order to name it. The general rule is in
`check_doc_links.rb`'s header: make an example unspellable as a path
rather than exempting the file, because exempting it would stop checking
a file that carries four real citations.

**A1 — make the register true**, before anything reads it. `045` sends
0.3.0's first session into it, and a session that opens `024.64` today is
told a CI job that exists does not exist.

**A2 — delete the frozen copies**, after A0 proves nothing cites them.
Order matters: `05` and `06` exist byte-identically inside
`COMPLETE_DESIGN`, so deleting the copy first means A3 rewrites each
section once rather than twice — which is the whole failure mode.

**A3 — fix the design package**, with the three `DOCUMENTATION_MAP`
trigger rows in the *same* change, per the map's own rule.

**A4 — fix the pointers**, last, once the destinations are frozen.
Fixing a pointer while its target is still moving is `026`'s persisted
`cd` in prose.

**B — turn the checks on**, each observed failing first.

## The checks

Each closes a class at occurrence ≥3, which is `CLAUDE.md`'s own bar.

| | Class | Check | Fails on |
|---|---|---|---|
| **C1** | a doc path resolving to nothing | `check_doc_links.rb` + a meta spec | any unresolvable doc path in tracked content, source comments included |
| **C2** | `AGENTS.md`'s work-in-progress pointer going stale | extend C1, fenced to that bullet | naming a task file that is not the highest on HEAD |
| **C3** | an open entry whose claim has decayed | every path in an **open** entry's `**Area:**` must exist; plus a release-time step to re-run the reproduction of every entry targeting the release being cut | `024.87` today |
| **C4** | two readers, one text, two grammars | extract `DeferredFindings` into `scripts/`; delete `metadata_of` **and its false comment** | a sub-numbered entry indexed under a dead anchor with the suite green |
| **C5** | a design document going stale with the code | three `DOCUMENTATION_MAP` rows, two of them machine-checked against `core/lib`'s method strings and `vscode/package.json` | the exact drift measured |
| **C6** | a gate cited as green and run by nobody | every script or npm script in `RELEASE_CHECKLIST`'s evidence column must be invoked by `release.sh`, a workflow, or a spec | three today |
| **C7** | a generated artifact maintained by eye | regenerate `SBOM.md` in memory and assert the tracked file matches | the first dependency change reaching one copy |
| **C8** | a corpus run that does not report on itself | `corpus_diagnostics.rb` prints cwd, revision, dirty count, file-list sha256 and loaded VERSION; refuses an empty corpus; takes `--expect-control` | `026`'s three recorded false results |
| **C9** | committing on a partial run | `scripts/preflight.rb` + an installable `pre-commit`, documented in `CONTRIBUTING` | what happened twice in the 0.2.13 session |

**Where a check deliberately does not go**, stated so the absence is a
decision rather than an oversight:

- **`024.90`'s grab-bag shape gets no spec.** Any rule counting bullets
  is guessing at authorial intent, and this repo has rolled back one
  countermeasure aimed at the wrong level (`024.47`). The fix is the
  split plus one legend sentence: *one entry states one defect, with one
  Area and one reproduction.*
- **`03`, `04`, `08`–`11` get a label, not a check.** One header
  sentence each: *this is a pre-implementation brief; where it and the
  code disagree, the code is the answer.*

**And a rule that changes rather than being enforced.** The register's
deletion rule — "a resolved entry is deleted once nothing cites it" —
fires on **zero of 74** entries, because the register is itself in the
tree. It guarantees monotonic growth. It becomes the tombstone form,
which the guard already accepts, and that is `024.R9`'s work in 0.3.0.

Folded in above as **C8** (corpus self-reporting) and **C9** (the commit

document**, since that is the failure this task is about.
