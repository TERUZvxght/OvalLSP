# Task 041: 0.2.11 — the loop's own leavings

What 0.2.10's three review rounds recorded rather than fixed. The branch
is **`feat/0.2.11`**, and `AGENTS.md` names it. `036` records where this
sits on the way to 1.0.0.

## Why this is a release and not an appendix

Nine entries, and they are not a list of odds and ends. Six of them are
one sentence: **this engine asserts absence from evidence that does not
establish absence.** A macro it could not read; a module it has seen one
file of; a `method_missing` on the wrong side; a `ClassMethods` that
belongs to no concern; a constant lookup that stops one step short of
Ruby's. Each was found separately and each is the same mistake.

0.2.10 is why they are here rather than in it. Its `drive` round measured
one attempt at the module half — 41 findings added, 0 removed, every one
false — and the release rolled it back rather than refine a rule that
bought nothing. That is the shape to avoid repeating: a completeness
*heuristic* is worse than no answer, and what these need is a
completeness *proof*.

## `024.110`, and a decision reversed on a measurement

**Fixed.** A bare call in a class or module body that this engine does
not recognise now opens the owner's *class* surface as well as its
instance one — because whatever supplies the macro is exactly the thing
that could not be read, and the engine was giving two contradictory
answers about one fact: declining to report anything the macro might
define, and reporting the macro itself.

**This reverses a decision `024.23` recorded as deliberate.** The
argument for it, in `open_surface_spec.rb`'s own words, was that opening
both surfaces "would make every unreadable macro silence its own report".
It does, and the measurement is why that is the right trade:

| actioncable + activejob + activemodel + activesupport | before | after |
|---|---|---|
| `unresolved-constant` (control) | 1,099 | 1,099 |
| `unknown-method` | **84** | **25** |
| added / removed | — | **0 / 59** |

Every removal sampled was confirmed against the interpreter as a false
report: `ActiveJob::Serializers::SymbolSerializer.instance` (from
`include Singleton`), `Hash.ruby2_keywords_hash`,
`ActionCable::Server::Base.config` (from `cattr_accessor`). What is lost
is the genuinely *mistyped* macro — and this engine has never been able
to tell one from a gem's DSL, so reporting one meant reporting both.

**Seven examples had to change, and six of them were `024.109`'s
category.** `engine_spec` and `server_ancestry_spec` both used a bare
`fixtures :all` as the thing that should be reported, in examples about
an entirely different rule — the Agent-confirmed ancestry gate. With the
class body silenced they would have passed whatever that rule decided.
Both now put the call inside a `def`, which opens nothing, so the rule
under test is again the thing that decides.

## `024.112`, and an expectation that was wrong before it was written

**Fixed.** A bare constant is now looked up through Ruby's second step —
the ancestors of the innermost cref — after the nesting and before Object.
`LocalInferencer` takes a `hierarchy_index` for it; without one the lookup
stops after the nesting, which is what 0.2.10 shipped.

**The first draft of the examples asserted something Ruby does not do.**
They were written in `module App`, and the file's own `before` already
declares `App::Config` — so Ruby's *first* step finds it and the
superclass's namespace never gets a turn. Asked with the fixture the
examples actually build:

```
$ ruby -e '
class Config; def top_only; end; end
module App; class Config; def app_only; end; end; end
class Zbase; class Config; def zbase_only; end; end; end
module App;   class Runner < Zbase; def which = Config; end; end
module Other; class Runner < Zbase; def which = Config; end; end
p App::Runner.new.which     # => App::Config
p Other::Runner.new.which   # => Zbase::Config
'
# ruby 3.4.10
```

Which is the difference between step 1 and step 2, and exactly what
`CLAUDE.md`'s "establish where the expected value comes from" section is
about — the expectation has to be taken from the interpreter *with the
fixture in front of it*, not from the shape of the rule in the abstract.
Two of the three examples failed for the right reason and one for the
wrong one, which is how it was caught.

Corpus, same four gems, control identical at 1,099: **0 added, 0
removed** — the rule only fires where a superclass's namespace declares a
same-named class, which none of these gems do.

## `024.116`, and what the two fixes share

**Fixed.** `declares_method_missing?` asked the index for
`kind: :instance_method` whichever side the lookup was on, so a class
answering `CWithMM.anything` through `def self.method_missing` was judged
closed. And `define_method`/`define_singleton_method` written inside a
block — `%w[a b].each { |n| define_singleton_method(n) { … } }`, which is
how a class generates a family of methods — were dropped by the
block guard in `#record_open_surface`. Those two calls name what they do;
unlike an arbitrary macro they are not a guess, so they open the surface
wherever they are written.

**`024.110` and `024.116` are the same sentence twice.** The engine had
evidence that it could not enumerate an owner's class-level surface — an
unreadable macro in the body, a `method_missing` on that side, a
`define_singleton_method` in a loop — and asserted absence anyway. That
is this release's whole theme, and the corpus says what it was worth:

| actioncable + activejob + activemodel + activesupport | main `9aafed0` | branch |
|---|---|---|
| `unresolved-constant` (control) | 1,099 | 1,099 |
| `unknown-method` | **84** | **25** |
| added / removed | — | **0 / 59** |

Fifty-nine fewer false reports and not one new finding, on four gems
nobody wrote for this engine.

## Review

Three rounds finding defects, then ship with what is open recorded. **The
round's finding list goes in this file as the round reports it.**

**And at least one round is `drive`.** 0.2.10's two reading rounds missed
41 false reports between them, including a defect one of them had just
introduced; the round that ran the product against real Ruby found every
one. A release about what the engine may assert is not reviewed by
reading it.
