## D5: five entries, one question

C1 collected six flags into one value in 0.2.8, and the 0.2.11 stocktake
found `Cref#defines_surface?` read at *one* site in the parser while
`#declares_singleton?` was read at *seven* — so a recorder could still
read one predicate of nine and get the wrong answer. **Collecting the
storage was not collecting the question.**

- **`024.34`** — `Cref#surface_for` is the question a recorder has:
  `[owner, side]` for a definition written here. It differs from
  `#declares_singleton?` in exactly one place, which is this entry.
- **`024.32`** — a written receiver makes a definition a singleton one
  whatever it names, and the owner resolves through the nesting rather
  than concatenating: `def Fetcher.start` inside `class Fetcher` named
  `::Fetcher::Fetcher`, a class that does not exist.
- **`024.117` and `024.111`'s literal half** — Ruby applies a `private`,
  a `module_function` and an `attr_accessor` written in an ordinary
  iterator block to the enclosing body. The frame was containing all
  three. It opens no frame when the owning call's receiver is a
  **literal** — a shape, not a list of names, for the reason
  `#record_open_surface` already gives about setters.
- **`024.33` and `024.31`** — the entry asks for a block to carry a
  *receiver* rather than a boolean, and `Cref#in_eval_block(owner)` is
  that. `K.instance_eval` and `K.class_eval` get the same answer, which
  is Ruby's; a receiver nothing can name records nothing; and a
  `Struct.new`/`Class.new` block's declarations stop being attributed to
  the class the call is written in.

**Two things this cost, both recorded rather than tidied away.** A spec
example was **deleted** because once a literal-iteration block shared the
cref, `024.110` declined about the owner and it could no longer
distinguish anything — `024.110`'s recorded cost arriving in a spec
instead of a corpus. And `024.33`'s fix made
`#block_self_is_module`'s explicit-receiver term unreachable; **the
mutation manifest is what said so**, which is the first time this project
has learned that a line is unpinned from a machine rather than from a
reviewer mutating it by hand.

## D10: 158 sites, none swallowing

Raised by the maintainer, who had noticed the pattern across the codebase
rather than in one place.

`core/spec/meta/rescue_verdicts.yml` names every `rescue` statement in
`core/lib` and what it does with the failure.
`scripts/check_swallowed_failures.rb` fails on a site with no verdict, a
verdict with no site, **and any verdict of `swallows`** — so the column
that would hold an unargued site stays empty. It runs in the suite and
gates in CI.

**60 surface, 98 contained, none swallowing.**

**Three failed the test and were changed rather than argued**, and all
three had the same shape — the fallback *was* the reporting value:

- `LocalInferencer#assigned_ivar_names` answered `[]` on a failed parse,
  and the check that reads it builds a *union*, so one unreadable
  ancestor file silently removed its ivars and every read of one became a
  false report. The layer above already knew to decline; **the failure
  was being caught one layer below the layer that knows what to do with
  it**, which is the commonest form of this and the hardest to see.
- `Engine#ivar_names_tested_for_existence` answered `[]`, which reads as
  "this file is defensive about nothing", turning every `defined?(@x)`
  into a report.
- `Engine#rbs_known_constant?` answered `false` — "RBS does not know this
  name", an assertion made from a question that could not be asked.

**The order was the entry's own condition and it was right.** The policy
went into `CLAUDE.md` *after* the tree obeyed it; writing it first would
have produced a rule with 111 exceptions on the day it appeared.

**An honest limit, recorded in the entry:** 98 arguments were written by
one author in one pass. A `contained` that turns out to be wrong is an
ordinary finding, and the file is where to record that it was.

## D2: the parser's half, and five entries that were never this class

`024.110` is the one 0.2.11 shipped and rolled back the same release. The
one-line change was right; the *reader* was wrong. `#open_surface?`
consulted every link in the chain, and `Class`, `Module`, `Object`,
`Kernel` and `BasicObject` are in every class's — so one bare
`alias_method` in a `core_ext` file said "I cannot enumerate" about the
whole workspace. It ignores a **synthesised** link now, and the claim is
per-owner: *this* class's body was unreadable, and nobody else's.

`024.116`'s residue: `define_method(:x)` names its method as plainly as a
`def` does, and only the open surface was recorded — so calls stopped
being reported while hover, definition and completion answered nothing.

**And D2 shed five entries before building anything**, which is `042`'s
first rule working the way `024.102`'s did not. `024.18` and `024.22`
need a different source of knowledge (the Runtime Agent, their own
Direction); `024.27` and `024.28` are `selectionRange`/`name_location` on
a generated declaration; `024.77` is a receiver's type after a relation
hop, which is D3's.

C1 found its two miscategorised entries by building the mechanism and
discovering they had not moved. **D2 found its five by asking where the
value is produced.** The first cost a release; the second cost an
afternoon's reading.

## What is open

D2's four remaining — `024.76`, `024.83`, `024.91`, and `024.106`'s
second half — share a shape: the completeness proof has to come from a
layer *above* the parser. The index knowing it has seen every file that
reopens a module; the RBS loader knowing its signature set is short.
0.2.13 built the parser's half.

`024.111`'s other half stays open and is narrowed rather than claimed: a
block whose receiver this parser cannot vouch for still gets a frame,
because `included do ... end` really does run its `private` against a
different module.
