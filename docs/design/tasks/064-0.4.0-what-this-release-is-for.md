# 0.4.0 — what this release is for

**Branch:** `release/0.4.0`, merging into `main` by pull request.

## Why this release exists

0.4.0 is the second release that adds user-visible capability, and the first since 0.3.0. `docs/ROADMAP.md` and both READMEs commit to three core features for this release:

1. **Signature help active parameter**: Highlighting the argument the cursor is in (`activeParameter`).
2. **Per-check diagnostic severity & `diagnosticsMode`**: Allowing per-check configuration (`error`, `warning`, `information`, `hint`, `none`) wired into `Diagnostics::Engine`, while strictly keeping `:safe` as the default baseline to prevent false positive diagnostics (Section 0).
3. **Auto-`require` code action**: Providing QuickFix suggestions to add `require "..."` when a constant is unresolved, strictly limited to verified require paths without speculative guessing.

In addition, 0.4.0 processes the queue of 46 deferred issues routed to this milestone (`024.13`, `024.19`, `024.47`, `024.224`, etc.) under explicit retreat lines.

## Architectural & Execution Plan (GPT-6 Astra & Claude Fable 5.1)

The release proceeds in four strictly ordered sequential steps to eliminate YAGNI and ensure zero regressions against Section 0:

### Step 1: `activeParameter` (Signature Help)
- **Status**: Self-contained, zero external dependency.
- **Approach**: Leverage existing `(` and `:comma` token infrastructure in parser service and server. Calculate active parameter index from cursor byte offset without building monolithic AST walkers.

### Step 2: `diagnosticsMode` & Severity Configuration
- **Status**: Connects client options to `Diagnostics::Engine`.
- **Approach**: Feed client configuration through `Server` into `Diagnostics::Engine`. Maintain default `unresolved-constant` as disabled (:safe equivalent) to protect Section 0.

### Step 3: `auto-require` CodeAction
- **Status**: Depends on `unresolved-constant` diagnostic trigger from Step 2.
- **Approach**: Minimal mapping in `GemIndex` for known library constants. Propose file-level insertion only when path is 100% known; decline (no-op) when uncertain.

### Step 4: Resolution of Deferred Issues with Strict Retreat Lines
- **Status**: 46 open issues.
- **Approach**: TDD using the tiered test runner (`test_runner.rb unit`). If any attempt on `024.224` causes regression or false positives, immediately roll back and record acceptance via `release.rb gate --accept 024.224 --reason "退行リスクのため先送り"` rather than delaying 0.4.0.
