# Task 038: 0.2.8 — the parser's bookkeeping, and a file's identity

**A patch.** No capability row moves. `037`'s C1 and C8: the two classes
of defect scheduled here when the open register was sorted by cause.

**The branch is `feat/0.2.8`.** (Named here per CLAUDE.md's residency
rule, and on `main` in `036` and `AGENTS.md`.)

## Why this release exists

`024.102` sorted 57 open defects by how they came about. Five of them —
`024.26`, `024.31`, `024.32`, `024.33`, `024.34` — and every open-surface
defect four releases of review rounds found one at a time share a single
cause: **`ParserService::Visitor` decided a declaration's owner, kind and
visibility from six independent mutable stacks**, read by twelve
recorders, each consulting whichever subset its author remembered. 47
read sites, and none of the six is named after a question a recorder
actually has.

That is not a bug to fix; it is an arrangement under which the next one
is a matter of time. The preventing logic, decided in `037`: one
immutable value answering the questions, pushed in one place, handed to
every recorder. There is then no subset to read wrongly.

`024.98` is the other half — a workspace opened through a symlink shows
every file twice, and one copy can never be cleared, because a uri is
used as an identity without being canonicalised.

## Scope

| | entry | what |
|---|---|---|
| must | `037` C1 | `Index::Cref` replaces the six stacks |
| must | `037` C8, `024.98` | one canonical uri for a workspace and its files |

## What is deliberately not here

`037`'s C2, C3 and C9 — one three-valued query per position, an answer
carrying what it was computed from, and analysis following the settled
state. They are 0.2.9, they are larger, and C2 in particular is the shape
`024.15` and `024.47` were rolled back for.

## Review

Under the arrangement rewritten in 0.2.5: a round closes when a reviewer
that has not seen the change set, using a method the previous round did
not use, reports nothing; three rounds finding defects, then ship with
what is open recorded.

0.2.7 ran four, and the fourth found that the countermeasures added to
prevent a class were themselves ineffective — measured, one by one. The
lesson carried here: **a check is a claim, and it gets a round of its own
aimed at whether it can fail at all.**

## Round 1 — `diff`

Measured, not read: the parser's whole output A/B'd across **3,606
installed gem files and 976 stdlib files**, comparing declarations,
generated-method facts, alias facts, open-surface owners, ancestor facts
and every reference-candidate field. Reference candidates came out
**byte-identical across 634,508 records** — `Module.nesting` ordering,
`def self.x` against `class << self`, and the `block_self_is_module` push
all survive intact. Corpus diagnostics identical on both sides, with
`unresolved-constant` as the control.

And inside that, two flips the refactor did make.

### The Cref introduced the defect it exists to prevent

`#in_method` reset `singleton_context` to false, on the reasoning that a
method body is not a singleton context. **Ruby disagrees**, and the
review round checked with the interpreter rather than with me:

```ruby
class S; class << self; def build; def helper; :h; end; end; end; end
S.build; S.respond_to?(:helper)      # => true
S.new.respond_to?(:helper)           # => false
```

The default definee does not change when a method body opens. So a
nested `def` was recorded as an instance method, and `Sgl.helper` was
reported missing — a wrong answer in the unsafe direction, on code that
runs, introduced by the value whose entire purpose is that one predicate
answers one question. `declares_singleton?` was being read by both "what
would an unqualified `def` here declare" and "what surface can a
receiverless macro here add to", and a method body changes only the
second — which `#defines_surface?` already answers.

**And a test-first example pinned it into place.** The spec asserted
"stops answering singleton inside a method written there" *before* the
code was written; the code was then written to match. Writing the test
first does not make it right, and this one encoded my reasoning rather
than the interpreter's behaviour. It is now the opposite assertion, with
the interpreter's session in the comment.

`#in_namespace` had a smaller version of the same: it reset
`in_method_body`, which the six stacks never did, so a `class` opened
inside a method body — a SyntaxError, but what a buffer looks like
mid-refactor — went silent.

### And the specs were worse than the code

- **The cref spec leaked a monkeypatch across the whole run.** It
  prepended a module to `ParserService::Visitor` in a `before(:all)` and
  never removed it, with its array on `Object`: measured at 4,261 entries
  after three spec files, with production code patched for whatever
  subset `--order random` puts after it. A subclass now, touching
  nothing.
- **The identity spec wrote into the developer's real cache** and started
  `prune_generations` over it — the function CLAUDE.md's "a test that
  deletes things" section is entirely about — three permanent scope
  directories per run, in a cache that had reached 4,322.
  `XDG_CACHE_HOME` is isolated now, as `server_cache_sweep_spec` already
  knew to do.
- **One of its examples could not fail**: it read `@workspace_root` back
  out and compared a pure function applied to both sides of an equality
  the example above had already asserted. It drives a real workspace pass
  now and checks the uri the diagnostics actually arrive under.

### The rest

`rootUri` is read alongside `workspaceFolders` (a client may send folders
with `rootUri: null`, and `rootUri` is deprecated), a named root that
does not exist is refused rather than adopted, and the signature
environment is rebuilt when the root moves — it is built in the
constructor from the cwd, so a client that spawns from the editor's own
directory would otherwise index one tree and read `sig/` from another.

`hunk_sweep.rb` had two: its error check matched only the singular
"1 error occurred outside of examples", so two load errors read as
UNPINNED; and its interrupt handler warned about a dirtied tree instead
of restoring it. The review found this checkout in exactly that state —
one line of `parser_service.rb` reverse-applied, which makes `#summarize`
raise on any file containing an `alias` keyword.

## Round 2 — `drive`

**The workspace-root half survived everything it was driven with.** Eight
scenarios, all correct: `rootUri` on a symlink (every symbol once, and
every path answered is the one the client named); a workspace containing
both a self-referential `lib/up -> ..` and a `mirror -> lib` (settled in
0.2 s, one hit, no walk explosion); a `rootUri` naming a directory that
does not exist; no root at all; `workspaceFolders` only; `rootPath` only;
and a root path containing a space, sent both encoded and unencoded.

**The parser half produced no findings either.** Round 1's A/B had
already compared the whole output across 4,582 files; this round drove
the shapes those stacks used to disagree about — `class << self` against
`def self.x`, `private` in every placement, `attr_*` and `define_method`
inside each, nested modules, `alias` in each context, a `def` inside a
`def`, `Class.new do`, a class reopened across two files — and found
nothing the Cref got wrong.

### Six defects it did find, none of them this release's

Each was A/B'd against `main` before being recorded, and the two that
looked most likely to be mine — a bare class name resolving to the wrong
namespace, and `private` inside `class << self` doing nothing — come out
identical on both sides.

`024.103` (a bare class name inside a namespace answers with an arbitrary
same-named class — a **false positive on working code**, and the call
that really raises is silent), `024.104` (`class_methods do` attributed
to the instance side, with all four features agreeing and all four
wrong), `024.105` (visibility is not recorded for singleton methods at
all), `024.106` (`module_function` and `extend self` produce nothing, and
a module's class-level calls are never checked), `024.107` (an alias is
known to every feature except completion), `024.108` (protected methods
offered on an explicit external receiver).

**Five of the six are 0.2.9's C2 seen from the outside**: one question
asked through four code paths, and an enumeration that cannot say it was
incomplete. `024.103` is the sharpest — it is section 0.4's own example,
a wrong answer on a layout as ordinary as `Billing::Comment` beside an
ActiveRecord `Comment`, and no existing entry covered it.

That is the argument for C2 that this release was not able to make from
the register alone: the entries were there, but a reviewer driving the
product found six more of the same shape in one session.
