## The review loop

Twenty independent rounds have run. Every round's findings were verified
before acting on them; two were rejected as wrong. The last round's
corpus comparison is worth knowing: the branch now produces **391 fewer
`unknown-method` reports than `main`** over the stdlib plus every
installed gem, and **none that `main` did not** — the difference is
entirely block-local variables `main` mis-typed.

### What the rounds found, in one line each

Rounds 1–8 were mostly unpinned lines and false documentation claims.
Rounds 9–20 were increasingly about wrong reports on real code:

- **9** — a view helper's `@ivar` reported as unassigned; the 2,000-file
  cap reported to nobody.
- **10** — the pass's traversal had no order (024.15's shape, new
  reader); helpers re-parsed on every keystroke (17.3ms → 0.26ms).
- **11** — a cache keyed on `document.version`, which restarts at 1 per
  open session.
- **12** — `defined?(@x)` counted as a read; `encoding` matched as a bare
  prefix and ate ordinary prose.
- **13** — a 200-file `didChangeWatchedFiles` blocked the dispatch thread
  13.5s (→ 0.14s); the first pass published the pre-Agent static reading
  project-wide.
- **14** — the batch pass took the *generation*, ending the workspace
  pass at file 1.
- **15** — `parameter_env`'s seed value unpinned (`nil` for every
  parameter on hover, with the suite green).
- **16** — the last two ranking bands unpinned; the batch never exercised
  as a batch.
- **17** — an RBI-declared type reported **incompatible with itself** (11
  instances in the `rbs` gem); a block's body hidden behind the enclosing
  call's type.
- **18** — **every `true`/`false`** reported against a plain-class
  parameter; an operator call's receiver mis-resolved.
- **19** — round 17's own fix produced **230 new `unknown-method` reports
  across the stdlib**; `summarize` 30% slower.
- **20** — a `Data.define`/`Struct.new` class reported incompatible with
  `Object`; the pass restarted itself on its own ancestry answers (9×
  amplification); a whole regex literal coloured as a variable.

### The method that finds these

Fixtures stopped finding defects around round 16. What works is **driving
the engine over large real corpora** — the Ruby stdlib, every installed
gem, this repository's own `core/lib` — and diffing the branch's findings
against `main`'s, then reading every difference. Rounds 17, 18, 19 and 20
each found a wrong report that way and none of them from a fixture. Keep
doing that.

## Process notes worth carrying forward

**The mutation sweep needs three guards, each learned by losing a
verdict to its absence.**

1. Check the edit landed by comparing against the **pre-mutation text**,
   not against `git diff` — a mutation that reverts an *uncommitted* fix
   produces exactly HEAD, and the git check then calls it "did not land"
   and skips the restore, leaving the fix reverted in the tree.
2. Verify every file is byte-identical to its baseline **after each
   mutation**, before scoring the next. A verdict measured against a tree
   a previous mutation failed to restore is not a verdict; this cost one
   ("the delegation gate reads as unpinned" — its predicate was still
   `false` from the run before).
3. Require a real `N examples, M failures` line. Never score off a blank
   string.

**Never `git checkout -- lib/` to clean up after a sweep.** It reverts
the round's own uncommitted work, not just the residue. This happened in
round 20 and cost four fixes that had to be re-applied from the
transcript.

**A spec that passes both ways pins nothing.** Several rounds' findings
were fixtures that could not distinguish the two candidate behaviours —
a band number where ASCII ordering makes both orders identical, a
fixture whose file names and line numbers sort the same way, an
`include(...)` that a *different* guard rejects on its own. When a
mutation survives, ask whether the fixture can see the difference at all
before assuming the line is dead.

**Some decisions are unpinnable and should be deleted rather than
tested.** Three were removed this way — a `data[:receiver] && data[:name]`
guard no input reaches, a `simple_name` map the signature environment
makes redundant, a `[name] +` seed `HierarchyIndex#ancestors` already
contains.

**Cost decisions get a source assertion, not a behavioural one.**
`spec/meta/workspace_index_cost_spec.rb` is the pattern: filter before
sort, `min_by(limit)` over `sort_by.first(limit)`, `touched.uniq`, and
the `SourceLocation` ASCII fast path all live there, because reversing
any of them leaves every answer unchanged and multiplies what a keystroke
costs.

## Judgement call for whoever continues

The loop has not converged: rounds 17, 18 and 20 each found a *new*
wrong-report shape in G15, and each was real. That is not a sign the
rounds are unproductive — each fix was a genuine defect on shipped Ruby —
but it does mean the corpus method will keep finding shapes for as long
as it is pointed at new corpora, and "no findings" may not be reachable
by continuing to widen the search.

The question worth putting to the user is whether the bar for shipping
0.2.0 is "a round comes back clean" or "the known shapes are fixed or
documented and the remaining search is bounded". Both are defensible; the
first is what the standing instruction says, and the second is what the
evidence suggests will end sooner.

Performance, for what it is worth, is now **better than `main`**:
`summarize` over 400 stdlib files went 2.25s → 1.01s, because the
ASCII fast path speeds up every range conversion and not only the new
ones.
