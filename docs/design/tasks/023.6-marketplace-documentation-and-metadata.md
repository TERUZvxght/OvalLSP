# Task 023.6: Marketplace公開文書一式・package.jsonメタデータ

## Goal

Marketplace公開に必要な文書一式を、実装済みの機能・テスト・コードから
判断できる範囲のみで作成し、`vscode/package.json`のMarketplace
メタデータを追加する。publisher/nameは変更しない。

## Depends on

- Task 023.1〜023.5(記載内容の一次情報源: ADR-0006、version handshake、
  Ruby resolver、darwin-arm64 packaging)

## Out of scope

- publisher ID/Extension nameの決定(Marketplace上の恒久的識別子のため、
  ユーザー確認が必要 — Task 023.8の最終報告で確認事項として提示)
- アイコン画像(PNG, 128x128以上)の追加 — リポジトリ内に権利関係が明確な
  素材が存在しないため、`package.json`へ`icon`フィールドを追加しない
  (存在しないファイルを指すと`vsce package`自体が失敗する上、
  「権利不明な素材を含めない」という制約に反する)。ユーザー提供の素材が
  得られ次第、別途追加する
- GitHub CI/secret scan/release workflow(Task 023.7)
- 実際のMarketplace publish・repository public化

### package.jsonメタデータ

追加: `keywords`(12件、≤30制約内)、`repository`
(`https://github.com/TERUZvxght/OvalLSP.git` — 現状private、
Task 023.7で公開準備を進める)、`homepage`、`bugs`、`galleryBanner`、
`extensionKind: ["workspace"]`(リモート環境非対応の現状でも、Language
Server拡張の標準的な安全側デフォルト)。

version: `0.0.1`→`0.1.0`へ変更(ユーザー指示の「First Preview candidate
versionは0.1.0」に基づく)。**Core側の`core/lib/ovallsp/version.rb`は
`0.0.1`のまま変更していない** — ADR-0006/Task 023.2の設計は
Extension版数とCore版数を意図的に独立管理するため、Extensionの
Previewバージョニングに合わせてCoreを追随させる理由がない。

`publisher`/`name`は指示通り変更していない — Marketplace上の恒久的
識別子であり、ユーザー確認なしに決定できないため(Task 023.8で確認
事項として提示)。

### パッケージ内容の追加検証で見つかった問題と修正

`npm run package`で生成した実際のVSIXを展開し、絶対パス・ユーザー名の
混入を確認したところ、native extension(prism/rbs)のビルドログ
(`mkmf.log`、`gem_make.out`、`ext/**/Makefile`)に、ビルドを実行した
マシンの絶対パス(`/Users/<username>/...`)がそのまま埋め込まれている
ことを発見した。これらはランタイムに一切読み込まれないビルド副産物
(実際にロードされるのはコンパイル済みの`.bundle`ファイルのみ)であり、
削除しても機能に影響しない。

**修正**: `vscode/scripts/copy-core.js`に`removeNativeBuildArtifacts`を
追加し、vendoring直後に`mkmf.log`/`gem_make.out`/`Makefile`を
無条件で削除するようにした(`ALLOW_MISSING_VENDOR`の有無に関わらず
常に実行)。修正後、実際にVSIXを生成し展開して
`grep -rl "/Users/<username>" unpacked/`が0件になることを確認済み。
`ruby scripts/vsix_semantic_smoke.rb`も削除後の状態で再度PASSすることを
確認し、native extension自体(`.bundle`ファイル)が引き続き正しく
ロードされることを確認した。
