# Task 023.2: Extension/Core version・protocol manifest・handshake

## Goal

Extension(VS Code拡張)とCore Server間で、互換性のないバージョン/protocol/
platform/Ruby環境の組合せを、機能リクエストへ進む前に明確な診断とともに
検知できるようにする。

## Depends on

- Task 023.1(配布/更新モデルの決定、ADR-0006)
- ADR-0004(VSIXへのCore同梱)、ADR-0005(platform-scoped VSIXと起動前互換性検証)

## In scope

- build manifest(`PLATFORM_MANIFEST.json`)の拡張(機械生成、手書き同期禁止)
- LSP `initialize`時のExtension/Core双方向のversion/protocol情報交換
- 8種の不一致検知ロジックと診断内容
- `OvalLSP: Show Version Information`コマンドの追加

## Out of scope

- LanguageClient lifecycleの修正(Task 023.3 — 本タスクは既存のstart()呼び出し位置を変更しない)
- `OvalLSP: Restart Language Server`/`OvalLSP: Open Language Server Logs`の新規追加 — 既存の`ovallsp.restartServer`/`ovallsp.showLogs`と重複するため見送り(Task 023.1調査結果)
- Core payload実物の起動時再検証(regressionテストC、Task 023.5のスコープ — 本タスクは比較ロジックのみ)

## 設計

### build manifestスキーマ(既存`PLATFORM_MANIFEST.json`の拡張)

`vscode/scripts/copy-core.js`が`vsce package`時に生成する既存の
`PLATFORM_MANIFEST.json`(ADR-0005、`rubyEngine`/`rubyVersionMajorMinor`/
`rubyPlatform`/`rubyFullVersion`/`generatedAt`)に、以下を追加した(既存の
消費者である`Ovallsp::VendorCompatibility`・`platformCompatibility.ts`は
自分が使うフィールドしか読まないため、追加は非破壊):

```json
{
  "rubyEngine": "ruby",
  "rubyVersionMajorMinor": "3.4",
  "rubyFullVersion": "3.4.7",
  "rubyPlatform": "arm64-darwin25",
  "generatedAt": "...",
  "extensionVersion": "0.0.1",
  "coreVersion": "0.0.1",
  "buildCommit": "<git SHA、取得不能時は\"unknown\">",
  "buildTarget": "darwin-arm64",
  "payloadSha256": "<sha256>"
}
```

全項目`vscode/scripts/copy-core.js`が機械的に生成する(`extensionVersion`は
`vscode/package.json`から、`coreVersion`は`core/lib/ovallsp/version.rb`から、
`buildCommit`は`git rev-parse HEAD`から、`payloadSha256`は生成される
`vendor/bundle`一式のsha256から)。手書き同期は一切ない。

`payloadSha256`は、生成順序の都合上manifestファイル自身を除外して計算する
(manifestは自分自身のhashを含められないため、`PLATFORM_MANIFEST.json`という
ファイル名をルート直下でスキップして計算)。クライアント側の再計算
(`versionInfo.ts`の`computeBundledPayloadSha256`)も同じ除外規則で実装し、
アルゴリズムが乖離しないようにした。

### LSP `initialize`時の交換

- client→server: `initializationOptions.ovallspClient = { extensionVersion, protocolVersion }`。Core側はまだこれを消費しないが(本タスクの比較は全てclient側で行う)、将来Core側検証を追加する際にすでにデータが送られている状態にしておく。
- server→client: `InitializeResult`に`ovallspInfo`フィールドを追加(`core/lib/ovallsp/server.rb#ovallsp_info`)。常に`coreVersion`/`protocol`(current/minimumClient/maximumClient/minimumServer/maximumServer)/`ruby`(engine/version/platform)を報告し、`build`はパッケージ済みVSIX(manifest存在時)のみ非nil。

### protocol version

`core/lib/ovallsp/protocol_version.rb`の`Ovallsp::ProtocolVersion`(`CURRENT`/
`MINIMUM_CLIENT`/`MAXIMUM_CLIENT`/`MINIMUM_SERVER`/`MAXIMUM_SERVER`、いずれも
`1`)と、`vscode/src/versionInfo.ts`の`CLIENT_PROTOCOL_VERSION`/
`SUPPORTED_SERVER_PROTOCOL_RANGE`は、既存の`RuntimeAgent::Agent::PROTOCOL_VERSION`/
`Plugins::CURRENT_PROTOCOL_VERSION`と同じ「monorepo境界を跨ぐ定数を手で
同期する」パターンで、独立した新規の定数系として追加した(既存流用ではない
— Task 023.1調査で確認済み)。

### 8種の不一致検知(`vscode/src/versionInfo.ts#compareVersionInfo`)

| # | モード | 適用範囲 |
|---|---|---|
| 1 | protocol範囲が交差しない | 全classification(bundled/monorepo/custom) |
| 2 | Core version/buildが標準bundled Coreと不一致 | bundledのみ |
| 3 | payload hash不一致 | bundledのみ |
| 4 | platform不一致 | bundledのみ |
| 5 | Ruby engine不一致 | bundledのみ |
| 6 | Ruby major.minor不一致 | bundledのみ |
| 7 | Core version情報取得不能(`ovallspInfo`欠落) | 全classification |
| 8 | custom Coreのprotocol不一致 | customの場合も#1と同じ判定を適用 |

2-6は`monorepo`/`custom`では意図的にスキップする(ADR-0006保証#9: custom
server pathは互換性チェックのみ、bundled manifestとの一致は要求しない)。

診断内容は`VersionDiagnostic`に集約: Extension version、Core version、
client/server protocol version、実行中Ruby(engine/version/platform)、
期待Ruby(bundled時のみ)、選択されたCoreパス、classification
(bundled/monorepo/custom)、対処方法。

### `OvalLSP: Show Version Information`コマンド

`vscode/src/extension.ts`に追加。対象workspace folderの診断内容を
OutputChannelへ表示し、情報/エラー通知を出す。絶対パス
(`selectedCorePath`)はOutputChannel(ユーザーが明示的に開く)にのみ表示し、
通知ポップアップ自体には含めない(Section 2の要求どおり)。

既存の`ovallsp.restartServer`("OvalLSP: Restart Server")・`ovallsp.showLogs`
("OvalLSP: Show Logs")をそのまま流用し、"Restart Language Server"/
"Open Language Server Logs"という別名の重複コマンドは追加しなかった。
