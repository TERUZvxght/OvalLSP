# Task 035: 0.2.6 — making the undefined-method check honest

**A patch.** No capability row moves: everything here makes the extension
do what it already claims. `docs/PUBLISHING.md`'s own worked example is
0.1.7, which removed two false diagnostics — a change every user sees —
and was a patch for exactly this reason.

**The branch is `feat/0.2.6`.** (Named here per CLAUDE.md's residency
rule, so a session resuming this release finds it from `main`.)

## Why this release exists

Section 0 names **type checking and calls to methods that do not exist**
as what 1.0.0 is. Measured over 213 files of real gem source, driven
through the real server and reproduced by two independent reviewers:

> **54 `unknown-method` reports. 53 of them wrong.**

And the other half:

> `Order.recent.first.no_such_method` is reported by **nothing**, while
> `Order.find(id).no_such_method` is reported normally — and completion
> at that same position already knows the method is absent.

By section 0.4 — a wrong answer is worse than no answer — a check whose
output on real code is almost entirely wrong is **worse than its own
absence**. That is the sharpest statement of the problem and it is the
project's own standard, not an outside one.

This is therefore the highest-value work available toward 1.0.0. Not the
largest, not the most interesting: the one where the foundation is
measurably unsound.

## What is deliberately not here

- **029's `M-2`/`M-3`** (immutable document snapshots, the publish
  funnel). Real, and `M-3` as specified is a no-op — round 1 of 0.2.5
  established that three of its four writers carry no version, so the
  ordering key it rests on does not exist for them. Redesigning that is
  its own release.
- **`024.47`'s naming-convention decision.** L-sized, and 0.2.5's round 3
  removed the argument that had routed `024.78` to it.
- **Restructuring for its own sake.** `024.15` (0.1.12: 47 files, four
  rounds, zero net progress, rolled back) and `024.47` (0.2.1: a rule
  centralised into resolution, rolled back) are the two shapes this
  project has paid for. A proposal here has to say what it costs.

## External input

`034-diagnostics-precision-briefing.md` carries the measurements,
reproductions and code to an external model, and deliberately withholds
this project's own diagnosis — 0.2.5's round 3 disproved one of those
causal claims, and handing it over would have bought a precise answer to
the wrong question.

**Whatever comes back is a proposal, not a finding.** It is reproduced
and measured here before any of it is adopted, on the same terms as
anything else.

## Review

Under the arrangement rewritten in 0.2.5: a round closes when a reviewer
that has not seen the change set, using a method the previous round did
not use, reports nothing; three rounds finding defects, then ship with
what is open recorded.

0.2.5's three rounds found, in order: four defects, one regression this
project introduced plus four standing ones, and three of its own claims
false. The last of those is the reason `reproduce` is worth using again
late rather than early.

## Where it stands

**`unknown-method` over the 213-file corpus: 54 → 6**, control category
accounted for (`024.76` carries the table, the per-change attribution and
the ten that remain). The recall half is closed too: a Union receiver is
now asked branch by branch instead of discarded, so
`Model.scope.first.missing` is reported (`024.77`).

Dynamic `include`/`extend` uncertainty is preserved too, rather than
dropped: an ancestor with no statically-known name now opens the surface
instead of being silently skipped, which is what took the corpus from ten
to nine.

`024.73` is closed: the plugin fork boundary carries JSON that cannot
name a class, and the parent rebuilds the typed values from fields it has
checked, so validation precedes construction. The protocol version stays
at 1 — the entry predicted a bump, and it turned out both ends of the
encoding are Core, so no plugin author sees a change.

`024.79` is closed: `Model.first` inferred nothing while
`Model.scope.first` answered, so the working path was the rarer one. The
fix is delegation rather than another name in a list — `Model.<name>`
asks the relation rules, because `ActiveRecord::Querying` delegates to
`all` — and that immediately exposed the same hole one level down, where
`first` was the only record-returning finder modelled at all.

`024.78` is closed, one level below where 0.2.5's round 3 put it. Round 3
was right that member lookup loses the qualification and wrong about
which component loses it: `WorkspaceIndex#resolve_type_name` matched on a
name's last segment alone, so `File::Stat` resolved to a top-level
workspace `Stat`. A written namespace now constrains the answer — as a
suffix on segment boundaries, not equality, because `Inner::Klass` from
inside `module Outer` legitimately means `Outer::Inner::Klass`. Bare
names are untouched, which is what keeps this clear of `024.47`'s
rollback.

That uncovered `024.82`: a class created by `Foo = Class.new(Bar)` is not
a type this index knows, and the last-segment fallback had been hiding it
behind an unrelated class of the same basename.

Still open in this release: the exact-name member-availability query the
check should be moved onto — which, with the four defects it was meant to
carry now fixed by narrower changes, needs re-arguing from measurement
before it is done at all. The nine that remain are seven
JRuby-only files and two abstract template methods, so the precision half
is done; what is left is the member-lookup path.

### Two things the measurement taught, which are not about diagnostics

Both are recorded because CLAUDE.md's rules exist to be re-earned, and
these re-earned two of them.

**The second sweep, over the four change sets after that one:** 11
behavioural hunks, 8 pinned. The three that were not are all the shapes
this rule already names as expected rather than defects — two `require`
lines (`json`, and `plugins/wire` in `ovallsp.rb`, both for constants the
file uses directly and both loaded transitively by something else), and
the whole-new-file hunk for `Plugins::Wire`, where reverting proves only
that the file exists. Its internal decisions are pinned separately, which
is what CLAUDE.md asks for that shape: `wire_spec` drives each encoding
in turn, and two loader examples fail against the old `Marshal` boundary.

**The hunk sweep found what review did not.** Twelve of fourteen
behavioural hunks were pinned. Of the two that were not, one was
`require "set"` (Ruby 3.4 autoloads it; kept to match the three other
files in `core/lib` that require it explicitly). The other was the
decrement in `WorkspaceIndex#remove_file_locked` that closes an open
surface again — reverting it left the whole suite green, and its absence
means a user who deletes the macro to get their diagnostics back does not
get them back. Nobody reading the diff noticed. A test now pins it.

**A wall-clock assertion resisted three repairs before it admitted it was
measuring nothing.** `server_cold_index_spec.rb` asserted
`elapsed < 1.0` for `initialize` over a 120-file workspace. It flaked
under load — the run takes ~0.55s and almost all of that is loading
signatures. But every attempted fix failed for a *different* reason than
the last:

1. a ratio against an empty workspace — still passed with `ColdIndexer`
   called inline, because indexing 120 two-line files takes ~50ms;
2. slowing the indexing by a second — still passed, because `server.run`
   returns after `exit`, which joins the background tasks, so the number
   always included the indexing whether a client waited or not;
3. timing the *reply* over a pipe with a two-second delay injected —
   still passed, because `dispatch` calls `respond` **before**
   `start_cold_index`. The reply is early by ordering, not by threading.

The property was there all along and no clock could see it. The example
now asserts the reply is already written when indexing begins, and fails
when those two lines are swapped. Worth writing down as the general
shape: *when a timing test flakes, ask what it would take to make it
fail; three of these could not fail at all.*

## The review loop

Two rounds, run against a fixed tree at `8bc7ed4` by reviewers that had
not seen the change set, using `diff` and `drive`. Both found defects, so
neither closed. Every finding is either fixed below or carries a register
number.

### What the rounds found in this change set — fixed

- **`Model.first(3)` inferred a record.** `first`/`last`/`take` answer an
  *Array* when given a count, and the table keyed on the name alone, so
  `recent = User.last(3); recent.map` was reported as an unknown method
  on `User` — a wrong answer where 0.2.5 had no answer, which is the
  trade section 0.4 puts first. The table is keyed on argument count now,
  and the Array shapes are silence rather than a guess (`024.87` holds
  the capability).
- **The open-surface measurement did not reproduce.** Recorded as "24 of
  257 classes, and every name among them can define a method"; measured
  against the shipped code, **52 of 329**, triggered by `warn`,
  `respond_to?`, `lambda`, `<`, `private_method_defined?`. The figures
  came from a prototype that counted only calls written directly in a
  class body while the shipped rule counted calls inside blocks too — so
  the number described a rule nobody ran. Both halves corrected: the
  record, and the rule. A block belongs to the call that owns it, so
  `included do ... end` still opens the surface while `assert_equal`
  inside somebody's `test` block no longer does; setters and operators
  cannot define; and a handful of read-only calls are named. **40 of
  329** now, and every remaining trigger but two can genuinely define.
- **An `include` the workspace cannot identify left the class-level
  surface closed.** `include Singleton` reported `.instance`,
  `include Sidekiq::Worker` reported `sidekiq_options`,
  `include ActiveModel::Model` reported `validates`. A singleton lookup
  now requires the *instance* chain to be identified too, because that is
  where `include` puts a module and `included` hooks are how a module
  adds class methods.
- **`alias_method :create, :new` written above `def new`.** Ruby binds an
  alias to what the target means *at that moment*; the engine bound it to
  the later `def`, and reported "`create` takes 1 argument, but 3 given"
  twice on ActiveSupport's own `TimeZone` — while the same construct in a
  smaller workspace reported "has no method named `create`". Two checks,
  two different wrong answers about one alias. An alias whose target is
  declared later *in the same file* is withdrawn and opens the surface
  instead; earlier or elsewhere is untouched.
- **`extend M` was asked about the wrong side of `M`.** A module reached
  through `extend` contributes its *instance* surface to the class-level
  chain.
- **A recognised DSL called with a splat recorded nothing and stayed
  closed.** `attr_reader(*NAMES)` reported `Bag#a` missing. The exemption
  keys on whether a declaration was actually recorded, not on the name.
- **Seven behavioural lines were unpinned**, including two input
  validations on the plugin boundary this release exists to harden. All
  pinned or removed; the dead one (`bare_name` in `namespace_suffix?`,
  unreachable because rooted names return earlier) is gone.
- **`Cache::Key::SCHEMA_VERSION` was not bumped** when `FileSummary`
  gained a member, so a 0.2.5-shaped entry fails to load and `Store#load`
  rescues that into a silent whole-cache miss. Bumped to 2, and the
  constant and the shape are now one golden pair in a spec — keeping them
  in two files is why it was missed.
- **Six comments and one in `server.rb` still described the boundary as
  `Marshal`-based**, the exact pattern CLAUDE.md's documentation section
  names: grep for the thing being replaced *before* committing.
- **`024.81` claimed `user-visible: no`** while its own prose two
  paragraphs below said a legitimate `include Helpers` contributes
  nothing. The refusal sits in `HierarchyIndex`, which completion and
  go-to-definition read, so it costs members and jumps as well as
  reports. Corrected, and documented in both languages.
- **`024.78`'s control was not a control.** `unresolved-constant` reads
  `resolve_type_name`, which that change rewrites, so by CLAUDE.md's own
  definition it could not come out equal — and the recorded composition
  of the difference was wrong too.
