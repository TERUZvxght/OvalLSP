# Task 035: 0.2.6 — making the undefined-method check honest

**A patch.** No capability row moves: everything here makes the extension
do what it already claims. `docs/PUBLISHING.md`'s own worked example is
0.1.7, which removed two false diagnostics — a change every user sees —
and was a patch for exactly this reason.

**The branch is `feat/0.2.6`.** (Named here per CLAUDE.md's residency
rule, so a session resuming this release finds it from `main`.)

## Why this release exists

Section 0 names **type checking and calls to methods that do not exist**
as what 1.0.0 is. Measured over 213 files of real gem source, driven
through the real server and reproduced by two independent reviewers:

> **54 `unknown-method` reports. 53 of them wrong.**

And the other half:

> `Order.recent.first.no_such_method` is reported by **nothing**, while
> `Order.find(id).no_such_method` is reported normally — and completion
> at that same position already knows the method is absent.

By section 0.4 — a wrong answer is worse than no answer — a check whose
output on real code is almost entirely wrong is **worse than its own
absence**. That is the sharpest statement of the problem and it is the
project's own standard, not an outside one.

This is therefore the highest-value work available toward 1.0.0. Not the
largest, not the most interesting: the one where the foundation is
measurably unsound.

## What is deliberately not here

- **029's `M-2`/`M-3`** (immutable document snapshots, the publish
  funnel). Real, and `M-3` as specified is a no-op — round 1 of 0.2.5
  established that three of its four writers carry no version, so the
  ordering key it rests on does not exist for them. Redesigning that is
  its own release.
- **`024.47`'s naming-convention decision.** L-sized, and 0.2.5's round 3
  removed the argument that had routed `024.78` to it.
- **Restructuring for its own sake.** `024.15` (0.1.12: 47 files, four
  rounds, zero net progress, rolled back) and `024.47` (0.2.1: a rule
  centralised into resolution, rolled back) are the two shapes this
  project has paid for. A proposal here has to say what it costs.

## External input

`034-diagnostics-precision-briefing.md` carries the measurements,
reproductions and code to an external model, and deliberately withholds
this project's own diagnosis — 0.2.5's round 3 disproved one of those
causal claims, and handing it over would have bought a precise answer to
the wrong question.

**Whatever comes back is a proposal, not a finding.** It is reproduced
and measured here before any of it is adopted, on the same terms as
anything else.

## Review

Under the arrangement rewritten in 0.2.5: a round closes when a reviewer
that has not seen the change set, using a method the previous round did
not use, reports nothing; three rounds finding defects, then ship with
what is open recorded.

0.2.5's three rounds found, in order: four defects, one regression this
project introduced plus four standing ones, and three of its own claims
false. The last of those is the reason `reproduce` is worth using again
late rather than early.

## Where it stands

**`unknown-method` over the 213-file corpus: 54 → 10**, control category
accounted for (`024.76` carries the table, the per-change attribution and
the ten that remain). The recall half is closed too: a Union receiver is
now asked branch by branch instead of discarded, so
`Model.scope.first.missing` is reported (`024.77`).

Still open in this release: preserving `include`/`extend` uncertainty
when the ancestor is a dynamic expression — one of the ten is
`Rack::Reloader` extending a module held in a constructor default —
`024.73`, `024.78`, `024.79`, and the exact-name member-availability
query the check should be moved onto.

### Two things the measurement taught, which are not about diagnostics

Both are recorded because CLAUDE.md's rules exist to be re-earned, and
these re-earned two of them.

**The hunk sweep found what review did not.** Twelve of fourteen
behavioural hunks were pinned. Of the two that were not, one was
`require "set"` (Ruby 3.4 autoloads it; kept to match the three other
files in `core/lib` that require it explicitly). The other was the
decrement in `WorkspaceIndex#remove_file_locked` that closes an open
surface again — reverting it left the whole suite green, and its absence
means a user who deletes the macro to get their diagnostics back does not
get them back. Nobody reading the diff noticed. A test now pins it.

**A wall-clock assertion resisted three repairs before it admitted it was
measuring nothing.** `server_cold_index_spec.rb` asserted
`elapsed < 1.0` for `initialize` over a 120-file workspace. It flaked
under load — the run takes ~0.55s and almost all of that is loading
signatures. But every attempted fix failed for a *different* reason than
the last:

1. a ratio against an empty workspace — still passed with `ColdIndexer`
   called inline, because indexing 120 two-line files takes ~50ms;
2. slowing the indexing by a second — still passed, because `server.run`
   returns after `exit`, which joins the background tasks, so the number
   always included the indexing whether a client waited or not;
3. timing the *reply* over a pipe with a two-second delay injected —
   still passed, because `dispatch` calls `respond` **before**
   `start_cold_index`. The reply is early by ordering, not by threading.

The property was there all along and no clock could see it. The example
now asserts the reply is already written when indexing begins, and fails
when those two lines are swapped. Worth writing down as the general
shape: *when a timing test flakes, ask what it would take to make it
fail; three of these could not fail at all.*
