# 045 — 0.3.0: what it is, and what to start with

**The first release that may add capability.** Every 0.2.x release since
0.2.6 has been clearing the way for this one, and
[`036`](036-road-to-1.0.0.md) has deliberately not enumerated it —
"enumerating features before the foundation is measured is how a release
recedes". The foundation is measured now, so this file enumerates it.

## What the public roadmap already promises

`docs/ROADMAP.md`'s 0.3.0 section is the contract, and it is nine items.
They are not nine independent pieces of work — but not in the way this
paragraph said until 0.3.0, when the table below was counted against it.
**Two wait on `024.R7`; five wait on nothing.** This read "five of them
wait on the same one", which is the count of the rows that need only
what already exists with the wrong predicate attached — and it is the
first claim this file makes about the release it orders (`024.292`).

| promise | depends on |

## Where to start, and why it is not the largest item

> **Amended in 0.2.16.** `024.85` was done there rather than here, on
> the argument this section makes: it is the smallest item on the list
> and it needed nothing that did not exist. The public roadmap's 0.3.0
> section is eight items now, not nine, and the first capability task
> below is spent. Nothing else in this file moves — the ordering
> argument for the remaining items is what it was.

**`024.85` — `self.` completes nothing.** `me = self` hovers `""`, and
`self.nope` is not reported while the receiverless `nope` on the line
above is. Bare-prefix completion at the same position works, so this is
`self` specifically.

It is first because it is the smallest thing on the list that a user
meets daily, it needs nothing that does not exist, and **it is a
capability whose acceptance test is a reproduction rather than a
measurement** — which is the shape this project has learned to trust.

Then the **five** that need only what is already built — occurrences,
call hierarchy, go-to-type-definition, inlay hints **and quick fixes**,
which this sentence omitted while the table above marks it "the
diagnostics that already exist" (`024.292`).
an index that answers today, and each adds a row to
`docs/EXTENSION_CAPABILITIES.md` with an E2E example, which
`capability_coverage_spec` already enforces.

**`024.R7` last, and on its own.** It is the largest thing in the
release, it is the only one that needs the Runtime Agent to grow a new

the table above names it in two rows (`024.292`).
0.3.0 one long piece of work with nothing shippable in the middle, which
is the shape `036` warns about.

## What 042's open classes mean for this release

**D2's four remaining entries are the reason `024.R7` exists.**
`024.76`, `024.83`, `024.91` and `024.106`'s second half all share a
shape: the completeness proof has to come from a layer above the parser —
the index knowing it has seen every file that reopens a module, the RBS
loader knowing its signature set is short. **A gem index is exactly that
layer**, which is why the roadmap's first promise and D2's remainder are
the same work seen from two sides.

**D3 is a precondition for two of the nine.** `Article.all.` completing
and `@ivar` completion both answer *about a position*, and `042`'s D3
records that "one query per position" was built as one query about a
*type*. `024.88` is the sharpest instance: completion after `x.` where
`x` is `String | Integer` offers 313 items including `upcase`, and the
diagnostic at the same position takes the opposite and correct view.
**Adding completion capability on top of that is adding to the half that
is wrong.**

So: `024.85` and the four index-only items can proceed. `Article.all.`
and `@ivar` completion should wait for D3, or ship knowing they inherit
`024.88`, which is a decision to make deliberately rather than discover.

**D1, D4, D6, D7, D8, D9, D10** are not preconditions for anything here.

## The rule this release runs under

0.3.0 may add capability. It does not get an exemption from the rest:

- Every capability row gets an E2E example, enforced.
- Every decision a spec claims to pin gets a mutation entry
  (`024.121`'s layer 2, built in 0.2.12).
- Every `rescue` added gets a verdict (`024.122`, and `CLAUDE.md` now
  says catching and continuing is not the default).
- Every change that alters what the engine *asserts* gets a corpus run
  with a control, on a corpus given to both sides identically.

**And the one that matters most for a capability release**: a new
capability that answers *sometimes* is a wrong answer where it does not.
Section 0 does not soften because the release is allowed to add things.

## What "startable" means, concretely

> **Amended in 0.2.14.** 0.3.0 is now **capability-only**. The 35 open
> defects that had been aimed at it are the accuracy line's, and moved to
> `0.2.15` — see [`047`](047-0.2.15-scope.md) and `024.153`. A release
> cannot be the one that adds capability and the one that absorbs
> everything unscheduled, and `docs/PUBLISHING.md` now says a minor ships
> with no open user-visible defect that has no target. The ordering
> argument below is unaffected: it orders the capabilities.

- The branch is **`release/0.3.0`**, and it merges into `main` by pull
  request. This bullet said `feat/0.3.0` until 2026-09-01, when the
  maintainer set one branch per version with no kind prefix — the
  prefix is a claim about a release's contents made before the work
  starts, and 0.2.17 was named a fix and shipped a capability.
  `CLAUDE.md` has the rule.
- **The first task is `024.R9`, the register restructure** — tombstones,
  relocation, and the move. A register is cheapest to move when nothing
  is appending to it, and 0.3.0 is a review loop that will append.
  Amended in 0.2.14 (`046`); the argument below orders the *capability*
  items and survives intact.
- The first capability task was `024.85`, and 0.2.16 took it. Re-run a
  reproduction before starting whichever is first now, and read the
  count from the tool rather than from here — this bullet said "the
  other 33 entries" for two releases while the number moved:
  `ruby scripts/deferred_findings.rb --targeting 0.3.0` lists what this
  release is on the hook for, and `024.41` is what happens to a
  reproduction nobody re-runs — quoted forward for fifteen releases with
  two of its six cases silently moved.
- `024.R7` is scoped, has a written Direction, and is deliberately last.
- Nothing in `042` blocks the first five items, and the two that are
  blocked are named with what blocks them.
