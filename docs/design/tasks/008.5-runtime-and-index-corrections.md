# Task 008.5: 実Rails統合・位置情報・索引整合性の修正

## 背景

Task 001〜008でCore Server／VS Code拡張／Rails Runtime Agentの一通りの機能が実装され、既存テスト（Fake Rails固定資材`rails_minimal`とASCII中心のRubyソース）はすべて合格していた。しかしコードレビューにより、Fake Rails環境やASCII中心のテストでは表面化しない次の性質の問題が見つかった。

- Fake Rails（`fake_routing.rb`/`fake_active_record.rb`）が実Railsの挙動と細部で食い違う（`source_location`の型、`resources`の複数verb命名規則など）。
- Prismのbyte offsetとRubyのcharacter offset、LSPのUTF-16 code unitという3種類の位置単位のうち、実装の一部が誤った単位を比較していた。
- 開いたことのないファイル（Cold Index未実装）、didClose後の未保存内容の残留、分岐後の型/環境マージ未実装など、単一ファイル・単純ケースのテストだけでは踏まない経路にバグが残っていた。

Task 008.5は、Task 009以降の新機能に進む前に、これらを是正するためのタスクである。

## 修正対象（in scope）

1. Runtime Agent起動方式（`bin/rails runner`ではなくplain rubyプロセスとして起動）
2. Route `source_location`のAgent境界での正規化
3. 文字オフセット／UTF-8バイトオフセット／UTF-16 code unitの分離
4. Cold Index（disk起点の初期索引付け）
5. ActiveRecordモデルのeager load・ModelRegistryの世代管理・nullable情報の保持
6. ERB内の同一行複数タグの抽出（Prism構文エラー回避）
7. 条件分岐（if/unless/elsif/修飾子）後の型・環境マージ
8. didClose時のWorkspaceIndex整合性（未保存内容の除去）
9. `_url`ヘルパーのSignature Help表示名
10. ルートのoptional parts（`(.:format)`等）のSignature Help反映
11. `UriUtil`の堅牢化（空白・非ASCII・`#`・`%`・Windows drive/UNC path）
12. Agent異常終了時の状態遷移（`:ready`に固着しない）
13. Runtime Agentのモデル取得のバルク化（`agent/models`）
14. WorkspaceIndexの副索引・Hashデフォルトプロックの副作用除去

加えて、実Rails（Fakeでない`rails`/`activerecord`/`sqlite3` gem）統合テストと、非ASCII位置の一連のテストを追加する。

## 修正対象外（out of scope / non-targets）

- Task 009以降で計画されている高度な型診断・null安全解析
- ERB Synthetic Document化・完全な位置対応の再設計（今回は同一行複数タグの構文エラーのみ是正し、抽出方式自体は維持）
- 任意テンプレートエンジン（Slim/HAML）対応
- `textDocument/hover`の型情報化（Task 001由来の静的プレースホルダーのまま。位置ベース型推論は既存の`rslsp/explainType`カスタムリクエストが担う）
- ClassNode内部へのLocalInferencerのトラバース対応拡張（現状は最上位StatementsNode/DefNodeのみ。既存アーキテクチャ・既存スコープを維持）
- Runtime Plugin機構（AASM等）

## 設計判断

### Runtime Agent起動方式

`bin/rails runner`はRailsの全initializerを実行し終えてからスクリプトに制御を渡すため、boot.rbのstdout保護が间に合わない。そこで`RailsBootstrap.start`はデフォルトで`bundle exec ruby <boot.rb> start <config/environment.rb>`をplain rubyプロセスとして起動する。boot.rb側は起動直後に（1）実プロトコル用の`STDOUT`を退避、（2）`$stdout`を`$stderr`へ切替、（3）`STDOUT`定数自体も`$stderr`に差し替え（`STDOUT`定数を直接使うgem/frameworkへの対策）、（4）その後で対象アプリの`config/environment.rb`を`require`、という順序で保護してからRailsを起動する。

Core Server自身が`bundle exec`で起動されている場合、`BUNDLE_GEMFILE`環境変数が子プロセスへそのまま継承され、対象Railsアプリ自身の`config/boot.rb`（`ENV["BUNDLE_GEMFILE"] ||= ...`）が誤ってCore側のGemfileを指してしまう。`RailsBootstrap.start`はデフォルト起動時に`env: { "BUNDLE_GEMFILE" => nil }`を明示的に渡し、子プロセスでこれを解除する。

### stdout隔離方式

上記の通り、`$stdout`と`STDOUT`定数の両方をプロトコル確立前に退避・差し替える。実Rails統合テスト（`spec/integration/real_rails_spec.rb`）で、通常のinitializerログ・gemの起動時出力・`STDOUT`定数直接使用のいずれもプロトコルフレーミングを破壊しないことを検証している。

### 位置単位の扱い

- **Rubyの文字（codepoint）オフセット**: `TextDocument#position_to_char_offset`。文字列インデックスとして使う場合に用いる（例: `word_at_position`などのテキスト走査）。
- **UTF-8バイトオフセット**: `TextDocument#position_to_byte_offset`（新設）。Prismの`Location#start_offset`/`end_offset`はバイト単位なので、Prism AST位置との比較・包含判定には必ずこちらを使う。
- **UTF-16 code unit**: LSPのwireフォーマット標準。`TextDocument.char_offset_for_utf16`/`byte_offset_for_utf16`で相互変換する。

3者を混同していた具体例（Task 008.5で修正）: `LocalInferencer#infer_at`が文字オフセットをPrismのバイトオフセットと直接比較しており、カーソル位置より前に日本語コメントなど非ASCII文字があるとノード選択がずれていた。修正後は`position_to_byte_offset`を使用する。

### Cold Index方式

LSP `initialize`応答後、バックグラウンドスレッドでワークスペースをdiskから走査し`**/*.rb`・`**/*.rake`・`**/*.erb`を索引付けする（`ColdIndexer`）。`.git`/`node_modules`/`vendor/bundle`/`tmp`/`log`/`coverage`/`public/assets`/`storage`は除外。URI構築には`File.expand_path`によるlogical pathを用い、シンボリックリンクの循環検出・ワークスペース外への逸脱防止にのみrealpathを使う（実際にmacOSの一時ディレクトリがシンボリックリンクである場合に、logical pathとrealpathの取り違えがopen-document-winsルールを壊すことを確認した上での設計）。開いているドキュメントの内容が常にdisk内容より優先される。ファイル読み込みは明示的に`encoding: Encoding::UTF_8`を指定する（指定しないとプロセスのデフォルトロケール、環境によってはUS-ASCIIが使われ、非ASCIIファイルで例外になる）。

### Railsモデルreload方式

開発環境（`config.eager_load = false`）ではまだ参照されていないモデルが`ActiveRecord::Base.descendants`に現れない。Agentは`discover_models`／`agent/model`の呼び出し前に`Rails.autoloaders.main.eager_load`（Zeitwerk）または`Rails.application.eager_load!`（フォールバック）を実行してからモデル一覧・詳細を取得する。失敗時はログのみでAgentを落とさない。`agent/reload`は`sections`（デフォルト`["routes", "models"]`）に応じて`Rails.application.reload_routes!`と`Rails.application.reloader.reload! + 再eager load`をそれぞれ独立に試行し、一方の失敗が他方をブロックしない。

### Registry世代置換方式

`ModelRegistry`に`#replace`（世代全置換）と`#remove`（単一モデル除去）を追加した。`RailsBootstrap`の初期populateは全モデルの`agent/models`バルク応答を`#replace`で一括インストールし、以前の世代にしか存在しないモデルは自動的に消える。`Server#refresh_models`は変更ファイルのモデルのみ`agent/reload(sections: ["models"])`→個別`fetch_model`し、Agentが`NOT_FOUND`を返したものは`#remove`する。`Column`に`nullable`を追加し、Agentが返す`null`情報を破棄せず保持する（`LocalInferencer`はnullableなカラムのアクセサ型を`T | nil`として返す）。

### ERB位置対応方式

`RubyRegionExtractor`は既存の「非コード部分を空白に置換し、バイト長・行数を保つ」方式を維持したまま、同一行で隣接する複数タグ（`<%= @a %><%= @b %>`等）の間に`;`を1文字挿入する（置換前の空白1文字を`;`に差し替えるため、全体の長さは変化しない）。真のSynthetic Document化・位置対応の再設計はTask 008.5の対象外とし、将来必要になった場合の課題として残す。

### Agent障害時の状態遷移

`AgentProcessManager`の状態は`not_started`→`starting`→`ready`→（`static_only`または`stopped`）。従来`agent/status`のタイムアウトのみが`:static_only`への降格を行っていたが、`agent/snapshot`・`agent/model`・`agent/reload`のいずれかがタイムアウト／EOF／不正フレームで失敗した場合も同様に降格するよう`#request_while_ready`に共通化した。read loopの例外捕捉も`FramedReader::EOF`/`IOError`/`Errno::EBADF`に加え`StandardError`全般に広げ、不正フレーム受信でreaderスレッドが黙って死んで`:ready`に固着することを防いだ。降格後もCoreの静的解析機能（parse・WorkspaceIndex・completion等）はAgentに依存しないため引き続き動作する。

## テスト方針

- 既存のFake Rails（`rails_minimal`）ベースのテストは維持し、単体・結合の大部分を高速に検証する。
- 実Rails（`rails`/`activerecord`/`sqlite3`が実際にインストールされているマシンでのみ実行される）統合テストを`spec/integration/real_rails_spec.rb`に追加した。`bundle install --local`がネットワークなしで解決できない環境では自動的にskipされる（fail扱いにしない）。CI負荷が許さない場合は`--tag ~real_rails`で除外できる。
- 非ASCII位置（日本語コメント・"日本語😀"文字列・emoji・UTF-16 2 code unit文字等）を含む fixtureをTextDocument／LocalInferencer単体テストと、Server経由のend-to-endテスト（`server_non_ascii_spec.rb`）の両方に用意した。
- 各修正について、修正前のコードに対してテストが実際に失敗することをgit stash等で確認してから確定させた（テストが何も検出していない「見せかけの合格」を避けるため）。
