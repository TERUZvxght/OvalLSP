# Task 023.5: Marketplace package・darwin-arm64 target・Core更新保証

## Goal

`vsce package`が常にdarwin-arm64専用ターゲットのVSIXを生成するようにし、
ADR-0006の配布/更新モデル(Marketplace更新がCore更新でもある)の
regressionテストA-Gのうち、Task 023.2/023.3/023.4でまだカバーされて
いなかったシナリオを補う。

## Depends on

- Task 023.2(version/protocol manifest)、023.3(lifecycle)、023.4(Ruby resolver/smoke)

## Out of scope

- 実際のMarketplace publish(ユーザーの明示承認が必要、Task 023.8のスコープ)
- 複数プラットフォーム向けVSIX(ADR-0005が明示的に不採用とした選択肢)

## 実装

### darwin-arm64 target固定

`vscode/package.json`の`package`スクリプトを
`vsce package --allow-missing-repository`から
`vsce package --target darwin-arm64 --allow-missing-repository`へ変更。
実機で`npm run package`を実行し、`ovallsp-darwin-arm64-0.0.1.vsix`
(target付きファイル名、1153 files、3.47MB)が生成されることを確認済み
— 汎用(targetなし)パッケージが生成されないことを実地で確認。

### regressionテストA-Gの状態

Task 023.2〜023.4で実装したテストが、A-Gのうち大半を実質的に既にカバー
していることを確認した:

| シナリオ | 状態 | 根拠 |
|---|---|---|
| A: 同一バージョン(E1/C1/P1)の通常起動 | ✅ 既存 | `test:integration`・`test:integration:packaged`が実機で検証済み(Task 023.2完了時点) |
| B: E1/C1→E2/C2の更新、旧Core非起動、Show Version Info反映 | ✅ 本タスクで追加 | `versionInfo.test.ts`の新規テスト(下記) |
| C: Core payload改竄検知 | ✅ 既存 | `versionInfo.test.ts`の"detects a payload hash mismatch"(Task 023.2) |
| D: protocol不一致でのクリーンな停止 | ✅ 既存 | `versionInfo.test.ts`の"detects a protocol range that does not intersect"(Task 023.2) |
| E: custom Coreの非自動更新・誤警告なし | ✅ 既存 | `versionInfo.test.ts`の"never compares...for a custom Core path"(Task 023.2) |
| F: activation中の更新/停止競合 | ✅ 既存 | `clientLifecycle.test.ts`全11テスト(Task 023.3) |
| G: Apple Silicon実行時のaccept/reject | ✅ 既存 | `platformCompatibility.test.ts`のRosetta回帰テスト+既存のRuby version/engine不一致テスト(Task 023.4) |

新たに追加したのはBのみ: `gatherClientVersionInfo`を同一
`extensionRoot`に対して2回呼び、1回目(E1/C1のmanifest)と2回目
(E2/C2のmanifestで上書き)の間で結果が正しく切り替わること、
古いCoreからの応答(E2のExtensionが誤ってC1を起動した場合に相当)を
`compareVersionInfo`が実際に不一致として検知することを検証。
ADR-0006の保証どおり、実際のディレクトリ入れ替えはVS Code自身の
Extension更新機構の責務であり、本コードベースの責務は「ディスクから
毎回読み直し、古い状態をキャッシュしない」ことだけである、という
設計上の境界に沿ったテストスコープとした。
