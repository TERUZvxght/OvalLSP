# Task 037: 0.2.7 — the concurrency foundations under the answers

**A patch.** No capability row moves. What changes is that answers stop
being able to arrive in the wrong order or be read half-written.

**The branch is `feat/0.2.7`.** (Named here per CLAUDE.md's residency
rule, so a session resuming this release finds it from `main`.)

## Why this release exists

`036-road-to-1.0.0.md` put `029`'s `M-2` and `M-3` here, and `024.56` is
the reason: a reproduced publish sequence for a closed file — **findings,
the clear, the findings again** — present in *every shipped build*,
carrying a `0.2.4` target it has now missed three times.

It is user-visible in the plainest way. You close a file and its
diagnostics come back. Section 0.4 asks whether a path is one people
walk; closing a file is not a corner.

Two more of the same shape, neither observed but both established by lock
inventory rather than by argument: a background publish could pair
old-text findings with a **new version number** — which the client's
staleness filter then *accepts*, because the number looks current — and
position arithmetic could run new text against stale offsets.

## Scope

| | entry | what |
|---|---|---|
| must | `029` M-2 | `TextDocument` becomes an immutable snapshot |
| must | `029` M-3, `024.56` | one publish funnel, with a per-uri memory |
| must | `029` C-3 | the architecture document's threading section, landed with them |

M-2 before M-3, because ordering by a version number means nothing while
text and version can be read torn. C-3 in the same change set, because
otherwise this ships code its own architecture document contradicts —
`029` states that condition explicitly and it is the one this project has
broken most often.

## What is deliberately not here

- **The remaining `024.8x` measurements** from 0.2.6's review rounds —
  `self.` completing to nothing, a constant hovering as its own name, a
  relation that stops being one. Real, daily, and all *missing* answers
  rather than wrong ones, which section 0.4 ranks below a wrong one.
  0.3.0 is where capability moves.
- **`024.83`** (a project that reopens a core class). The largest
  remaining source of wrong reports, and `024.13`'s design question
  rather than a narrowing. It needs a witness that a class exists outside
  the workspace; that is its own task.
- **`029`'s S-1** (one factory for the semantic stack). Recorded there,
  and restructuring for its own sake is what `024.15` cost.

## Review

Under the arrangement rewritten in 0.2.5: a round closes when a reviewer
that has not seen the change set, using a method the previous round did
not use, reports nothing; three rounds finding defects, then ship with
what is open recorded.

0.2.6 ran all three and all three found defects — including two
measurements of this project's own that did not reproduce. The lesson
carried forward: **measure the thing that shipped, not the prototype**,
and prefer an assertion about ordering or ownership to one about a clock.
