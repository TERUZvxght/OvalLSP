ホーム/導入

インストールし、何が動いているかを知る

用意していただく前提はひとつ、Ruby 3.4.x だけ。それ以外は拡張機能の中に入っています。何かが噛み合わないとき、OvalLSP は中途半端に動き出さず、何がどうおかしいのかを伝えます。

インストールの前に

これは初期の Pre-Release ビルドで、対象は Apple Silicon の macOS （darwin-arm64）のみです。それ以外の OS / CPU では同梱のネイティブ依存を読み込まず、推測された構成で動く代わりに診断を表示します。Rosetta 2 経由を含む Intel Mac、そして WSL・Dev Container・Remote SSH はこの Preview では非対応です。

動作要件

Apple Silicon の macOS

公開されている VSIX は vsce package --target darwin-arm64 でビルドされ、そのプラットフォーム向けにコンパイルされた Prism と RBS のネイティブ拡張を同梱しています。

インストール済みの Ruby 3.4.x

明示的な ovallsp.rubyExecutablePath、あるいは mise、asdf、 rbenv、 Homebrew（/opt/homebrew）のいずれかで検出できる必要があります。検証しているのは 3.4.5 と 3.4.7 です。3.4 ちょうどである必要があります。VSIX はビルド時のバージョン向けにコンパイルされたネイティブ拡張を同梱し、それ以外を拒否するため、3.3 の環境では機能が縮退するのではなく不一致のメッセージが出ます。Core のソース自体は 3.3 にも対応していて CI も両方で走らせていますが、それが意味を持つのはチェックアウトから Core を動かす場合だけです。

VS Code 1.85 以上

engines.vscode: ^1.85.0 として宣言しています。これより古い VS Code ではそもそもインストールできません。これは意図した失敗方法です。この拡張が登録する言語機能は、そのリリース以前には存在しませんでした。

bundle install も、チェックアウトも、2 度目のダウンロードも不要です。 Core Server とその実行時依存は VSIX に同梱されています。OvalLSP は Ruby 自体をインストールしませんし、できません — 何らかの Ruby 3.4.x がすでに存在している必要があります。その前提さえ満たせば、必要なものは他にすべて揃っています。
インストール

5 分。その大半は VS Code の作業です

  1. 拡張機能をインストール

    Marketplace の UI から、あるいは右のコマンドで。Pre-Release チャンネルで公開されています。

  2. Ruby / Rails プロジェクトを開く

    .rb ファイルを開くと、ワークスペースフォルダごとに Core Server が自動的に起動します。

  3. ワークスペースを信頼する

    プロンプトが出たら信頼して、Rails 対応機能を有効にしてください。Runtime Agent は未信頼のワークスペースでは決して動きません。

  4. 何が動いているか確認する

    OvalLSP: Show Version Information で、拡張機能と Core Server のバージョンが互換であること、そしてどの Ruby が選ばれたかを確認できます。

# Pre-Release ビルドをインストール
code --install-extension teruz.ovallsp --pre-release

起動の進行状況はステータスバーに表示されます。

Ruby の解決

OvalLSP はどうやって Ruby を見つけるか

以下の順に探し、最初に見つかったものを使います。VS Code を Dock や Spotlight から起動した場合、その PATH にはシェルの追加設定が含まれないことがあります。ターミナルでは動く Ruby が拡張機能から見えない、という現象のほとんどはこれが原因です。

その場合は ovallsp.rubyExecutablePath を明示的に設定するか、下記のバージョンマネージャ経由で Ruby を入れてください。いずれも PATH に依存せず検出されます。 OvalLSP: Show Environment Diagnostics を実行すると、何を試し、各候補をなぜ採用／却下したかがそのまま確認できます。

  1. 明示的な設定

    ovallsp.rubyExecutablePath が他のすべてに優先します。

  2. mise

    ワークスペースフォルダ自身がピン留めしたバージョンとして解決されます。

  3. asdf

    同様に、.tool-versions はエディタの環境ではなくワークスペースから読まれます。

  4. rbenv

    同様に、.ruby-version 経由で。

  5. Homebrew

    Apple Silicon のプレフィックス /opt/homebrew。

  6. シェルの PATH

    最後の手段であり、Dock からの起動で最も欠けやすい経路です。

うまくいかないとき

トラブルシューティング

役に立つ順に並べています。OvalLSP は静かに縮退するのではなく、はっきり失敗するように作られているので、たいていは最初の 3 つのどれかに答えがあります。

Ruby ファイルを開いても何も起きない

まず OvalLSP: Show Logs で生の出力チャンネルを確認し、続いて OvalLSP: Show Environment Diagnostics で Ruby の解決結果を確認してください。最も多い原因は、ターミナルからは見えているのに拡張機能ホストからは見えない Ruby です。

バージョンが一致しないと表示される

起動時に拡張機能と Core Server はバージョン・プロトコル・ビルド・Ruby/プラットフォーム情報を交換します。不一致の場合、OvalLSP は機能リクエストを送る前に停止し、縮退したセッションの代わりに診断を表示します。よくある原因は、以前のバージョンが残したプロセス、正しくインストールされなかったペイロード、互換性のないカスタム ovallsp.server.path です。 OvalLSP: Show Version Information で検出内容を確認してください。

Rails 固有の機能が動かない

OvalLSP: Restart Rails Agent を試し、次にワークスペースが信頼済みかを確認してください。 Runtime Agent は未信頼のワークスペースでは決して起動しません。ステータスバーが Ready (static) なら、エージェントは寄与していません。また、エージェントが起動を試みるには、ワークスペースのルート直下に bin/rails が必要です。

結果が古い／インデックスがおかしい

OvalLSP: Re-index Workspace でフルの再インデックスを強制できます。永続キャッシュが壊れているように見える場合、キャッシュは ~/.cache/ovallsp/ にあり、ワークスペース・Ruby・Prism・Gemfile.lock・RBS の組み合わせでキー付けされています。該当ディレクトリを削除すれば、新規にインデックスし直します。

候補がすべて二重に出る

ほぼ確実に、同じウィンドウで別の Ruby 言語サーバー拡張が有効になっています。 VS Code は登録されたプロバイダの結果を「選ぶ」のではなく「まとめて」返すため、ホバー・補完・定義ジャンプで両方の結果が同時に出ます。 Shopify の Ruby LSP と並べて検証した結果、クラッシュもインストール時の競合もありませんでしたが、定義ジャンプの候補は 1 件から 4 件に増えました。これは特定の拡張ではなく VS Code のプロバイダモデルの性質です。OvalLSP の答えだけを見たい場合は、そのワークスペースで他を無効化してください。

ovallsp.server.path は何のためのものですか

同梱のものとは別の Core Server を指すための設定です（このリポジトリに対する開発など）。カスタムパスも同梱の Core とまったく同じようにプロトコル互換性を検査されますが、バージョン・ビルド・ペイロードの比較において「標準の同梱 Core」として扱われることはなく、自動更新もされません。

Core Server はどのように更新されますか

拡張機能と一緒に、アトミックに更新されます。Core は VSIX の中に同梱されているため、別途のダウンロード手順も独立したバックグラウンド更新機構もありません。 VS Code が拡張機能を更新すれば、次にワークスペースをアクティブ化したときにはそのバージョンに同梱された Core が動きます。

それでも解決しない場合は SUPPORT.ja.md に、どのようなサポートがあり、どう依頼すればよいかを記載しています。なお、単独開発で活発に開発中のため、外部からの Issue および Pull Request は現在受け付けていません（CONTRIBUTING.ja.md）。セキュリティ報告は例外です — 脆弱性の報告をご覧ください。
