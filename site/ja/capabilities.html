ホーム/機能マトリクス

検証済みのもの、そうでないもの

軸は 2 つ。何の機能かと、どの環境で動くか。エンドツーエンドのテストがない機能は機能ではなく、テストがスキップされている機能は出荷されていません。この表がそのまま約束であり、載っているものはテストに裏づけられているか、裏づけがないと明示されているかのどちらかです。

検証済み

その環境でエンドツーエンドに検証済み。壊れたら落ちるテストがあります。

未検証

動く可能性は高いものの（エンジンの多くは環境に依存しません）、検証していないので何も保証しません。

0.3.0

未実装。予定されているリリースを示します。「未検証」と併記される場合は、そのリリースで実装予定だがその環境では依然未検証、という意味です。

該当なし

Runtime Agent しか供給できない Rails 由来のデータで定義される機能です。壊れているのではなく、設計上存在しません。

表の読み方

あえて何も言わないセルがある理由

gem を継承したクラスに対する沈黙

未知メソッドの 2 行は、レシーバの継承関係がすべて判明している場合 — ワークスペースのクラス、あるいは Runtime Agent がメソッドを報告する Active Record モデル — にのみ発火します。 gem を継承するクラス（ApplicationController、つまり大半のコントローラやジョブ）では、報告すること自体が推測になるため、意図的に黙ります。これを解消するのが gem の定義のインデックス化であり、その行が 0.3.0 を掲げている理由です。

逆のケース: gem のクラスを再オープンするファイル

gem のクラスを再オープンするワークスペースのファイルは、それを定義するファイルと見た目が同じです。 test/test_helper.rb の class ActiveSupport::TestCase は、あらゆる Rails アプリケーションが持つ典型例で、0.1.6 までは誤検知になっていました。 0.1.7 以降は、そのクラスが本当はどこから来ているのかを Runtime Agent に問い合わせ、静的な継承チェーンの「完全である」という主張を信用せずに検証します。 Runtime Agent がない場合（未信頼のワークスペース、あるいは Rails でない場合）は問い合わせ先がないため、従来の解釈のままとなります。

未定義の「変数」は独立した行ではありません

Ruby ではローカル変数でない裸の識別子は self へのメソッド呼び出しとして解析されるため、タイプミスした変数は同じ未知メソッドのチェックが、同じ制限のもとで報告します。一方、代入されていない @ivar は本質的に別物で（Ruby は例外を投げず nil を返します）、独立した行を持ちます。

「該当なし」は不具合ではなく設計判断です

これらの機能は Runtime Agent しか供給できない Rails 由来のデータで定義されます。未信頼のワークスペースではエージェントが意図的に起動せず、Rails アプリでなければそもそも報告すべきものがありません。

素の Ruby の列は「失敗する予測」ではありません

その大半はおそらく今日でも動きます。1.0.0 を掲げているのは、それを保証するため — Rails の規約に明示的な境界を与え、Rails でないプロジェクトが何を期待してよいかを仕様化するため — であり、これは 1.0.0 が担う 2 つの課題のうちの 1 つです。もう 1 つは残るプラットフォームの公開と検証です。それまでは、この列については何も保証しません。

バージョン番号の意味

パッチは新しく告知するものが無いことを意味します。ユーザーから見える変更が無い、という意味ではありません。パッチでも見えるものは普通に変わります。0.1.14 は約12,000件の誤報を取り除き、Railsプロジェクトなら誰でも気づく変化でした。ここの行が追加されたり「検証済み」に変わったりすることもあります — 前のリリースが当然できると理解されていて実際にはできなかったことを指す行であれば。0.2.1 は4回それをしました。マイナーは機能が告知されたこと、メジャーはユーザーが依存していたものが動かなくなったことを意味します。予定されている行は 0.2.x のような範囲ではなくマイナーリリースを正確に指し、同じバージョンを共有する複数の行は 0.1.6 が5つ出したようにまとめて出ます。

「検証済み」の各項目は EXTENSION_CAPABILITIES.ja.md の行に対応しています。そこには「ユーザーが何をして、何が起きなければならないか」が書かれており、 core/spec/e2e/capabilities_spec.rb と vscode/scripts/verify-installed-extension.sh によって検証されています。

「検証済み」が適用される範囲

実際に実行して検証した組み合わせだけを supported と宣言しています。設計文書のプレースホルダをそのまま宣言することはありません。

組み合わせ 区分 根拠
macOS, Apple Silicon（darwin-arm64） supported 開発環境そのもの。全テストスイート、VSIX パッケージング、VSIX セマンティックスモークがここで green。
Ruby 3.4.x supported Core のテストスイートを 3.4.7 と 3.4.5 の両方で実際に実行し green。
Rails 8.1 supported 実 Rails 統合テストのフィクスチャが ~> 8.1 をピン留めし、CI もこのバージョンを明示的にインストール。
Ruby 3.3 / 3.5 未検証 required_ruby_version >= 3.3 は「3.3 を拒否しない」という宣言にすぎず、実行した証拠ではありません。
Rails 7.x 以前 未検証 テストしているのは Rails 8.1 のみ。一部の挙動は Rails 7.1 以降のデフォルトを前提としています。
Linux unsupported CI は ubuntu-latest で Core と TypeScript のスイートを green で実行していますが、公開 VSIX のネイティブペイロードは darwin-arm64 専用で、実機インストールは未検証です。
Windows unsupported RubyInstaller の検出ロジックは実装済みですが、実機検証は行っていません。
macOS Intel / Rosetta 2 unsupported x86_64 の Ruby は同じプラットフォーム互換性チェックで拒否されます。
WSL / Dev Container / Remote SSH unsupported 未検証。
