ホーム/セキュリティとプライバシー

ローカルのツールであり、ローカルに留まります

OvalLSP はネットワークのリスナーを持たず、実行時にネットワークリクエストを行いません。この種のツールで実際に問題になるリスクはそれとは別のものであり、「起こらないはず」で済ませず、明示的に扱っています。

テレメトリなし 分析 SDK も、クラッシュレポータも、利用状況の追跡もありません
通信なし Core にも拡張機能にも送信系の HTTP クライアントは存在しません
アップロードなし ソースコードが端末の外に出ることはありません
脅威モデル

ここで本当に問題になる 3 つのリスク

stdio で VS Code と話す言語サーバーに、遠隔からの攻撃面はほとんどありません。代わりにあるのは、「どこか他所から来たもの」を実行し、ログに書く習性です。

信頼されていないワークスペース

他人のリポジトリを開いたり、悪意ある Pull Request をチェックアウトしたりしただけで、 Core プロセスや開発者のマシンが侵害されてはなりません。

信頼されていないプラグイン

サードパーティ製の OvalLSP プラグインが、Core の内部状態を乗っ取ったり、 LSP のプロトコルストリームそのものに手を出したりできてはなりません。

ログへの秘密情報の流出

Core は対象 Rails アプリの例外テキストをそのままログに出すことが多く、そこはまさに資格情報が現れやすい場所です。

対策

それぞれに実際に何をしているか

  • Runtime Agent はフェイルクローズです。 対象アプリケーション自身のコードを実行しうるため、VS Code でワークスペースが明示的に 信頼済み とされたときにのみ起動します。信頼シグナルが欠けている、 false である、そもそも存在しない — いずれの場合も「起動しない」として扱い、既定で許可することはありません。
  • プラグインは本物の OS プロセス境界の内側で動きます。 同一プロセス内の名前空間的なサンドボックスではなく、実際の fork です。 Core の生きた LSP トランスポートにも内部インデックスのオブジェクトにもアクセスできず、境界を越えるのは Marshal 可能な素のデータだけです。
  • 最も権限の高いランタイムプラグインは、未信頼のワークスペースでは一切ロードされません。
  • ログはどこかに書き出される前に秘匿処理されます。 Bearer トークン、Basic 認証、データベース接続文字列、既知のベンダーキー形式、ラベル付きの資格情報は、すべて先に秘匿パイプラインを通ります。
  • すべてのプロトコル境界でバージョンの完全一致を要求します。 Agent ↔ Core も、プラグイン ↔ Core も同様で、不一致は許容せず拒否します。
脅威モデルと対策の完全な一覧は docs/SECURITY_CHECKLIST.md にあり、その要約が SECURITY.ja.md にあります。
プライバシー

端末の外に出るもの: ありません

これは宣言ではなく、実際のコードベースに対して検証されています。 Core Server にも拡張機能にも、ネットワーククライアントのコード、テレメトリ／分析ライブラリ、送信系の HTTP 呼び出しは存在しません。

プロジェクト内で唯一ネットワークを使う場所

パッケージング時、リリースをビルドするマシンでのみ: VSIX に同梱するために、Core の実行時依存（Prism、RBS）を RubyGems.org から取得します。エンドユーザーの端末で起きることは決してありません。

VS Code 自身の Marketplace 更新は VS Code の挙動であり、OvalLSP のものではありません。それ以外に自動ダウンロードや自己更新の仕組みはありません — Core は拡張機能の中に同梱され、拡張機能と一緒にアトミックに更新されます。

ディスクに書かれるもの

出力チャンネルと Core の stderr には、OvalLSP 自身の動作に関する診断メッセージ（起動、インデックスの進行、エラー、バージョンハンドシェイク）が出ます。これらは VS Code の出力パネルに留まり、どこにも送信されません。

OvalLSP 自身がディスクに書くのは $XDG_CACHE_HOME/ovallsp/（この変数が未設定または空なら ~/.cache/ovallsp/）の永続的な解析キャッシュだけです。ワークスペース・ツールチェーンのバージョン・OvalLSP 自身のバージョンでキー付けされています。この中にはソースコードの一部が入ります。解析済みの宣言と型に加えて、各メソッドの本体テキストと各引数のデフォルト式をそのまま、そして各ファイルの絶対パスを保存します。どこにも送信されず、このディレクトリはいつ削除しても安全です。0.2.1 からは、このルート配下のディレクトリを起動時に削除します — このワークスペースの古い世代のうち直近8つを超えたものと、ディスク上に存在しなくなったワークスペースです。0.2.3 からは、消えたワークスペースについては最後に開いた時点から30日間保持します。マウントされていないボリュームは削除されたプロジェクトと見分けがつかないためです。代償として、削除したプロジェクトのキャッシュ済みソースが最大1か月残ります。ディレクトリはいつ削除しても安全です。

このページは以前「ソースコードの中身ではなく」と書いていました。これは 0.1.12 で撤回され PRIVACY.ja.md で訂正されています。ディスクに何が書かれるかの唯一の出典はそちらです。このページは 0.2.0 まで撤回済みの文言を掲げ続けていました。

オプトイン

ランタイム型観測

OvalLSP: Run Tests with Type Observation は、あなた自身のテストスイートを実行し、そこで実際に通ったメソッド呼び出しの「形」を記録して、実測の根拠を型エンジンに戻します。

記録するのは形です — どのクラスのどのメソッドが、いくつのどんな型の引数で呼ばれ、何を返したか。引数や戻り値の値は決して記録しません。実行されるのはあなたが明示的に起動したときだけで、コマンドは ovallsp.observation.testCommand（既定値 bundle exec rspec）に従います。記録された内容はすべて端末内に留まります。 OvalLSP: Clear Observed Types で破棄でき、 OvalLSP: Show Type Evidence でその推論が何に基づいたかを確認できます。

記録するもののうち4つは、ここで名前を挙げておく価値があります。「値ではなく形」という説明からは導けないためです。実行の識別子（開始時刻・Core のプロセス ID・乱数から作られます）、観測したメソッドが入っているファイルのダイジェスト、そのメソッドの行番号、そして実行が終わった時刻です。ダイジェストと行番号は、観測後にそのメソッドが編集された可能性に気づくためだけに使われます。

完全な記述は PRIVACY.ja.md にあり、観測が記録しないものも明記されています。0.2.0 まで、このページの要約は上の4項目を落としていました。出典は PRIVACY.ja.md であり、このページがそこから離れていました。
報告

脆弱性を見つけたら

公開 Issue ではなく、非公開で報告してください。GitHub の非公開脆弱性報告（リポジトリの Security タブ → Report a vulnerability）をご利用ください。

次の情報を含めていただけると助かります。

  • 脆弱性の説明と、想定される影響。
  • 再現手順（関連する場合は、最小の Ruby / Rails プロジェクトのフィクスチャ）。
  • 拡張機能のバージョン、Core Server のバージョン、実行環境。 OvalLSP: Show Version Information の出力が良い出発点になります。

報告にはできる限り速やかに受領の連絡をし、内容を把握したうえで対応時期をお伝えします。対応が済むまでは公開を控えていただけますようお願いします。
