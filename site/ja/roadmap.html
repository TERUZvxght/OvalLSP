ホーム/ロードマップ

各リリースで何ができるようになるか

ユーザーが気づく順に並べています。ここでのバージョン番号は 何が同時に届くか の約束であって、日付ではありません。パッチリリースは設計上ここに現れません — 新しく告知するものがないからです。すでにした約束が実際に果たされるのはパッチです。

patch — 0.1.x

ユーザーから見える変更なし。修正、堅牢化、テスト。機能の行が増えることはありません。

minor — 0.x.0

機能が追加されたリリース。どの機能かは、このページにリリースごとに列挙されています。

major — x.0.0

ユーザーが依存していたものが動かなくなったリリース。完全な定義は docs/PUBLISHING.ja.md にあります。

0.2.0 公開済み

最初の 1 文字からの補完と、開いていないファイルの診断

  • 先に . を打たなくても補完が答えます。ワークスペースのクラス、スコープ内のローカル変数、その場で呼べるメソッドです。0.2.0 ではワークスペースが加わるまでに2文字必要で、0.2.1 でその下限を外したため1文字で足ります。
  • 開いていないファイルの誤りも報告されます。以前は、診断はエディタで開いているファイルにしか存在しませんでした。
  • 型の違う引数を渡すと報告されます。RBS/RBI が型を宣言している場合に限ります。以前は引数の個数しか見ていませんでした。
  • 一度も代入されない @ivar の読み出しが、ERBビューで報告されます。Ruby は例外を出さず nil を返すため、以前は何も知らせるものがなく、ビューがただ空で描画されていました。
  • ホバーと補完に RDoc/YARD のドキュメントが表示されます。レシーバを書いた場合に限ります。
  • セマンティックハイライト。 Ruby の foo はローカル変数か self へのメソッド呼び出しか曖昧です。エンジンはすでにどちらか知っていて、エディタは知りません。ERB テンプレートの Ruby 領域も対象です。
このうち 3 つは Pylance を基準にしています。動的型付け言語の言語サーバーとして、最もよく知られた参照点だからです。プロジェクト全体の診断、hover でのドキュメント表示、セマンティックハイライトの 3 つです。順番で数えず名前を挙げているのは、この一覧の先頭 3 つではないためです。以前のこのページはそう書いていました。
0.2.1 公開済み

誤った報告を減らし、すでに公開していた約束に追いつく

  • レシーバが ] や ) で終わる呼び出しを、未定義メソッドとして報告しなくなりました。 Ruby 3.4.7 の標準ライブラリ・Rails 8.1.3 の5つの gem・minitest に対して、3,747件中1,656件の誤報が消えました。
  • アップグレードが修正を届けるようになりました。 解析キャッシュの鍵に OvalLSP 自身のバージョンが入っておらず、バイトが変わっていないファイルには前のリリースの結果が返り続けていました。
  • 呼び出しではないものについて、ホバー・定義・シグネチャヘルプがメソッドの説明を返さなくなりました — コメント内の単語、def の引数名、メソッドと同名のローカル変数など。

全項目は 変更履歴 にあります。すべてのリリースはそちらに記録しています。

0.2.2 公開済み

ファイルを削除していたテストと、必要だった封じ込め

  • 気づくような変化はありません。このリリースは、このリポジトリ自身のテストスイートにあった欠陥が実行マシンのファイルを破壊したために存在します。公開済みの拡張機能は影響を受けておらず、受けようがありませんでした。
  • キャッシュが行う削除はすべて1つの関数を通るようになりました。キャッシュrootの外のパスを拒否します。各呼び出し側が自分で対象を計算する形をやめました。

全容は 変更履歴 にあります。すべてのリリースはそこに完全な形で記録されています。

0.2.12 リリース済み

検査する道具と、それが見つけたもの

  • private なエイリアスが補完に出なくなりました。 過去の2リリースがこの問題の半分ずつを別々に直しており(片方はエイリアスを補完に入れ、片方は private/protected を除外し)、両者は一度も出会っていませんでした — エイリアスには自分の宣言がなく、可視性の規則は宣言を読むためです。
  • ワークスペースが Object に足したクラスメソッドに、再び届きます。 変更履歴が 0.1.15 以来「0.1.14 より悪くなる唯一の形」と書き続けてきた項目です。
  • 修飾なしの名前で include したモジュールが、メソッドを失わなくなりました。 Ruby は書かれた位置から名前を探します。この拡張機能も、別の名前空間が同じ名前を持つからといって拒否するのをやめました。

機能の追加はありません。このリリースの目的は、3ラウンド連続で 「守るはずの変更に対して落ちることができない example」が見つかった ことへの対処です。spec が「自分が捕まえると主張する変異」を名乗れる ようになり、CI がそれを適用します。初めて正しく動いた実行で、 「意図的な妥協」と文書化されていた死んだコードを見つけ、次に 「出荷済み」と記録され一度も書かれていなかった修正を見つけました。

0.2.11 リリース済み

このエンジンが何を断定してよいか

  • concern のクラスメソッドが、include したクラスに届きます。 class_methods do ブロックも、古い def self.included(base) の綴りも、どちらも「存在しないメソッド」と報告されていましたが、どちらも動きます。
  • module_function :name が、メソッドが別ファイルにあっても働きます。 ホバーも定義ジャンプも補完も何も答えていませんでしたが、3つとも答えるようになりました。
  • 裸のクラス名が、継承元にあるものからも解決されます — Ruby と同じで、名前がたまたま一致するトップレベルのクラスではありません。
  • def self.method_missing で答えるクラスや、define_singleton_method でクラスメソッドを作るクラスが、実際に答える呼び出しについて報告されなくなりました。

機能の追加はありません。Rails の4つの gem での実測では、このリリースは 何も変えません — unknown-method は前後とも84件、コントロールも 同一です。修正はそれらの gem が含まない形に対するものです。1つの変更は 試して取り下げました — 読めないマクロを黙らせる修正は、ワークスペース全体の クラスレベル検査も黙らせ、Rails 自身の実在する潜在エラーを隠しました。

0.2.10 リリース済み

答えが「何から計算されたか」を知っている

  • 大きなファイルでの入力中、質問が古い作業の後ろに並ばなくなりました。 3,900行のファイルでの実測で、入力中に求めたホバーは 1.43秒 → 0.04秒。1回の解析より速い連続入力は、落ち着いた状態について1つの答えを返します。
  • 自分の別のクラスと名前を共有しているクラスが、Ruby と同じように解決されます。 `module App` の中の Config は、`App` が宣言していれば App::Config。自身のメソッドが「存在しない」と報告される一方で実際に失敗する呼び出しが黙殺される、という状態がなくなりました。
  • ActiveSupport::Concern の class_methods do がクラス側に付き、module_function と extend self がメソッドを生みます — どちらのイディオムも以前は何も生んでいませんでした。
  • Core を動かせない Ruby で、中途半端に起動しなくなりました。 4つの文書が「互換性がなければ何も答える前に停止する」と書いていましたが、していませんでした。その Ruby が自前の prism・rbs をロードできるかを尋ねたうえで、停止します。

機能の追加はありません。レビューは3ラウンド。3つ目は変更を読むのでは なく実際の Ruby に対して製品を走らせる方法で、読む2ラウンドがどちらも 見逃していた出荷済み Rails ソース上の41件の誤報告を見つけました — うち1件はその前のラウンドの修正そのものです。いずれもこのリリースには 入っていません。

0.2.9 リリース済み

一つの問いを、一度だけ、正直に

  • 選んだら例外になる名前を、補完が出さなくなりました。 obj. の private メソッドも、other_object. の protected メソッドも、いま書いている位置からは呼べません。private なエイリアスも同様で、これはエイリアスに自分の宣言がなく、可視性の規則が読む先が無かったためにすり抜けていました。
  • 存在するメソッドを「未定義」と報告するのをやめました。 to_s、send、Comparable のようなモジュールが持ち込むメソッドが、受け手によっては未知として報告されていました。インストール済み gem 213 ファイルでの実測で、誤検出は 54 件から 6 件になりました。
  • 存在しない選択肢を署名ヘルプが出すのをやめました。 別のメソッドを override したメソッドは署名が2件出ていましたが、Ruby が呼ぶのは1つだけです。0.2.8 は引数名が親と同じ場合だけを直しており、今回は引数名を変える普通のケースを直しています。

機能の追加はありません。内部では、「この受け手はこのメンバを持って いるか」への答えが、空であることが二つの意味を持つリストではなく なりました。present / absent / unknown の3状態で答え、unknown は受け取った側が推測するのではなく列挙に失敗した当人が作ります。次に 見つかる「分からない理由」が、発見1件につき誤報1件を払うのではなく、 構造として全機能を黙らせます。

0.2.8 shipped

パーサの帳簿と、ファイルの同一性

  • シンボリックリンク経由で開いたワークスペースで、全ファイルが二重に出なくなりました。 拡張機能は解決後のパスで解析し、エディタは開いたパスで会話していたため、2つ目のコピーは決して消せませんでした — エラーを直しても、保存しても、タブを閉じてもです。
  • 定義ジャンプがエディタの使うパスを返します。 辿っても、いま開いているファイルの2つ目のタブが開くことはなくなりました。
  • パーサが宣言の所属先を6つの別々の帳簿から決めるのをやめました。 記録済みの欠陥5件と、直近4リリースの「このマクロが逆側に帰属していた」系の修正はすべて、12箇所がそれぞれ「作者が覚えていた部分集合」を参照していたことから来ていました。

機能の追加はありません。パーサの変更は議論ではなく測定で確認しました — 変更前後の出力全体を gem 3,606 ファイルと標準ライブラリ 976 ファイルで比較し、 参照レコードは 634,508 件がバイト単位で同一でした。

0.2.7 shipped

文書が書きかけで読まれず、publish が順序を外して届かない

  • ファイルを閉じても、そのエラーが残らなくなりました。 背後で既に始まっていた再解析が、閉じたばかりのファイルを再発行していました。誰も開いていないファイルを再発行するものは無いので、そのエラーは「問題」パネルにセッションの間ずっと残りました。これまでの全バージョンにありました。
  • 遅い解析が古い答えを戻すこともなくなりました。 publish は全て、ファイルごとに最後に言ったことを覚えている1箇所を通り、古いものを拒み、ファイルを閉じる操作が常に勝ちます。
  • ファイルの本文・版数・行位置が常に一緒に動きます。 前バージョンでの実測: 並行編集下で、位置を求める 1,977,451 回のうち 1,977,450 回が、どちらの文書のものでもない位置を返していました。この計算はホバー・補完・定義ジャンプの土台にあります。

機能の追加はありません。このリリースには独立したレビューが4ラウンド走り、 publish 規則の最初の実装は直そうとしたものより悪い欠陥を持ち込みました — 2つのラウンドが独立に発見し、全て記録しています。

0.2.6 shipped

未定義メソッド検査を、正直なものにする

  • 動くコードへの誤った「メソッドが無い」報告: 54 → 6 件。 毎回同じインストール済み gem ソース 213 ファイルに対する実測です。読めないマクロを本体で実行しているクラスや、正体を特定できないものを include しているクラスは、推測せず「把握できていない」ことを認めるようになりました。
  • Model.first が答えます。 last と take も同様です。Model.scope.first が答えるのにこちらは何も返さず、より一般的な書き方の方が動いていませんでした。relation を経由した存在しない呼び出しも報告されるようになりました。
  • 名前空間付きで書いた名前が、別の名前空間のクラスで答えられなくなりました。 File.stat(path). はワークスペースの Stat のメンバーを出していましたが、本来の 167 件を出します。
  • プラグインの結果が、オブジェクトではなくデータとしてプロセス境界を渡ります。 親プロセスはストリームが名指ししたクラスを検証前に生成していました。プラグイン側の変更は不要です。
  • 読めないファイル1つでセッションが終わらなくなりました。 インタプリタのスタックを使い切る深さのファイルはプロセスごと落としていました。不正なメッセージフレームも同様です。

機能の追加はありません。KNOWN_LIMITATIONS は減るのでは なく10節増えました。3ラウンドのレビューが、以前から間違っていて今も 間違っていることを大量に計測したためです。誰も述べていない限界は、 誰でも読める限界より悪いからです。

0.2.5 shipped

土台と、その上に載っていた答え

  • モデルの scope が、それが属するモデルについて答えます。別の名前空間に同名クラスがあると、Shipping::Order.recent.first. の補完が別モデルのメソッドを並べ、定義ジャンプは何も見つけませんでした。
  • ネストしたコア型が名前空間を保ちます。File.stat(path) は Stat として答えており、同名のワークスペースクラスに乗っ取られていました。読み込まれる RBS 型 334 種のうち 240 種がネストです。
  • Workspace Trust が実行するすべてを守ります。Runtime Agent だけでなく、再起動・observed tests の実行・プラグイン読み込みも確認するようになりました。
  • キャッシュが所有者のみ読める権限になりました。あなたのソースのメソッド本体を保持していますが、共有マシンでは他の全アカウントから読めていました。

capability の追加はありません。答えの下にある土台と、それが原因で 間違っていた答えのリリースです。

0.2.4 shipped

信頼していないワークスペースが、実行対象を選べていました

  • バイナリやコマンドを指定する設定は、フォルダを信頼するまでワークスペーススコープから無視されるようになりました。制限モードでリポジトリを開くと、ウィンドウを開いた約2秒後、Workspace Trust が参照されるより前に、そのリポジトリが指定したプログラムが実行されていました。ユーザー設定・マシン設定は影響を受けず、静的解析は未信頼でも従来どおり動作します。

セキュリティ修正です。それ以外にエディタの動作は変わらず、capability も 動きません — manifest は元々これを約束しており、本リリースはそれを 真にするものです。

0.3.0

gem が定義しているものを知る

  • Article.all. で補完が出ます。Relation が自分の持つもの——where・order・limit、およびそれらが作るチェーン——を答えます。hover は既に型名を答えますが、Relation 自身の API が何であるかを教えるものが無く、それを供給するのが上の gem 索引です。
  • self. で補完が出ます。いま書いているオブジェクトに対して呼べるメソッドです。前置きのみの補完が既に出している一覧を、ドットの後で。
  • gem を継承したクラスでも未知メソッドが報告される — ApplicationController、つまり大半のコントローラやジョブです。現在は、報告すれば推測になってしまうため、意図的に黙っています。
  • インレイヒント。 推論された型と引数名が、ホバーしたときだけでなくコード中に表示されます。
  • 各診断に対するクイックフィックス。 足りないメソッドを定義する、ルートヘルパ名を直す、引数の個数を合わせる。
  • 型定義へのジャンプ — 呼び出しているメソッドではなく、式が評価されるクラスへ飛びます。
  • コール階層 — 参照の平坦なリストではなく、呼び出し元と呼び出し先をたどれる形で。
  • カーソル下のシンボルの他の出現箇所をハイライトします。 ファイル内が対象です。
  • @ivar の名前を、記号を打った瞬間に補完します。

1.0.0

機能ではなく、保証

このページで唯一、機能を追加しないリリースです。代わりに、機能マトリクスから 2 つの但し書きを取り除きます。

  • 公開するすべてのプラットフォームを検証する。 Apple Silicon だけでなく darwin-x64、win32-x64、linux-x64 も。
  • 素の Ruby プロジェクトを保証する。 Rails だけでなく。エンジンの大半はおそらく今日でも動きますが、それを仕様化も検証もしていません。
それまでは、機能マトリクスの「検証済み」はすべて「macOS Apple Silicon で、Rails プロジェクトで、同梱の Core で検証済み」という意味であり、それ以外は何も保証していません。
選定の方法

この一覧はどう決めたか

各項目は機能マトリクスの行に対応しています。マトリクスの行を持たないロードマップ項目はなく、届くリリースが明示されていないマトリクスの行もありません。 0.2.0 の最初の 3 項目は Pylance を基準にしています。動的型付け言語の言語サーバーとして、最もよく知られた参照点だからです。プロジェクト全体の診断（今は、見ていないファイルの間違いは見えません）、ホバーでのドキュメント表示（ホバーはそれが何であるかは言うが、何のためかは言いません）、セマンティックハイライト（Ruby の foo はローカル変数かメソッド呼び出しか曖昧で、エンジンはすでに知っていて、エディタは知りません）の 3 つです。

あえて予定しないことにした Pylance 相当の機能も、その理由とともに 024-deferred-review-findings.md に記録されています。上記の各項目の根拠も同じ場所にあります。
