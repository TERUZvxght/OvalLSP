ホーム/ロードマップ

各リリースで何ができるようになるか

ユーザーが気づく順に並べています。ここでのバージョン番号は 何が同時に届くか の約束であって、日付ではありません。パッチリリースは設計上ここに現れません — 何も追加しないので、列挙するものがないからです。

patch — 0.1.x

ユーザーから見える変更なし。修正、堅牢化、テスト。機能の行が増えることはありません。

minor — 0.x.0

機能が追加されたリリース。どの機能かは、このページにリリースごとに列挙されています。

major — x.0.0

ユーザーが依存していたものが動かなくなったリリース。完全な定義は docs/PUBLISHING.ja.md にあります。

0.2.0 次のマイナー

最初の 1 文字からの補完と、開いていないファイルの診断

  • A と打つだけで候補が出る。 現在の補完は先に . が必要です。裸のプレフィックスに一致するのはルートヘルパだけで、ワークスペースのクラス、スコープ内のローカル変数、その場で呼べるメソッド — つまり実際に打鍵する内容のほとんど — は名前を最後まで打つまで何も出ません。あらゆるエディタで最もよく使われる補完です。
  • 開いていないファイルの誤りも報告される。 現在、診断はエディタで開いているファイルにしか存在しないため、3 階層離れたディレクトリのエラーは、たまたま開くまで見えません。
  • 型の違う引数を渡すと報告される。 現在チェックしているのは引数の個数だけです。
  • 一度も代入されない @ivar の読み出しが報告される。 Ruby は例外を投げず nil を返すため、現在は何も教えてくれず、ビューがただ空で描画されます。
  • ホバーと補完にドキュメントが表示される。 現在のホバーはそれが何であるかを言うだけで、何のためのものかは決して言いません。RDoc/YARD のコメントは def のすぐ上にあるにもかかわらず。
  • セマンティックハイライト。 Ruby の foo はローカル変数か self へのメソッド呼び出しか曖昧です。エンジンはすでにどちらか知っていて、エディタは知りません。ERB テンプレートの Ruby 領域も対象です。
このうち最初の 3 つは Pylance を基準にしています。動的型付け言語の言語サーバーとして、最もよく知られた参照点だからです。
0.3.0

gem が定義しているものを知る

  • gem を継承したクラスでも未知メソッドが報告される — ApplicationController、つまり大半のコントローラやジョブです。現在は、報告すれば推測になってしまうため、意図的に黙っています。
  • インレイヒント。 推論された型と引数名が、ホバーしたときだけでなくコード中に表示されます。
  • 各診断に対するクイックフィックス。 足りないメソッドを定義する、ルートヘルパ名を直す、引数の個数を合わせる。
  • 型定義へのジャンプ — 呼び出しているメソッドではなく、式が評価されるクラスへ飛びます。
  • 同じシンボルの他の出現箇所をハイライト（ファイル内）。
  • コール階層 — 参照の平坦なリストではなく、呼び出し元と呼び出し先をたどれる形で。
0.4.0

細部の調整

  • チェックごとの重大度設定。 納得できないチェックを警告ではなくヒントにしたり、無効にしたりできます。
  • require の自動挿入。
  • シグネチャヘルプが、カーソルのある引数をハイライトする。
1.0.0

機能ではなく、保証

このページで唯一、機能を追加しないリリースです。代わりに、機能マトリクスから 2 つの但し書きを取り除きます。

  • 公開するすべてのプラットフォームを検証する。 Apple Silicon だけでなく darwin-x64、win32-x64、linux-x64 も。
  • 素の Ruby プロジェクトを保証する。 Rails だけでなく。エンジンの大半はおそらく今日でも動きますが、それを仕様化も検証もしていません。
それまでは、機能マトリクスの「検証済み」はすべて「macOS Apple Silicon で、Rails プロジェクトで、同梱の Core で検証済み」という意味であり、それ以外は何も保証していません。
選定の方法

この一覧はどう決めたか

各項目は機能マトリクスの行に対応しています。マトリクスの行を持たないロードマップ項目はなく、届くリリースが明示されていないマトリクスの行もありません。 0.2.0 の最初の 3 項目は Pylance を基準にしています。動的型付け言語の言語サーバーとして、最もよく知られた参照点だからです。プロジェクト全体の診断（今は、見ていないファイルの間違いは見えません）、ホバーでのドキュメント表示（ホバーはそれが何であるかは言うが、何のためかは言いません）、セマンティックハイライト（Ruby の foo はローカル変数かメソッド呼び出しか曖昧で、エンジンはすでに知っていて、エディタは知りません）の 3 つです。

あえて予定しないことにした Pylance 相当の機能も、その理由とともに 024-deferred-review-findings.md に記録されています。上記の各項目の根拠も同じ場所にあります。

リリース済みのバージョンはどこに記録されているか

このページが扱うのは、まだ出荷されていないものです。出荷済みの内容は — なぜその変更を行ったか、何を測ったか、どの案が否定されたかも含めて — リリースごとに変更履歴にあります。
