本当に理解する Ruby。

OvalLSP は Ruby と Rails のためのセマンティック言語サーバーです。 Prism でコードを構文解析し、ワークスペース全体をインデックス化し、信頼された Rails ワークスペースではアプリケーション自身に「実際のルートとモデル」を問い合わせます。正規表現による推測はなく、テレメトリもなく、実行時のネットワークアクセスもありません。

できること

コードを理解した上で答える言語機能

以下の答えはすべて、実際の構文木、宣言のワークスペース全体インデックス、そして Rails が関わる場面ではアプリケーション自身のランタイム内省から導かれています。 OvalLSP は、知り得ないことについては推測せず、黙ります。

型を推論するホバー

リテラル、コンストラクタ、ローカル変数、Active Record のファインダ、そしてコントローラから ERB ビューへ引き継がれるインスタンス変数。 RBS/RBI シグネチャと統合されたローカル型推論エンジンが支えています。

アプリを知っている補完

モデルのカラムと関連、Active Record のインスタンス／クラス API、 *_path/*_url のルートヘルパ、RBS 由来の標準ライブラリ、そしてワークスペース内のクラス。タブストップ付きの呼び出しテンプレートとして挿入されます。

ワークスペース全体のナビゲーション

ワークスペースのメソッド、モデルのカラムと関連、標準ライブラリ（RBS の中）への定義ジャンプ。同じインデックスの上で、参照検索、ガード付きリネーム、ドキュメントシンボル、ワークスペースシンボルが動きます。

推測を拒む診断

構文エラー、継承関係がすべて判明しているクラスに対する未知メソッド、存在しないルートヘルパ、引数の個数の誤り。gem を継承したクラスに対しては、報告すること自体が推測になるため、あえて黙ります。

あなたの許可の下で動く Runtime Agent

bin/rails を含む信頼されたワークスペースでは、バックグラウンドのエージェントが実際のルートとモデルを内省します。信頼されていないワークスペースでは起動せず、Rails 由来の機能は設計通り静的解析の答えに縮退します。

推測ではなく、観測

オプトインのランタイム型観測が、あなた自身のテストスイートが実際に通した呼び出しの「形」だけを記録します。値は記録しません。ソースから読み取れないものを、すでに走らせているテストから学びます。

Rails

スキーマを推測しません。訊きます。

Rails アプリケーションの本当の姿は、実行して初めて確定するコードの中にあります。起動時に描かれるルート、データベースから読まれるカラム、DSL で宣言される関連。静的解析だけでは、そのすべてを近似するほかありません。

ワークスペースのルートに bin/rails があり、かつワークスペースが信頼されている場合、 OvalLSP はバックグラウンドスレッドで Runtime Agent を起動し、アプリケーションが実際に定義しているルートとモデルのスナップショットを取得して、補完・定義ジャンプ・型推論に流し込みます。エージェントを待ってブロックすることはありません。内省に失敗しても、エージェントがクラッシュしても、そもそも Rails でなくても、OvalLSP は静的解析だけで動き続けます。

  • カラムと関連を、実際のスキーマから、実際の型で。
  • ルートヘルパ — 補完、シグネチャヘルプ、そして config/routes.rb への定義ジャンプ。
  • Rails の DSL — enum、scope、delegate が定義するメソッドまで解決します。
  • コントローラ → ビュー — ERB テンプレート中の @ivar に、アクションが代入した型が付きます。
  • gem クラスの再オープン — テストヘルパの class ActiveSupport::TestCase は「定義」ではなく「再オープン」として認識され、誤検知を出しません。

正直な部分

「検証済み」とは、テストが証明しているという意味です

このプロジェクトは、きれいにインストールでき、きれいに起動し、健全なステータスを報告しながら、ユーザーが気づくようなことはほとんど何もしないバージョンを何度も出してしまいました。どのチェックも、ユーザーが訊かない質問に答えていたのです。そこで機能一覧は「ユーザーが何をして、何が見えなければならないか」として書き直され、その一つひとつが実際の Rails アプリケーションに対してエンドツーエンドで検証されています。

アーキテクチャ

4 つのプロセス。うち 1 つはあなたのアプリ

拡張機能は薄い LSP クライアントにすぎません。解析はすべて独立した Ruby 製 Core Server にあり、それは拡張機能の中に同梱され、拡張機能と一緒にアトミックに更新されます。

2 度目のダウンロードは不要

Core Server とその実行時依存（Prism、RBS）は VSIX に同梱されています。 bundle install もリポジトリのチェックアウトもバックグラウンド更新機構も不要です。拡張機能を更新すれば、Core もアトミックに追随します。

作業の前にハンドシェイク

起動時に拡張機能と Core がバージョン・プロトコル・ビルド・Ruby/プラットフォーム情報を交換します。不一致は報告され、あなたが判断するあいだセッションは動き続けます。詳細は Output チャンネルに出ます(その後の扱いは 024.55 が追跡しています)。

ウィンドウを閉じれば何も残らない

Core Server と Runtime Agent の寿命は、それを起動したワークスペースに束ねられています。クラッシュループ防止と指数バックオフ再起動を備え、ウィンドウを閉じたあとにプロセスが残らないことが検証されています。

意図的な制限

OvalLSP でないもの

これはエディタ機能のための「確信度を意識したヒューリスティックエンジン」であって、 Ruby の型チェッカーではありません。以下は未修正のバグではなく、設計上の境界です。

動的な定義は対象外

既知の Rails DSL 以外の method_missing や define_method、文字列引数を取る class_eval/instance_eval、実行時にしか存在しない定数解決はモデル化していません。推測すれば、自信たっぷりに間違った答えを返すことになるからです。

当面は 1 プラットフォームのみ

公開されている VSIX は darwin-arm64 向けにビルドされ、そのためにコンパイルされたネイティブ拡張を同梱しています。それ以外の環境ではペイロードを読み込みません。代わりに、あなたの Ruby 自身が prism と rbs を読めるかを確認し、読めればそちらで動いて Output チャンネルにその旨を出し(未検証の構成です)、読めなければエラーを出します(詳細は Output チャンネルに出ます)。Rosetta 2 経由を含む Intel Mac、 WSL、Dev Container、Remote SSH はこの Preview では非対応です。

gem 由来のメソッドはまだインデックスしていない

未知メソッドのチェックは、レシーバの継承関係がすべて判明している場合にのみ発火します。 gem を継承するクラス — ApplicationController、つまり大半のコントローラやジョブ — では黙ります。これを解消するのが gem の定義のインデックス化であり、 0.3.0 に予定されています。

他の Ruby 言語サーバーとは結果が重なります

VS Code はアクティブなプロバイダの結果を「選ぶ」のではなく「まとめて」表示します。そのため他の Ruby 言語サーバーと併用すると、両方の結果が同時に出ます。クラッシュはしませんが、候補が二重になります。OvalLSP の答えだけを見たい場合は、そのワークスペースで他を無効化してください。

FAQ

先に訊いておきたいこと

インストール直後、追加設定なしで動きますか？

対応する Ruby がすでにシステムから見えていれば、動きます。OvalLSP には 何らかの Ruby 3.4.x が必要で、mise / asdf / rbenv / Homebrew、あるいは明示的な ovallsp.rubyExecutablePath のいずれかで解決されます。それさえあれば、実行に必要な残りはすべて VSIX に入っています。追加のダウンロードも bundle install もチェックアウトも不要です。

対応する Ruby が見つからない場合、OvalLSP は中途半端に起動せず、何が問題でどうすればよいかを示す診断を表示します。

コードがどこかに送信されることはありますか？

ありません。テレメトリの仕組みは一切なく、Core Server にも拡張機能にも送信系の HTTP クライアントは存在しません。プロジェクト全体で唯一ネットワークを使うのは、リリースをビルドするマシンが VSIX に同梱する gem を RubyGems.org から取得するときだけです。詳細はセキュリティとプライバシーをご覧ください。

Runtime Agent は実際に何を実行するのですか？

あなたのアプリケーション自身の Rails / Bundler のコードを別プロセスで実行し、定義されているルートとモデルを読み取ります。ワークスペース由来の任意のコードを動かす以上、 VS Code でワークスペースを信頼済みにしたときにのみ起動します。信頼されていないワークスペースでは起動せず、Rails 由来の機能はすべて静的解析の答えに縮退します。これは障害ではなく設計です。

Rails を使わない素の Ruby プロジェクトでも使えますか？

ほぼ確実に動きます。エンジンの大部分は環境に依存せず、Runtime Agent は単に起動しないだけです。ただし、それを検証しているテストがまだないため、何も保証はしていません。素の Ruby での体験を仕様化し保証することは、 1.0.0 が担う 2 つの課題のうちの 1 つです。

なぜ Apple Silicon のみなのですか？

VSIX は特定の Ruby ABI・OS・CPU の組み合わせ向けにコンパイルされたネイティブ拡張（Prism、RBS）を同梱しています。読み込めるかもしれないビルドを配るのではなく、実際に検証できた組み合わせに対してのみ公開し、それ以外では理由を説明してペイロードの読み込みを拒否します。残るプラットフォームを公開して検証することが、 1.0.0 のもう半分です。

コントリビュートできますか？

現時点では受け付けていません。単独開発で活発に開発中であり、外部からの Issue や Pull Request をレビューすると進行中の作業より後回しになり、変更が衝突するおそれがあるためです。理由は CONTRIBUTING.ja.md に記載しています。セキュリティ報告は例外です — SECURITY.ja.md をご覧ください。
