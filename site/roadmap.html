What each release lets you do

In the order a user notices it. A version number here is a promise about what arrives together, not a date. Patch releases are absent by design: they announce nothing new — though they are where a promise already made gets kept.

patch — 0.1.x

Nothing a user sees changed. Fixes, hardening, tests. Never adds a capability row.

minor — 0.x.0

A capability was added. This page lists exactly which ones, per release.

major — x.0.0

Something a user relied on stopped working. The full statement is in docs/PUBLISHING.md.

0.2.0 shipped

Completion from the first keystroke, and diagnostics beyond the open file

  • Completion answers without a leading . — workspace classes, the locals in scope, and the methods callable right there. 0.2.0 needed two characters before the workspace joined in; 0.2.1 removed that floor, so one is enough.
  • Mistakes in files you have not opened are reported. A diagnostic used to exist only for a file open in an editor.
  • Passing an argument of the wrong type is reported, where an RBS/RBI declaration states it. Only the number of arguments was checked before.
  • Reading an @ivar that is never assigned is reported, in ERB views. Ruby returns nil rather than raising, so nothing used to tell you — the view simply rendered empty.
  • Hover and completion show the RDoc/YARD documentation, where a receiver was written.
  • Semantic highlighting. Ruby's foo is ambiguous between a local variable and a method call on self; the engine already knows which and the editor does not. Covers ERB templates' Ruby regions too.
Three of these are measured against Pylance — the closest well-known reference point for a language server in a dynamically typed language: project-wide diagnostics, documentation in hover, and semantic highlighting. Naming them rather than counting them, because they are not the first three in this list and an earlier version of this page said they were.
0.2.1 shipped

Fewer wrong reports, and the promises already published

  • A call whose receiver ends in ] or ) is no longer reported as an unknown method. Over Ruby 3.4.7’s standard library, five Rails 8.1.3 gems and minitest, 1,656 of 3,747 unknown-method reports are gone.
  • Upgrading delivers the fixes. The parse cache was not keyed on OvalLSP’s own version, so every file whose bytes had not changed kept answering with the previous release’s results.
  • Hover, definition and signature help stop answering about a method for something that is not a call — a word in a comment, a parameter name, a local that shares a name with a method.

The full list is in the changelog, which is where every release is recorded in full.

0.2.2 shipped

A test that deleted things, and the containment it needed

  • Nothing you can notice changes. This release exists because a defect in this repository’s own test suite destroyed files on the machine running it. The published extension was never affected and could not have been.
  • Every deletion the cache performs now goes through one function that refuses a path outside the cache root, instead of each call site computing its own target.

The full account is in the changelog, which is where every release is recorded in full.

0.2.3 shipped

What the record says is what ships

  • The known-limitations entry for a class named after a core class is rewritten from measurement. It claimed hover, definition and completion stopped answering; they answer — what the shipped build actually does is silently withhold diagnostics on such a receiver.
  • 0.2.1’s contradictory release-note bullet is removed. Its notes carried two bullets under one heading disagreeing about completion on a shadowed literal; the one describing a change reverted before release is gone, in both languages.
  • The site’s version badge is current again, with a check that runs on every pull request and every push to main — it used to run only when a site file changed, so a version bump alone could never fire it.

The full list is in the changelog, which is where every release is recorded in full.

0.3.0

Knowing what the gems define

  • Article.all. completes. A Relation answers what it holds — where, order, limit, and the chain they build. Hover already names the type; nothing yet tells the engine what a Relation's own API is, and the gem index above is what supplies it.
  • self. completes. The methods callable on the object you are writing in — the same list a bare prefix already offers, after a dot.
  • Unknown methods are reported on classes that inherit from a gem — ApplicationController, and so most controllers and jobs. Today the check is deliberately silent there, because reporting would mean guessing.
  • Inlay hints. The inferred types and parameter names appear in the code itself, not only when you hover.
  • Quick fixes for each diagnostic. Define the missing method, correct the route helper name, fix the argument count.
  • Go to type definition — jump to the class an expression evaluates to, rather than to the method being called.
  • Call hierarchy — callers and callees, navigable, instead of a flat list of references.
  • Highlight the other occurrences of the symbol under the cursor, within the file.
  • Completion of @ivar names the moment you type the sigil.
0.4.0

Refinements

  • Per-check severity settings, so a check you disagree with can be a hint rather than a warning, or off.
  • Auto-require insertion.
  • Signature help highlights the argument the cursor is in.
1.0.0

Guarantees, not features

The only release on this page that adds no capability. It removes the two asterisks from the capability matrix instead.

  • Every platform we publish for is verified, not just Apple Silicon — darwin-x64, win32-x64, linux-x64.
  • A plain Ruby project is guaranteed, not only a Rails one. Most of the engine almost certainly works there today; nothing specifies or verifies it.
Until then, every “Verified” in the capability matrix means “verified on macOS Apple Silicon, in a Rails project, with the bundled Core” — and nothing else is promised.

How this list was chosen

Every item corresponds to a row in the capability matrix — there is no roadmap entry without a matrix row, and no matrix row without a stated release. The first three items in 0.2.0 are measured against Pylance, the closest well-known reference point for a language server in a dynamically typed language: project-wide diagnostics (today a mistake in a file you are not looking at is invisible), documentation in hover (hover says what a thing is, never what it is for), and semantic highlighting (Ruby's foo is ambiguous between a local variable and a method call — the engine already knows which, the editor does not).

The Pylance features deliberately not planned are recorded with their reasoning too, in 024-deferred-review-findings.md alongside the rationale for each item above.
