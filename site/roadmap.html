What each release lets you do

In the order a user notices it. A version number here is a promise about what arrives together, not a date. Patch releases are absent by design: they announce nothing new — though they are where a promise already made gets kept.

patch — 0.1.x

Nothing a user sees changed. Fixes, hardening, tests. Never adds a capability row.

minor — 0.x.0

A capability was added. This page lists exactly which ones, per release.

major — x.0.0

Something a user relied on stopped working. The full statement is in docs/PUBLISHING.md.

0.2.0 shipped

Completion from the first keystroke, and diagnostics beyond the open file

  • Completion answers without a leading . — workspace classes, the locals in scope, and the methods callable right there. 0.2.0 needed two characters before the workspace joined in; 0.2.1 removed that floor, so one is enough.
  • Mistakes in files you have not opened are reported. A diagnostic used to exist only for a file open in an editor.
  • Passing an argument of the wrong type is reported, where an RBS/RBI declaration states it. Only the number of arguments was checked before.
  • Reading an @ivar that is never assigned is reported, in ERB views. Ruby returns nil rather than raising, so nothing used to tell you — the view simply rendered empty.
  • Hover and completion show the RDoc/YARD documentation, where a receiver was written.
  • Semantic highlighting. Ruby's foo is ambiguous between a local variable and a method call on self; the engine already knows which and the editor does not. Covers ERB templates' Ruby regions too.
Three of these are measured against Pylance — the closest well-known reference point for a language server in a dynamically typed language: project-wide diagnostics, documentation in hover, and semantic highlighting. Naming them rather than counting them, because they are not the first three in this list and an earlier version of this page said they were.
0.2.1 shipped

Fewer wrong reports, and the promises already published

  • A call whose receiver ends in ] or ) is no longer reported as an unknown method. Over Ruby 3.4.7’s standard library, five Rails 8.1.3 gems and minitest, 1,656 of 3,747 unknown-method reports are gone.
  • Upgrading delivers the fixes. The parse cache was not keyed on OvalLSP’s own version, so every file whose bytes had not changed kept answering with the previous release’s results.
  • Hover, definition and signature help stop answering about a method for something that is not a call — a word in a comment, a parameter name, a local that shares a name with a method.

The full list is in the changelog, which is where every release is recorded in full.

0.2.2 shipped

A test that deleted things, and the containment it needed

  • Nothing you can notice changes. This release exists because a defect in this repository’s own test suite destroyed files on the machine running it. The published extension was never affected and could not have been.
  • Every deletion the cache performs now goes through one function that refuses a path outside the cache root, instead of each call site computing its own target.

The full account is in the changelog, which is where every release is recorded in full.

0.2.15 shipped

Answers the engine already had

  • String.new(, File.read(, Integer.sqrt( answer again — in signature help, hover and go to definition, all three of which were silent for every class method the standard library declares. 14 stdlib calls measured, 0 before and answering after, six controls unchanged.
  • A signature is spelled the way you wrote it. def simple(a, b = 2, *rest, key:, opt: 1, **others, &blk) had presented as simple(a, b, rest, key, opt, others, blk), telling you key was the fourth positional argument when it is a required keyword.
  • One unresolvable include in your own sig/ no longer turns that whole class into false reports. Measured on the rbs gem’s 89 hand-written signatures: 20 false reports, now none.

No capability is added. Every fix is a case where the engine knew the answer and something between it and the reply threw it away — a paren-less call argument judged by its trailing literal, an outline entry selecting a whole class body instead of its name, a private written in a loop not reaching the methods below it.

0.2.14 shipped

The record, and the checks that keep it true

  • Nothing here changes what the extension answers. Every line this release touches in the engine is a comment, and the VS Code extension is untouched. It exists because the project’s own record had drifted from the product.
  • A limitation this product does not have had been published to users, in both languages. A finding was split into nine entries and seven were verified; one of the two that were not described a defect the engine had not had for several releases. Withdrawn.
  • Three checks could not fail in the case they existed for. “Did the suite actually run” counted examples, and a fully skipped file still reports examples; a text scanner matched its own prose and exempted its own file; a tree scan read only committed files, while the commit gate runs before the commit.

A patch that adds no capability and fixes no user-visible defect. It is here because several of the checks meant to notice a drifting record could not fail, and because PUBLISHING.md had documented the publish command that shipped a corrupt VSIX as v0.1.2 and kept it for twenty-five releases.

0.2.13 shipped

What a class’s own body says, and failures that stop being silent

  • A class that runs a macro this extension cannot read no longer reports the macro itself. It already declined to report anything the macro might define; reporting the call that opened that door was one fact answered two ways. Over 1,659 files of 16 installed gems, false unknown-method reports fell from 506 to 389 — and the one real latent NoMethodError in that corpus is still reported.
  • def Foo.bar is a class method, and attr_accessor inside a def inside class << self is an instance one — both were recorded the other way round, so both answers were inverted.
  • A Struct.new or Class.new block’s methods stop appearing on the class around it, and define_method(:name) puts the name in hover, go to definition and completion instead of only silencing reports about it.

No capability is added. Every fix here is one shape of a single question: when this engine cannot enumerate something, does it say so, or answer as though nothing went wrong? All 158 rescue statements in the Core Server were enumerated and each now records what it does with the failure — three were changed because their fallback was the reporting value.

0.2.12 shipped

The apparatus, and what it found

  • A private alias is no longer offered by completion. Two earlier releases fixed the halves of this separately — one put aliases into completion, one filtered private and protected — and neither made them meet, because an alias has no declaration of its own and the visibility rule reads declarations.
  • A class method your workspace adds to Object is reachable again. The one shape the changelog has described as worse than 0.1.14 since 0.1.15.
  • A module included by a bare name keeps its methods. Ruby looks the name up where you wrote it; so does this now, rather than refusing when another namespace shares it.

No capability is added. What the release is for: three review rounds in a row had found an example that could not fail under the change it guarded against. A spec can now name the mutation it claims to catch, and CI applies it. On its first working run it found a documented “deliberate trade-off” that was dead code, and then a fix recorded as shipped that had never been written.

0.2.11 shipped

What the engine may assert

  • A concern's class methods reach the class that includes it. Both the class_methods do block and the older def self.included(base) spelling were reported as missing methods, and both work.
  • module_function :name works when the method is in another file. Hover, go to definition and completion all answered nothing for it; now all three do.
  • A bare class name is resolved through what your class inherits, as Ruby does — not by a top-level class that happens to share the name.
  • A class answering through def self.method_missing, or generating class methods with define_singleton_method, is no longer reported for the calls it really does answer.

No capability is added, and measured over four Rails gems this release changes nothing: 84 unknown-method findings before and after, control identical. The fixes are for shapes those gems do not contain. One change was tried and taken back out — silencing an unreadable macro also silenced every class-level check in the workspace, and hid a real latent error in Rails itself.

0.2.10 shipped

An answer knows what it was computed from

  • Typing on a large file stops queueing your questions behind stale work. Measured on a 3,900-line file: a hover asked during a burst of edits took 1.43 seconds; it now takes 0.04. A burst faster than one analysis produces one answer, about where the buffer landed.
  • A class of yours named like another class of yours resolves the way Ruby resolves it. Config inside module App means App::Config if App declares one — so its own methods are no longer reported as missing while the call that really raises goes unmentioned.
  • class_methods do in an ActiveSupport::Concern attaches to the class, and module_function and extend self produce their methods — both idioms produced nothing at all before.
  • A Ruby that cannot run the Core no longer half-starts it. Four documents said this extension stops before answering anything on an incompatible interpreter, and it did not. It does now, after asking whether that Ruby can load prism and rbs of its own.

No capability is added. Three review rounds; the third ran the product against real Ruby rather than reading the change, and found 41 false reports on shipped Rails source that the two reading rounds had both missed — one of them a fix from the round before it. None of that reached this release.

0.2.9 shipped

One question, asked once, answered honestly

  • Completion no longer offers a name that would raise if you picked it. A private method on obj. and a protected one on other_object. are both uncallable from where you are typing. So was a private alias, which slipped through because an alias has no declaration of its own for the visibility rule to read.
  • The undefined-method check stopped reporting methods that exist. to_s, send and anything a module such as Comparable brings in were reported as unknown on some receivers. Measured over 213 files of installed gems, false positives fell from 54 to 6.
  • Signature help stopped offering a choice that does not exist. A method that overrides another showed both signatures — Ruby calls exactly one. 0.2.8 fixed the case where the override reused its parent’s parameter names; this fixes the ordinary case, where it renames them.

No capability is added. Underneath, “does this receiver have this member” stopped answering with a list whose emptiness meant two different things. It answers present, absent or unknown, and unknown is produced by whatever failed to enumerate rather than inferred by whoever received it — so the next way of not knowing makes every feature silent by construction, instead of one false report per discovery.

0.2.8 shipped

The parser’s bookkeeping, and a file’s identity

  • A workspace opened through a symlink no longer shows every file twice. The extension analysed your files under the resolved path while the editor talked about the path you opened, so the second copy could never be cleared — not by fixing the errors, not by saving, not by closing the tab.
  • Go to definition returns a path your editor will use, so following it no longer opens a second tab of the file you are already in.
  • The parser stopped deciding a declaration’s owner from six separate pieces of bookkeeping. Five recorded defects, and every “this macro was attributed to the wrong side” fix of the last four releases, came from twelve places each consulting whichever subset its author remembered.

No capability is added. The parser change was measured rather than argued: its whole output compared before and after across 3,606 gem files and 976 standard-library files, with the reference records byte-identical across 634,508 of them.

0.2.7 shipped

A document cannot be read half-written, and a publish cannot arrive out of order

  • Closing a file no longer leaves its errors behind. A background re-analysis already in flight republished a file you had just closed, and nothing republishes a file nobody has open — so those errors stayed in the Problems panel for the rest of the session. This was in every version shipped so far.
  • A slower analysis cannot put its older answers back. Every publish goes through one place that remembers what it last said about a file, refuses anything older, and lets closing a file win.
  • A file’s text, version and line positions always belong together. Measured on the previous version: under a concurrent edit, 1,977,450 of 1,977,451 attempts to work out a position returned one belonging to neither document. That arithmetic is under hover, completion and go to definition.

No capability is added. Four independent review rounds ran against this release, and the first attempt at the publish rule introduced a defect worse than the one it fixes — found by two of them independently, and recorded in full.

0.2.6 shipped

The undefined-method check, made honest

  • False “has no method” reports on real code: 54 → 6. Measured over the same 213 files of installed gem source each time. A class whose body runs a macro this extension cannot read, or that includes something it cannot identify, now admits it does not know that class’s methods instead of guessing.
  • Model.first answers, and so do last and take. It inferred nothing while Model.scope.first answered, so the commoner idiom was the one that did not work. A call that does not exist through a relation is reported now too.
  • A name written with its namespace is not answered by a class in another one. File.stat(path). offered a workspace Stat’s members; it offers the real 167 now.
  • A plugin’s result crosses the process boundary as data, not as objects — the parent used to rebuild whatever classes the stream named, before validating any of it. No plugin needs a change.
  • One unreadable file no longer ends the session. A file deep enough to exhaust the interpreter stack took the whole process with it, and so did any malformed message frame.

No capability is added. KNOWN_LIMITATIONS gained ten sections rather than losing them: three review rounds measured a great deal that was already wrong and is still wrong, and a limitation nobody has stated is worse than one everybody can read.

0.2.5 shipped

The foundations, and the answers that rested on them

  • A model’s scope answers for the model it belongs to. Where two namespaces held a class of the same name, completion after Shipping::Order.recent.first. listed the other model’s methods and go-to-definition found nothing.
  • A nested core type keeps its namespace. File.stat(path) answered as Stat, and a workspace class of that name captured it. 240 of the 334 loaded RBS types are nested.
  • Workspace Trust gates everything that executes, not only the Runtime Agent — restarts, observed-test runs and plugin loading all ask now.
  • The cache is owner-only. It holds method bodies from your own source and was readable by every other account on a shared machine.

No capability is added. This release is the foundations underneath the answers, and the answers that were wrong because of them.

0.2.4 shipped

An untrusted workspace could choose what the extension runs

  • Settings that name a binary or a command are now ignored from workspace scope until you trust the folder. Opening a repository in Restricted Mode used to run a program of that repository’s choosing, a couple of seconds after the window opened and before Workspace Trust was consulted. User and machine settings are unaffected, and static analysis still works untrusted.

A security fix. Nothing an editor does changes otherwise, and no capability moves — the manifest already promised this and the release makes it true.

0.2.3 shipped

What the record says is what ships

  • The known-limitations entry for a class named after a core class is rewritten from measurement. It claimed hover, definition and completion stopped answering; they answer — what the shipped build actually does is silently withhold diagnostics on such a receiver.
  • 0.2.1’s contradictory release-note bullet is removed. Its notes carried two bullets under one heading disagreeing about completion on a shadowed literal; the one describing a change reverted before release is gone, in both languages.
  • The site’s version badge is current again, with a check that runs on every pull request and every push to main — it used to run only when a site file changed, so a version bump alone could never fire it.

The full list is in the changelog, which is where every release is recorded in full.

0.2.15

The accuracy line

  • Open engine defects, and nothing announced. A patch release closes the gap between what the extension already claimed and what it does — and from 0.2.14, against any earlier claim rather than only the previous release's. No capability is added here; that is what makes it a patch.
0.3.0

Knowing what the gems define

  • Article.all. completes. A Relation answers what it holds — where, order, limit, and the chain they build. Hover already names the type; nothing yet tells the engine what a Relation's own API is, and the gem index above is what supplies it.
  • self. completes. The methods callable on the object you are writing in — the same list a bare prefix already offers, after a dot.
  • Unknown methods are reported on classes that inherit from a gem — ApplicationController, and so most controllers and jobs. Today the check is deliberately silent there, because reporting would mean guessing.
  • Inlay hints. The inferred types and parameter names appear in the code itself, not only when you hover.
  • Quick fixes for each diagnostic. Define the missing method, correct the route helper name, fix the argument count.
  • Go to type definition — jump to the class an expression evaluates to, rather than to the method being called.
  • Call hierarchy — callers and callees, navigable, instead of a flat list of references.
  • Highlight the other occurrences of the symbol under the cursor, within the file.
  • Completion of @ivar names the moment you type the sigil.
0.4.0

Refinements

  • Per-check severity settings, so a check you disagree with can be a hint rather than a warning, or off.
  • Auto-require insertion.
  • Signature help highlights the argument the cursor is in.
1.0.0

Guarantees, not features

The only release on this page that adds no capability. It removes the two asterisks from the capability matrix instead.

  • Every platform we publish for is verified, not just Apple Silicon — darwin-x64, win32-x64, linux-x64.
  • A plain Ruby project is guaranteed, not only a Rails one. Most of the engine almost certainly works there today; nothing specifies or verifies it.
Until then, every “Verified” in the capability matrix means “verified on macOS Apple Silicon, in a Rails project, with the bundled Core” — and nothing else is promised.
Method

How this list was chosen

Every item corresponds to a row in the capability matrix — there is no roadmap entry without a matrix row, and no matrix row without a stated release. The first three items in 0.2.0 are measured against Pylance, the closest well-known reference point for a language server in a dynamically typed language: project-wide diagnostics (today a mistake in a file you are not looking at is invisible), documentation in hover (hover says what a thing is, never what it is for), and semantic highlighting (Ruby's foo is ambiguous between a local variable and a method call — the engine already knows which, the editor does not).

The Pylance features deliberately not planned are recorded with their reasoning too, in 024-deferred-review-findings.md alongside the rationale for each item above.
