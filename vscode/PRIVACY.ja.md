# Privacy

[English version](PRIVACY.md)

## 要約

OvalLSPはテレメトリを収集せず、外部と通信せず、あなたのソースコードや
workspace情報をどこにも送信しません。全ての動作はあなた自身のマシン上で
ローカルに完結します。

## テレメトリ

一切ありません。OvalLSPはいかなる種類のテレメトリ統合も持ちません
(クラッシュレポートサービス、analytics SDK、利用状況トラッキングの
いずれもなし)。これは単なる宣言ではなく、実際のコードベースに対して
検証済みです: Core Server(`core/`)、拡張機能(`vscode/src/`)のいずれにも、
ネットワーククライアントのコード・telemetry/analyticsライブラリ・
outboundなHTTP/HTTPS呼び出しは一切含まれていません。

## ネットワークアクセス

OvalLSP自体は実行時にネットワークリクエストを一切行いません。この
プロジェクト内で唯一存在するネットワークアクセスは:

- **packaging時のみ**(VSIXをビルドする時のみで、利用者にインストール
  された拡張機能自体が行うものではない): Core Serverのruntime gem依存
  (Prism、RBS)をRubyGems.orgから取得し、VSIXへ同梱するため。これは
  リリースをビルドするマシン上でのみ発生し、利用者のマシン上では発生
  しません。
- **VS Code自身のMarketplace更新機構** — これはVS Code自体の挙動であり
  OvalLSPのものではありません。詳細はお使いのVS Code自身のprivacy文書を
  参照してください。

VS Code自身のMarketplace拡張機能更新以外に、自動ダウンロードや
self-update機構は存在しません(理由はメインの
[README](README.ja.md#サーバー起動更新モデル)参照 — Core Serverは
拡張機能の内部に同梱され、独立したダウンローダーではなく、拡張機能と
アトミックに更新されます)。

## ローカルに記録される内容

`OvalLSP: Show Logs`のoutput channelとCore Server自身のstderr出力には、
OvalLSP自身の動作(起動、インデックス進行状況、エラー、version
互換性handshake)に関する診断メッセージが含まれます。これらのログは
あなたのマシン上(VS Code自身のOutputパネル)に留まり、どこにも送信
されません。output channelを閉じて再度開くことでクリアできます。
通常の利用でOvalLSP自身がディスクに書き込むのは、`$XDG_CACHE_HOME/ovallsp/`
(この環境変数が未設定または空なら `~/.cache/ovallsp/`)配下の
[永続parseキャッシュ](README.ja.md#トラブルシューティング)のみです。
workspace・toolchainのversion・OvalLSP自身のバージョンをキーにしています。
使われなくなった組合せのディレクトリは起動時に削除されます。0.2.1 まではこれが
無く、拡張機能を入れている限り溜まり続けていました。直近8つを残します。**このキャッシュには
あなたのソースコードの一部が含まれます。** parse済みの宣言と型に加えて、
各メソッドの本文テキストと各パラメータのデフォルト式をそのまま保存します。
本文は、あとでファイルを読み直さずに戻り値の型を推論するためであり、
デフォルト式はパーサが記録するためです。各ファイルの絶対パスも保存します。
(ファイルが変更されたかどうかは、このテキストではなくハッシュで判定して
います。)いずれもどこにも送信されず、
このディレクトリはいつ削除しても安全です(再索引で作り直されます)。

型観測の実行中は、さらに2つのファイルが書かれます(通常は実行中のみ。実行を
越えて残るのがどういう場合かは下記参照)。

## Runtime型観測(opt-in)

`OvalLSP: Run Tests with Type Observation`は完全にopt-inです(明示的に
コマンドを実行するまで無効)。実際にあなた自身のテスト実行で行使された
メソッドについて、以下を記録します:

- class/module名とmethod識別子;
- 各位置引数について、その位置で観測された**クラス**の集合——クラス名で
  あって、オブジェクトそのものではありません;
- そのメソッドが**返した**クラスの集合(同じ条件);
- 何回の呼び出しが寄与したか。例外を送出した呼び出しも、その件数と
  渡されたクラスは寄与します。伏せられるのは戻り値の型だけで、例外を
  送出したという記録は残りません;
- その実行の識別子(開始時刻・Coreのプロセスid・乱数から生成);
- 観測対象メソッドが含まれる**ファイル**のダイジェストと、そのメソッドの
  行番号(そのメソッドがその後編集された可能性を検出する目的にのみ使用)、
  および実行の終了時刻。

引数の値・戻り値・文字列内容・SQL・環境変数・ファイル内容は一切記録
しません — このevidenceを構築するnormalizerは、観測対象に対して
`#inspect`/`#to_s`を一切呼び出しません。ここで重要な区別はクラス*名*と
オブジェクトそのものの違いです。`User` は記録されますが、そのユーザーは
記録されません。集約結果はパースキャッシュには書き込まれず、サーバを再起動すると残りません。
ディスクに触れる唯一の写しは、すぐ下で述べる実行中の一時ファイルで、その
寿命についてはそちらで述べます。

観測の実行中だけ、一時ファイルが2つ存在します。どちらもシステムの一時
ディレクトリに所有者のみ読み書き可能な権限で作成され、実行の終了時に削除
されます——ただし保証はされません。削除は、既に送出されている例外を置き換え
ないよう意図的に静かに失敗させているため、一時ディレクトリが読み取り専用に
なっている場合には残ります。クラッシュや強制終了では、削除処理自体が実行
されません。

- 実行結果(内容は上記のとおり);
- ログファイル。ここには**あなたのテストコマンド自身の標準出力と標準
  エラーがリダイレクトされます**。OvalLSPはこのログを読みません。`--stdio` モード
  ではファイルディスクリプタ1が稼働中のLSPトランスポートであり、子プロセス
  の出力をそこに流すわけにいかないために存在します。ただし、
  あなたのテストスイートが出力したものがそのまま入ります。Railsアプリで
  あればSQLが日常的に含まれ、コードや環境がログ出力するものは何でも
  入りえます。上記の「記録しません」という保証は、OvalLSPが*抽出して
  保持するもの*についてのものであり、あなた自身のスイートの出力について
  の主張ではありません。それはあなたのプログラムのものです。

いずれのファイルの内容も、どこにも送信されません。

## Runtime Agent

Runtime Agent(Rails route/modelの調査)は、VS Code上で明示的に
**信頼済み**とマークしたworkspaceでのみ起動し、あなた自身のプロジェクト
の一部として既に存在するコード(あなたのプロジェクト自身のBundler
context経由)のみを実行します — あなた自身がアプリケーションを実行した
時に既に発生するもの以外の、新たなネットワークアクセスや外部への
データフローを一切導入しません。

**あなたのアプリケーション自身の出力は、ログチャンネルに流れます。**
Agentは子プロセスであなたのRailsアプリケーションを起動するため、その
アプリケーションが書き出すもの — Railsの起動時出力、あなた自身の `puts`、
標準出力に書くlogger、その子プロセスが出力するもの — は、Agentのプロセス
idを前置きして `OvalLSP: Show Logs` チャンネルへ転送されます。このチャンネル
の他の内容と同じくあなたのマシンに留まり、どこへも送信されませんが、
OvalLSP自身の出力ではなくあなたのアプリケーションの出力です。起動時に
何かを出力するなら、それはそこに見えます。出力チャンネルを閉じて開き直せば
消去できます。

## カスタムCore Serverパス

`ovallsp.server.path`を設定し、この拡張機能が同梱するもの以外のCore
Serverビルドを指定した場合、上記は引き続きOvalLSP自身のコードに対して
成り立ちますが、そのカスタムビルド自体が何を行うかについてはあなた
自身の責任になります — このプロジェクトが配布・レビューしている正確な
コードではなくなるためです。
